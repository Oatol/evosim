### 实现中相对 DESIGN.md 的两处调整（已同步回文档）

1. **渲染改为"离屏静态层 + 脏格更新"**：原设计是直接在主画布上做脏格重绘，实际发现缩放后像素边界换算繁琐、且环绕平铺时同一格需多处重绘。改成 1 像素 = 1 格的离屏层后，两个方向都简化，缩放代价与格子数无关。
2. **操作映射调整**：原计划空格键做平移，实际改为空格 = 播放/暂停（更符合模拟工具习惯），平移改用右键/中键/Alt+左键。

另修正一个真实 bug：平铺的 `maxTiles = 9` 限制卡得太死，缩放稍远就退化成"只画一块"。经推导，平铺总绘制像素约等于 `(视口宽+瓦片宽)×(视口高+瓦片高)`，最坏 4 倍视口面积，**与瓦片数量无关**，因此该限制本身是错的，已放开到 512 仅作安全阀。

### 解决的真问题

- **默认配置下种群 6000 tick 灭绝**：世界最终 49.4% 是食物。根因是生产者细胞在 `(1,1)`，把食物造到 `(2,1)`/`(1,2)`，而嘴在 `(0,0)` 只能吃到距离 1 的格子 → 这部分食物永久泄漏、不断堆积 → 堵死繁殖空间 → 正反馈推向灭绝。做腐败率扫描定量解决：0% 灭绝 / 1% 稳定 1546 / **2% 稳定 1774（选定默认）** / 8% 稳定 2034。40000 tick 长程验证：种群 1775–1845，食物稳定 9.1%。
- **环绕移动后坐标漂移**：生物从 `col=0` 向左走出界后 `col` 变成 `-1`，`grid.index` 会折回所以画面正确，但坐标无限漂移。加 `normalizePosition()` 在移动/繁殖/构造后调用。**注意繁殖时子代偏移要用未归一化的母体坐标算**，否则 `isStraightPath` 绕远路误判受阻。
- **繁殖失败时的无谓分配**：把 `isClear()` 预检提前到子代 `new Organism()` 之前。

### 关键设计决策

1. **两级变异率**：先掷 `mutability` 决定这胎要不要变，通过后再对三个结构算子各掷一次。`mutability` 是元变异的作用对象，调到 0 就能一键关掉全部结构变异。
2. **元变异只在变异真发生时漂移**。每胎都漂移会让变异率做无约束随机游走，与选择压力脱钩。代价是元变异演化很慢（40 代只从 5.00 漂到 5.10）——这是刻意的：变异率是慢变量，形态是快变量。
3. **指纹复用**：结构没变时直接沿用母体指纹，省掉排序 + 哈希。变异率只有几个百分点，绝大多数繁殖走零成本路径。
4. **`Species` 不持有 `Anatomy` 引用**，只存描述字符串快照——物种是历史记录，不该跟着存活个体被改。
5. **`StatsRecorder.js` 没有单独成文件**。原计划有它，实际职责被 `World.detailedStats()` + `main.js` 采样循环 + `FossilRecord` 三处分担，再抽一层只是多一次无意义的转发。

### 解决 / 发现的问题

- **变异后必须复查位置**（真问题，写代码时想到的）：出生距离用母体 `birthDistance` 算，但"加细胞"会让子代变大 → 原安全距离可能不够。繁殖流程改为「母体蓝图便宜预检 → 造子代 → 变异 → 变异后蓝图严格复查」。跳过最后一步会让子代和母体压在同一格，两个生物往同一格写 `owners`，之后谁 `clearGrid()` 都抹掉对方身体。测试里专门验证了"大量变异繁殖后网格无重叠 = 0 处"。
- **曲线被挤出首屏**（真问题，截图发现的）：右栏先放读数（16 行）再放曲线，导致打开页面只能看到"演化曲线"标题、看不到任何曲线。改为**曲线置顶**，并把世界读数从 7 行精简到 4 行（删掉 tick / 非空格 / 总格数）、操作提示压成一行。
- **"重新生成世界"后不恢复运行**（真 UX 问题，端到端测试暴露的）：按钮 `engine.pause()` 后没有 resume，用户点完看到静止画面会以为坏了。改为"保持原有运行状态"（重新生成、应用尺寸、R 键重置三处），"清空"保持暂停（清完世界是空的，等用户画东西更合理）。
- **CDP 测试拿到旧代码**（踩坑）：`python -m http.server` 不发 `Cache-Control`，Chrome 对 JS 做启发式缓存。复用 `--user-data-dir` 的 profile 会导致"改了代码但行为没变"（表现为按钮行为没更新，tick 一直是 0）。解决：CDP 脚本每次启动前 `rmSync` profile 目录。
- **扫描脚本把初始瞬态当成生态瓶颈**（测试自身的问题）：第一版扫描显示"所有变异率的最低种群都是 7"，看起来像严重瓶颈。实际是前 100 tick 刚投放的 7 个生物还没繁殖开。修正：最低种群跳过前 2000 tick。

### 关键设计决定

1. **输出层线性，不用 tanh**。决策靠 argmax，压缩到 `(-1,1)` 会把强弱差异抹平，越强的倾向反而越挤在一起。
2. **`b2` 给随机初值而不是 0**。没有眼睛的生物视觉输入全是 0，此时输出完全由 `b2` 决定；若 `b2` 全 0，所有无眼个体都会朝同一方向走，种群初期会呈现明显的方向偏置。
3. **输出是相对方向的**。`o[0..3]` = 前/右/后/左的移动倾向，`planDirection = (rotation + argmax) & 3`——身体转过去"前"就跟着转。转身与移动解耦。
4. **`turnCooldown`（4 tick）是必需的**。没有它，把 `o[4]` 权重调高的个体会每 tick 转身一次、原地打转，而它的能量收支看起来和正常个体一样——选择压力抓不住这个退化。
5. **检视器静态层 / 动态层分离**。权重在个体活着时不会变，540 条连线只在切换对象/尺寸变化时重建一次，存进离屏 canvas；每帧只 `drawImage` + 重画节点。连线再按 (符号, 档位) 批量描边（8 次 beginPath + stroke），逐条设 `strokeStyle` 是最大性能陷阱。
6. **检视器做成模态浮层而不是侧栏**。40 个输入节点需要足够高度，挤在 232px 宽的侧栏里没法用。

### 解决 / 发现的问题

- **`Inspector.onClose` 是死代码**（真 bug，CDP 测试抓到的）：`close()` 只清 `organism` 和 `hidden`，从不触发 `onClose`。而 `renderer.highlight` 的清理挂在 `onClose` 上——所以按 Esc、点背景、重建世界三条路径都会在世界画布上留下一圈残留的高亮环。修正：把 `onClose` 的触发收进 `close()`，并加"已关闭就不再触发"的守卫。所有关闭路径自然收敛。
- **`engine.fps` / `engine.tps` 在暂停时是冻结的旧读数**（测试自身踩的坑）：`setSpeed()` 不会启动引擎，而 CDP 测试的"重建世界"段结束时引擎正处于暂停态 → 性能段读到 28 fps 的假数据。加诊断后确认真实 RAF 是 60.5 Hz、单帧成本 0.075 ms。修正：性能段显式 `engine.start()`，并新增"引擎确实在跑"这条断言兜底。
- **新生个体在出生那一 tick 还没轮到 `think()`**（测试自身的问题）：遍历全体生物检查 `brain.lastInput` 时，刚在上一 tick 阶段 B 出生的个体 `lastInput` 还是 `null`，被误判成"感知向量维度错误"（5 个异常）。修正：把这类个体单独计数并在断言里扣除。这个事实也写进了 DESIGN.md——检视器需要按 0 兜底。
- **CDP 里不能直接返回带循环引用的对象**（踩坑）：`{ highlight: renderer.highlight }` 会因为 Organism 带着 world/grid 引用而报 `Object reference type chain is too long`，整个脚本崩在中途。只返回 `highlight.id` 就好。
- **阶段 3 的 CDP 脚本断言了"徽章已更新到阶段 3"**，阶段 4 之后必然失败。改成 `/^阶段 \d/`——具体是第几阶段由当时的 `cdp-phaseN` 负责，回归脚本只确认徽章被填充过。

**结论**：杀手 + 移动器的组合被强烈选择（三个种子一致的 5–6× 富集），也就是**主动追击**而不是守株待兔；种群呈现周期性振荡而不是收敛到平衡点。"捕食者-猎物"这一条基本成立。

**但眼睛是个例外**——它演化出来了，却一直很稀有。合理解释：眼睛要占一格身体（多一份能量开销与繁殖成本），而 `lookRange = 20` 让距离信号区分度太低（`closeness = 1 - dist/20`，视野内的目标大多给出接近 1 的值）。**这条留给阶段 7 调参**，方向是降低 `lookRange` 或让视觉输入对距离更敏感。

### 关键设计决定

1. **参数面板由元数据生成**。参数表是唯一事实来源，加参数只改 `config.js`。40 多个控件手写会失控。
2. **抽屉而不是常驻侧栏**。参数有 40 多项，塞进左栏会把画笔/笔刷挤出屏幕——而"一边画一边调参"正是这个沙盒的核心玩法。
3. **网格尺寸是唯一"延迟生效"的参数**。它要重建世界、清空生态，所以拖滑块只暂存待应用值，点"应用"才生效。不能让滑块直接写 `Config.world.cols`：世界没重建前 Config 与 grid 会不一致。
4. **权重用 base64 编码原始 Float32 字节**，不是 JSON 数字数组。① 精确——JSON 浮点四舍五入后读档演化会分叉，而"存档能原样接着跑"是硬要求；② 小——557 权重 3.4KB→2.6KB。身体蓝图仍保持明文数组（需要人眼检查的形态可读）。
5. **食物索引按 `world.foodCells` 原样顺序存**，不能按索引升序重排。腐败是 `foodCells[rng.int(len)]` 按数组位置抽样，而 foodCells 顺序是 swap-remove 的历史产物，重排无法复原。
6. **读档用 `world.adoptOrganism()` 而非 `addOrganism()`**。后者会调 `species.observe()` 把 `cumulativePop` 重复累加，而读档时物种表是整体恢复的。
7. **单文件打包用"每模块包 IIFE + 极简模块表"**，不直接拼接。模块间会重名（`Mutation.js` 与 `Camera.js` 都有顶层 `clamp`），拼接后静默覆盖且无报错。打包器还强制检查循环依赖。
8. **exe 用 Node SEA**（`--experimental-sea-config` + postject），把 node.exe 副本变成自带运行时的 exe；启动器起本地 HTTP 服务并开浏览器。为什么起服务而不是直接开文件：部分浏览器（Firefox）在 `file://` 下禁用 localStorage。

### 解决 / 发现的问题

- **`restoreBrain` 忘了解码 base64**（真 bug）：权重改成 base64 后序列化端换了、反序列化端没跟上，直接把 base64 字符串 `set()` 进 Float32Array，读档抛 `RangeError`。逻辑测试第一版就炸出来。
- **食物索引顺序没被保存**（真 bug，最隐蔽）：存档按索引升序重排食物，读档后跑 250 tick 就分叉——实测差 126 格、种群 21 vs 33。排查方式：先确认 RNG 状态 `a/b/c/d` 完全一致（排除随机数），再定位到 `applyFoodDecay` 的按位置抽样。
- **检视器模态浮层盖住画布**（真 UX 问题，CDP 测试抓到）：`elementFromPoint` 返回 `.inspector-head`——"检视 → 克隆选中 → 点画布投放"这条链路中间必须手动按 Esc。改成点"克隆选中"时自动 `inspector.close()`。
- **`localStorage` 在 `file://` 下可能抛异常**：单文件版会踩到。加 `storageAvailable()` 探测，降级成友好提示。
- **打包器误报"入口替换失败"**：守卫写成 `html.includes('src/main.js')`，而打包后的脚本里本身就含这个字符串（作为入口模块 id）。改成检查原始 `<script type="module"` 标签是否还在。
- **`String.replace` 的 `$` 陷阱**：替换串里含 `${...}` 会被当成替换模式。改成函数式替换 `() => ...`。
- **postject 报 `Can't read resource file`**：`shell: true` 调 npx 时，项目路径含空格（`WorkBuddy AI`）被拆成多个参数。改成把 postject 装本地、用 `node` 直接执行其 CLI。
- **CDP 性能断言偶发失败**：连续跑多个 CDP 脚本时 CPU 竞争会让无头 RAF 抖动。改成"8 次采样取最优"，并把下载等待放宽到 15s。
- **cdp-phase4 的徽章断言**硬编码"阶段 4"，阶段 5 后必然失败。改成 `/^阶段 \d/`（与 cdp-phase3 一致）。

### 收尾时抓到的测试脚手架缺陷（值得记）

- **CDP 脚本连到了旧实例的页面**（最隐蔽的一个）：`chrome.kill()` 只发 SIGTERM，Windows 上 Chrome 常常忽略它，留下子进程**继续占着调试端口 9226**。新 Chrome 绑不上端口，`fetch('http://127.0.0.1:9226/json/list')` 就返回了**旧实例**的 target 列表 → 测试在别人的页面里跑。症状是"启动时就有克隆蓝图""启动时检视器是开的"这类不可能出现的状态。修法：① 启动前 `freePort(PORT)` 用 `netstat -ano` 找出占用调试端口的进程并 `taskkill /F /T`；② 结束/崩溃时强杀进程树而不是 `chrome.kill()`。清理后连跑两轮，残留 chrome 进程数归零。
- **profile 清理撞 EBUSY**：`rmSync(profile)` 常因"上一轮 Chrome 还没退干净"报 `EBUSY: resource busy or locked`。加 `resetProfile()`：重试 8 次（每次 `Atomics.wait` 同步小睡 400ms），仍失败就换成带 pid 的新目录。
- **CDP 性能断言偶发抖动**：连续跑多个 CDP 脚本时 CPU 竞争让无头 RAF 抖动 → `帧率健康`/`tick 速率达标` 偶发失败。改成 8 次采样取最优。
- **cdp-phase4 的徽章断言硬编码"阶段 4"**，阶段 5 后必然失败。改成 `/^阶段 \d/`。

## 修复：缩小时世界被重复平铺（用户反馈）

**现象**：用户截图反馈"缩小会这样"。当前模型读不了图，所以把截图丢给 Chrome 转成 ASCII 打印出来"看"——确认画面是把同一个世界重复平铺了约 7×5 份。

**根因**：`Renderer._drawTiled` 无条件按视口范围平铺，目的是"跨环绕边界平移时不出现空洞"。但当世界**比视口小**（缩小后），为了铺满视口就要重复很多份。

**修法**：平铺只在"世界比视口大"的方向做。世界比视口小的方向只画一块，四周留背景。

**验证**：
- 把世界填满墙 → 缩小时内容外接框 = 世界尺寸（不再铺满视口）；放大时仍铺满（背景像素 0）
- 新判据（写进 `cdp-phase4.mjs` 第 9 节）：把画面横向平移"一个世界宽度"再比对重合率——平铺时会高度重合，只画一块时重合率≈0。实测 zoom 1.2 时重合率 **0.0%**
- 结构契约测试：桩 ctx 调 `_drawTiled`，世界小于视口 → 1 块；世界大于视口 → 1–4 块
- 回归：phase3/4/5 逻辑 + cdp-phase3/4/5 全通过；单文件与 exe 各 18 项通过

**排查手法值得复用**：读不了图时，用 Chrome 打开图片 → canvas → `getImageData` → 降采样成 ASCII 打印，可以直接"看"到截图内容。脚本见（已删）`tools/_diag-img.mjs` 的思路。

**顺带修**：`tools/build-exe.mjs` 覆盖 `dist/evosim.exe` 时若旧进程还在跑会报 EBUSY → 先 `taskkill /F /IM evosim.exe` 再带重试删除。
