## 用户反馈的三个检视器毛病（根因同一个）

用户报告：克隆时提示"先用检视选中"、点检视器外区域会关掉它、"跟随"按钮无效。
排查后确认三个症状**同一个根因**：`Inspector` 是全屏模态（`.inspector{position:fixed;inset:0}`
+ 遮罩 `inset:0`），遮罩盖住了整个视口（含左右栏、顶栏、时间轴）：

1. **跟随其实在工作**（`camera.updateFollow` 每帧把相机对准该个体），但画布被遮罩盖住 → 看不到。
2. **"克隆选中"永远失败**：遮罩盖住工具栏，点按钮其实点在遮罩上 → 触发 `backdrop.click → close()`，
   选中被清空；第二次点才落到按钮上，此时已无选中 → 提示"先用检视工具点一个个体"。
3. **关闭按钮其实一直有**（右上角 `×`），只是 26px 的小按钮在全屏遮罩的观感下不显眼。

修法：改成**不挡画布的非模态浮窗** + **图钉锁定** + 加"保存生物"。三个症状一起消失。

### 关键设计决定

1. **默认值与旧行为逐位等价**：hp=1、foodValue=1、杀手 damage=1 → 升级到注册表后生态完全不变，
   既有测试与实测数据继续有效。这是"大重构不破坏已验证基线"的关键。
2. **代谢消耗默认关闭**。扫描（12000 tick × 3 种子）显示消耗×1 就有 1/3 种子灭绝。根因不在数值大小，
   而在**能量模型**：生物能量长期贴近 0（一攒够 `foodNeeded` 就繁殖掉），任何消耗都让它们立刻饥饿；
   生产者 5%/tick 的造食率也撑不起持续支出。可用组合：「消耗×1 + 造食率 15%」→ 稳定 ~2300 不灭绝。
3. **派生量不缓存**（`maxHealth`/`upkeepCost`/`foodValueTotal`）。属性可随时在面板改，缓存会读到旧值；
   调用频率（每个体每 tick 一次 + 每次挨打一次）不值得引入失效逻辑。
4. **饿死有缓冲**（`starvationTicks=60`）。没有它，刚出生（能量为 0）的个体会当 tick 暴毙。
5. **注册表是唯一事实来源**。加一种细胞 = 加一个定义对象；参数面板的 30 行控件也是自动生成的。
6. **`Config.cells` 用嵌套对象 + 面板字段键用点号路径**（`MOUTH.hp`），比扁平键更可读，
   且运行时读取不用拼字符串。
7. **生物库读回统一走 `blueprintOf()`**：库里存紧凑数组 `[type,dx,dy,dir?]`，任何地方要对象数组都从它转。

### 解决 / 发现的问题

- **`SpeciesEditor._loadEntry` 把紧凑数组当对象数组读**（真 bug，CDP 测试抓到）：库里存的是
  `[type,dx,dy]`，代码却写 `dx=c[0]`（其实是 type）、`type=c[2]`（其实是 dy），载入的蓝图整个错位。
  改成走 `library.blueprintOf(entry)`。
- **检视器全屏模态遮罩**（真 UX 问题，用户反馈）：见上，改成非模态浮窗。
- **`setPointerCapture` 在合成 PointerEvent 上会抛**：拖动测试用 `dispatchEvent(new PointerEvent(...))`，
  `pointerId` 不是真实指针 → `InvalidPointerId`。包 try/catch（对真实场景也更稳）。
- **测试自身的两处错**：视觉测试读错了方向分组的槽位下标（眼睛朝右 → base = 1×9 而不是 0）；
  "关闭消耗时能量不变"用了 energy=5，结果顺手触发了繁殖（`energy >= foodNeeded` → 扣 1），
  改成 0.5。
- **CDP 断言硬编码阶段号**：cdp-phase5/6 又各中一次，统一改成 `/^阶段 \d/`。

### 1. 物种树占满整个空间（看不到画布 / 高亮）

和当初检视器犯的是**同一个错**：全屏模态遮罩。用户原话"物种树页面占了整个空间，

  width:min(720px, calc(100vw - 300px)); height:min(560px, calc(100vh - 120px)); pointer-events:auto`
- head 里加图钉（`pinBtn`），**默认锁上**（`this.pinned = true`）——树是参照物，
  选完物种还要回画布操作；解锁后点画布才关
- 接上 `enableDrag(head, panel)`；`_bindOutsideClose()` 判据是
  `event.target.closest('.canvas-wrap')`（"点没点在画布上"，不是"点没点在面板外"）

**这是本项目第二次踩"全屏 backdrop"这个坑**，所以三个浮窗（inspector / species-editor /
species-tree）现在共用同一条规则，已写进 DESIGN.md §9.4。

### 2. 暂停时准星也冻住

根因：`Engine.pause()` 里调了 `cancelAnimationFrame` → `onFrame` 不再触发 →
准星 / 高亮 / 浮窗全部停在最后一帧。

改法：**渲染循环与模拟解耦**。
- `pause()` 只 `running = false` + `_accumulator = 0` + `_ensureLoop()`，不再取消 RAF
- 新增 `stop()` 供真正停掉循环（页面销毁用）
- 新增 `_ensureLoop()`：`_rafId === null` 时才挂帧
- `_frame` 开头把 `_rafId = null`（这样暂停/继续都能安全重挂）
- `_frame` 里模拟段条件从 `if (this.speed > 0)` 改成 `if (this.running && this.speed > 0)`，
  渲染段无条件

### 3. 物种工坊手动放置 + 导出落程序目录

## 阶段 7 补充②：参数倍率 + 橡皮擦 + 扩展讨论（2026-10-16 深夜）

### 1. 两个全局能量旋钮

用户要"全局消耗量倍率 + 食物量倍率（调节一个食物能提供多少能量）"。

- **消耗量倍率其实早就有了**（`life.metabolismScale`，默认 0 = 关闭），只是标签叫"代谢消耗倍率"。
  改成**「全局消耗量倍率」**对齐用户表述，key 不动（存档兼容）。
- **食物量倍率是新的**：`life.foodEnergyScale`，默认 1。
  - 落点只有一处：`BodyCell.mouthFunction` 的 `organism.energy += 1` → `+= foodEnergyGain(world.config)`。
  - 新增导出 `foodEnergyGain(config)`，非法值（0 / undefined / NaN）兜底成 1——
    旧存档没有这段也不会把进食变成 0 能量。
  - **只影响"吃进来多少"**，不影响生产者造食、也不影响死亡掉落的食物份数。测试专门锁了这条。
  - 面板范围 0.1–10。
- 两个倍率是一对互补旋钮：推消耗会把生态推向灭绝（§6.4 的扫描），推食物量不会。

### 2. 橡皮擦笔刷

用户要"只删墙壁等无机像素、不影响细胞的笔刷，命名为橡皮擦"。

- `Editor.js` 新增 `BRUSH_ERASER = 'eraser'` + `_eraseCell(col,row)`。
- **判据是 `grid.owners[index] < 0`**（生物写格子时登记 owner，地形不登记），
  而不是"类型是不是 EMPTY/FOOD/WALL"——前者不依赖类型枚举，将来加新地形不用改代码。
- 吃 `brushSize`，走 `_strokeLine` → 拖动擦除也正常。
- `Toolbar.js` 的 `BRUSHES` 加一项（配色 `#cbd5e1`），`_syncSwatches` 里给橡皮擦一句专属提示。
  `isTerrain` 判据天然包含它（不等于 ORGANISM/CLONE），所以笔刷大小行会正常显示。
- **和「空」笔刷的区别**（写进 DESIGN §9.1）：「空」是无差别覆盖，刷过生物会抹掉身体、留残骸；
  橡皮擦只擦地形，正好用来"给生物开路 / 清场地而不伤它们"。两者并存。
- 注意：`SpeciesEditor` 里也出现过"橡皮擦"这个词（工坊调色板里 EMPTY 的 title），
  那是蓝图编辑器语境，不冲突。

### 3. 扩展讨论（DESIGN.md §15.1–15.4）

用户要"讨论可以添加的其他几种细胞类型以及无机像素"。整理成四节：

- **成本模型**：不可见的无机像素 = 改 1 处（极低、存档兼容）；
  不可见的身体细胞 = 低；需要"进入某格有反应"的地形 = 中（要先加 `onEnter` 钩子）；
  `visible: true` = **高（作废旧存档大脑）**——`VISUAL_SLOTS` 9 写死、`SENSE_DIM` 40。
  三条硬约束：id 必须 < 64（`VISION_SLOT` 是 `Int8Array(64)`）、`visible` 是破坏性的、
  `Toolbar.BRUSHES` 仍是手写的（建议改成由 `PAINTABLE_CELL_TYPES` 派生）。
- **细胞类型**（按性价比）：储食（中，但是让消耗倍率成为主玩法的前置）、再生（低）、
  刺/反伤（低）、毒素（低–中）、粘附/触手（中）、光合（高，要场系统）、嗅觉/听觉（高，破坏存档）。
  最推荐储食 + 再生 + 刺。
- **无机像素**：岩石（低，价值有限）、岩浆 / 沼泽 / 水 / 冰 / 辐射带 / 腐殖质（低–中，**共用 `onEnter` 钩子**）、
  传送门（中）、光源（高）。最推荐岩浆 + 沼泽 + 辐射带 + 腐殖质。
  特别地，**辐射带**（区域内扣血但变异率 ×N）是解决"眼睛一直稀有"的另一个思路：
  它提高"探索新区域"的收益，而探索需要感知。
- **实施顺序**：`onEnter` 钩子 → 四个地形 → 储食 → 再生+刺 → 派生 BRUSHES → 最后才是环境场。

## 阶段 8 批次 1：地形与 onEnter 钩子（2026-10-16 深夜）

用户说"现在可以开始了"，按排好的顺序做第一批：
**橡皮擦改法 → onEnter 钩子 → 岩浆/沼泽/辐射带/腐殖质**。

### 0. 橡皮擦改法

用户要求"只擦墙、留下食物"。实现成 **只清地形（注册表的 `terrain` 标记），食物与生物一律不动**——
这样以后加岩浆/水/冰不用再改代码。走 `setCellAt(EMPTY)`（连地板一起清），不是 `revealFloor`。

### 1. 最大的架构改动：`floor` 地板层

**实现到一半发现的真问题**：生物 `writeGrid()` 会把 `types` 覆盖成自己的细胞类型。
如果地形只存在 `types` 里，**一只生物从岩浆上走过，岩浆就被抹掉了**——地形会被生物啃光。

所以 `GridMap` 加了第三层 `Uint8Array floor`：
- 生物盖上去只改 `types`，`floor` 不动
- 生物离开调 `World.revealFloor(index)` 把地板铺回顶层
- **只有玩家画"空"/橡皮擦才真清地板**（`setCellAt(EMPTY,-1)` 连地板一起清）
- 食物被吃 / 腐败也走 `revealFloor` → 压在腐殖质上的食物吃完后腐殖质露回来
- 食物**不在** floor 里（资源不是地形）

这是本批最关键的改动，也是后面水/冰/毒素场的基础。

### 2. 三个钩子

注册表加 5 个字段：`terrain` / `passable` / `enter` / `stand` / `tick`。
函数写在新的 `life/Terrain.js`，数值写在 `Config.terrain`（新分组，6 项）。

| 钩子 | 触发 | 调用方 |
|---|---|---|
| `enter` | 移动成功那一下 | `Organism.attemptMove()` |
| `stand` | 驻留每 tick（移动之后） | `Organism.act()` |
| `tick` | 世界级每 tick | `World.applyTerrainTick()` |

**`enter` 和 `stand` 必须分开**：只做 enter 表达不了"待在辐射带里持续掉血"，
只做 stand 丢掉了"踏进岩浆烫一下"的瞬时冲击。

**读的是 `floor` 层而不是顶层 `types`**——生物自己的细胞就压在枢轴格上，
顶层是它自己，只有地板层知道它脚底下踩的是什么。这条一开始写错了（读 types），
CDP 测试里"站在辐射带上掉血"直接测不出来。

### 3. 四种地形

- **岩浆** `enter: burn` + `stand: burn`：踏入 2 伤、驻留 1 伤/tick。3 格生物踏进去活不过一 tick
- **沼泽** `enter: bog`：移动额外耗 0.5 能量
- **辐射带** `stand: irradiate`：0.25 伤/tick + `inRadiation` 标记
- **腐殖质** `tick: fertilize`：0.5%/tick 往相邻空格冒食物，用 swap-remove 索引（和食物索引同一套）

**辐射倍率不能直接改 `mutability`**（5% ×3 ×3 ×3 三 tick 就封顶）：
只打一个每 tick 重置的 `inRadiation` 标记，由 `Mutation.mutateOrganism` 在**繁殖那一步**
临时乘 `radMutationBoost`（默认 3）。语义才准确。

### 4. 画笔列表派生

`Toolbar.BRUSHES` 从手写改成由 `TERRAIN_BRUSH_TYPES`（`independent && paintable`）派生。
注意**不能用 `PAINTABLE_CELL_TYPES`**——它含身体细胞（只能在工坊蓝图里画，不该出现在世界画笔里）。

### 5. 存档升 v2

`grid.walls` → `grid.terrain: { KEY: [索引] }`，存的是 **floor 层**（含被生物踩住的）。
v1 存档仍能读（退回读 `walls` 当"只有墙的地板"）。`SAVE_VERSION = 2`。

### 踩的坑（回归测试抓到的真 bug）

**给 `FOOD` 也标了 `passable: true`** → `isPassable(FOOD)` 返回 true → 把
`combat.foodBlocksReproduction`（默认 true，食物本该挡路）**直接架空了**。
症状：phase5-test 的"读档后继续演化可复现"**第 48 tick 分叉**（RNG 状态也分叉）。

定位过程：探针脚本对比 → 地板/RNG/食物索引/个体内部状态全一致 → 逐 tick 比 RNG 状态 →
第 48 tick 分叉 → 说明有代码路径不同 → 排查 `isClear` 的新增分支 → 发现 FOOD 的特例被短路。

修法：`isPassable()` **只对 `terrain: true` 的类型生效**，食物那条特例只由
`isClear` / `canPlaceAt` 一处管。

## 阶段 9：储食 / 再生 / 刺三种新身体细胞（2026-10-16 深夜）

用户说"继续下一步"，按排好的顺序做：**储食细胞 → 再生 + 刺**。
三种都是纯身体细胞、不需要场系统，改动面高度重叠（注册表 / 行为表 / 属性表 / 调色板 / 测试），一次做完。

### 1. 储食（STORAGE, id 13）

**关键设计：把"繁殖阈值"和"繁殖成本"拆开。**

```js
reproduceAt() {          // 触发阈值：储食细胞抬高它
  const base = this.foodNeeded();
  if (!this.anatomy.hasStorage) return base;      // ← 无储食时逐位相同，基线不变
  return base * (1 + this.storageCount() * Config.life.storageFoodBonus);
}
// act():        if (energy >= reproduceAt()) reproduce();
// reproduce():  energy -= foodNeeded();          ← 扣的是基础成本，不是阈值
```

于是储食个体要攒到 2× 能量才繁殖，但只花 1×，**剩下的 1× 留在身上 = 储备**。

这是让「全局消耗量倍率」成为主玩法的钥匙——之前生态一开消耗就崩，根因是生物能量长期贴着 0
（一攒够就繁殖掉），没有任何缓冲。

- `foodValue: 3`：脂肪是热量密度最高的组织，死掉之后尸体格外肥
- `energyRatio` 改用 `reproduceAt()`（能量条显示的是"离繁殖还有多远"）
- 默认 `storageFoodBonus = 1`（调到 0 就退回"储食只是块普通肉"）

### 2. 再生（REGEN, id 14）

写成 `BodyCell.CELL_BEHAVIORS.regen`，而不是在 `act()` 里特判 `hasRegen`：
行为表本来就是**按细胞逐个调用**的，所以"每多一个再生细胞就多回一份血"自动成立，不需要任何计数逻辑。

它抹的是 `damage`（已累积的伤害），不是"加生命上限"。所以再生和装甲互补：
**装甲让伤害进不来，再生让伤害慢慢退回去**。默认 `regenRate = 0.1`/细胞/tick——
比杀手的 1 点/tick 慢，所以它只是"减缓死亡"，救不了站在岩浆里的个体。

### 3. 刺（SPIKE, id 15）

`Organism.harm(amount, attacker)` 多了一个 `attacker` 参数：
- **只有生物之间的近战会传**（目前只有杀手细胞 `killerFunction`）
- 地形伤害（岩浆/辐射）不传 → 站在岩浆里不会去扎岩浆
- **反伤时不再往下传 attacker** → 递归深度恒为 1。不截断的话两只带刺的会无限互扎（爆栈）
- **刺不吃装甲减免**：装甲挡的是"被咬"，挡不住"被扎"（反伤走 `harm()`，装甲判定在 `killerFunction` 里，
  两条路）。这让刺能对"装甲 + 杀手"这条路线形成制衡

### 4. 三种都 `visible: false` → 没有造成存档断代

感知扩容要动 `VISUAL_SLOTS`(9) / `SENSE_DIM`(40)，会让旧存档大脑失效，所以留到最后一批统一做。
在那之前新细胞只是"身体的一部分"，别的生物看不见，但照样占格子、照样有成本。

### 5. 顺手改的

- `window.evosim` 暴露 `CellType`（调试与 CDP 测试都用得上）
- `Inspector` 的「繁殖所需」改成「繁殖阈值」，并显示 `reproduceAt()`；状态行加"储备 N / 反伤 N"
- 阶段徽章改成「阶段 9 · 储食 / 再生 / 刺细胞」

### 6. 回归时抓到的一处脆弱断言

phase5-test 有一条"眼睛细胞带朝向"依赖**"演化 60 tick 内自然长出眼睛"**。
加细胞类型会改变 `LIVING_CELL_TYPES`（变异候选池）→ 整条演化轨迹改变 → 眼睛没出现、断言翻车。

不再赌演化。这是本项目第一条"测试不能依赖随机演化结果"的教训。
