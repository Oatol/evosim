## 用户反馈的三个检视器毛病（根因同一个）

用户报告：克隆时提示"先用检视选中"、点检视器外区域会关掉它、"跟随"按钮无效。
排查后确认三个症状**同一个根因**：`Inspector` 是全屏模态（`.inspector{position:fixed;inset:0}`
+ 遮罩 `inset:0`），遮罩盖住了整个视口（含左右栏、顶栏、时间轴）：

1. **跟随其实在工作**（`camera.updateFollow` 每帧把相机对准该个体），但画布被遮罩盖住 → 看不到。
2. **"克隆选中"永远失败**：遮罩盖住工具栏，点按钮其实点在遮罩上 → 触发 `backdrop.click → close()`，
   选中被清空；第二次点才落到按钮上，此时已无选中 → 提示"先用检视工具点一个个体"。
3. **关闭按钮其实一直有**（右上角 `×`），只是 26px 的小按钮在全屏遮罩的观感下不显眼。

修法：改成**不挡画布的非模态浮窗** + **图钉锁定** + 加"保存生物"。三个症状一起消失。

### 关键设计决定

1. **默认值与旧行为逐位等价**：hp=1、foodValue=1、杀手 damage=1 → 升级到注册表后生态完全不变，
   既有测试与实测数据继续有效。这是"大重构不破坏已验证基线"的关键。
2. **代谢消耗默认关闭**。扫描（12000 tick × 3 种子）显示消耗×1 就有 1/3 种子灭绝。根因不在数值大小，
   而在**能量模型**：生物能量长期贴近 0（一攒够 `foodNeeded` 就繁殖掉），任何消耗都让它们立刻饥饿；
   生产者 5%/tick 的造食率也撑不起持续支出。可用组合：「消耗×1 + 造食率 15%」→ 稳定 ~2300 不灭绝。
3. **派生量不缓存**（`maxHealth`/`upkeepCost`/`foodValueTotal`）。属性可随时在面板改，缓存会读到旧值；
   调用频率（每个体每 tick 一次 + 每次挨打一次）不值得引入失效逻辑。
4. **饿死有缓冲**（`starvationTicks=60`）。没有它，刚出生（能量为 0）的个体会当 tick 暴毙。
5. **注册表是唯一事实来源**。加一种细胞 = 加一个定义对象；参数面板的 30 行控件也是自动生成的。
6. **`Config.cells` 用嵌套对象 + 面板字段键用点号路径**（`MOUTH.hp`），比扁平键更可读，
   且运行时读取不用拼字符串。
7. **生物库读回统一走 `blueprintOf()`**：库里存紧凑数组 `[type,dx,dy,dir?]`，任何地方要对象数组都从它转。

### 解决 / 发现的问题

- **`SpeciesEditor._loadEntry` 把紧凑数组当对象数组读**（真 bug，CDP 测试抓到）：库里存的是
  `[type,dx,dy]`，代码却写 `dx=c[0]`（其实是 type）、`type=c[2]`（其实是 dy），载入的蓝图整个错位。
  改成走 `library.blueprintOf(entry)`。
- **检视器全屏模态遮罩**（真 UX 问题，用户反馈）：见上，改成非模态浮窗。
- **`setPointerCapture` 在合成 PointerEvent 上会抛**：拖动测试用 `dispatchEvent(new PointerEvent(...))`，
  `pointerId` 不是真实指针 → `InvalidPointerId`。包 try/catch（对真实场景也更稳）。
- **测试自身的两处错**：视觉测试读错了方向分组的槽位下标（眼睛朝右 → base = 1×9 而不是 0）；
  "关闭消耗时能量不变"用了 energy=5，结果顺手触发了繁殖（`energy >= foodNeeded` → 扣 1），
  改成 0.5。
- **CDP 断言硬编码阶段号**：cdp-phase5/6 又各中一次，统一改成 `/^阶段 \d/`。

### 1. 物种树占满整个空间（看不到画布 / 高亮）

和当初检视器犯的是**同一个错**：全屏模态遮罩。用户原话"物种树页面占了整个空间，

  width:min(720px, calc(100vw - 300px)); height:min(560px, calc(100vh - 120px)); pointer-events:auto`
- head 里加图钉（`pinBtn`），**默认锁上**（`this.pinned = true`）——树是参照物，
  选完物种还要回画布操作；解锁后点画布才关
- 接上 `enableDrag(head, panel)`；`_bindOutsideClose()` 判据是
  `event.target.closest('.canvas-wrap')`（"点没点在画布上"，不是"点没点在面板外"）

**这是本项目第二次踩"全屏 backdrop"这个坑**，所以三个浮窗（inspector / species-editor /
species-tree）现在共用同一条规则，已写进 DESIGN.md §9.4。

### 2. 暂停时准星也冻住

根因：`Engine.pause()` 里调了 `cancelAnimationFrame` → `onFrame` 不再触发 →
准星 / 高亮 / 浮窗全部停在最后一帧。

改法：**渲染循环与模拟解耦**。
- `pause()` 只 `running = false` + `_accumulator = 0` + `_ensureLoop()`，不再取消 RAF
- 新增 `stop()` 供真正停掉循环（页面销毁用）
- 新增 `_ensureLoop()`：`_rafId === null` 时才挂帧
- `_frame` 开头把 `_rafId = null`（这样暂停/继续都能安全重挂）
- `_frame` 里模拟段条件从 `if (this.speed > 0)` 改成 `if (this.running && this.speed > 0)`，
  渲染段无条件

### 3. 物种工坊手动放置 + 导出落程序目录

## 阶段 7 补充②：参数倍率 + 橡皮擦 + 扩展讨论（2026-10-16 深夜）

### 1. 两个全局能量旋钮

用户要"全局消耗量倍率 + 食物量倍率（调节一个食物能提供多少能量）"。

- **消耗量倍率其实早就有了**（`life.metabolismScale`，默认 0 = 关闭），只是标签叫"代谢消耗倍率"。
  改成**「全局消耗量倍率」**对齐用户表述，key 不动（存档兼容）。
- **食物量倍率是新的**：`life.foodEnergyScale`，默认 1。
  - 落点只有一处：`BodyCell.mouthFunction` 的 `organism.energy += 1` → `+= foodEnergyGain(world.config)`。
  - 新增导出 `foodEnergyGain(config)`，非法值（0 / undefined / NaN）兜底成 1——
    旧存档没有这段也不会把进食变成 0 能量。
  - **只影响"吃进来多少"**，不影响生产者造食、也不影响死亡掉落的食物份数。测试专门锁了这条。
  - 面板范围 0.1–10。
- 两个倍率是一对互补旋钮：推消耗会把生态推向灭绝（§6.4 的扫描），推食物量不会。

### 2. 橡皮擦笔刷

用户要"只删墙壁等无机像素、不影响细胞的笔刷，命名为橡皮擦"。

- `Editor.js` 新增 `BRUSH_ERASER = 'eraser'` + `_eraseCell(col,row)`。
- **判据是 `grid.owners[index] < 0`**（生物写格子时登记 owner，地形不登记），
  而不是"类型是不是 EMPTY/FOOD/WALL"——前者不依赖类型枚举，将来加新地形不用改代码。
- 吃 `brushSize`，走 `_strokeLine` → 拖动擦除也正常。
- `Toolbar.js` 的 `BRUSHES` 加一项（配色 `#cbd5e1`），`_syncSwatches` 里给橡皮擦一句专属提示。
  `isTerrain` 判据天然包含它（不等于 ORGANISM/CLONE），所以笔刷大小行会正常显示。
- **和「空」笔刷的区别**（写进 DESIGN §9.1）：「空」是无差别覆盖，刷过生物会抹掉身体、留残骸；
  橡皮擦只擦地形，正好用来"给生物开路 / 清场地而不伤它们"。两者并存。
- 注意：`SpeciesEditor` 里也出现过"橡皮擦"这个词（工坊调色板里 EMPTY 的 title），
  那是蓝图编辑器语境，不冲突。

### 3. 扩展讨论（DESIGN.md §15.1–15.4）

用户要"讨论可以添加的其他几种细胞类型以及无机像素"。整理成四节：

- **成本模型**：不可见的无机像素 = 改 1 处（极低、存档兼容）；
  不可见的身体细胞 = 低；需要"进入某格有反应"的地形 = 中（要先加 `onEnter` 钩子）；
  `visible: true` = **高（作废旧存档大脑）**——`VISUAL_SLOTS` 9 写死、`SENSE_DIM` 40。
  三条硬约束：id 必须 < 64（`VISION_SLOT` 是 `Int8Array(64)`）、`visible` 是破坏性的、
  `Toolbar.BRUSHES` 仍是手写的（建议改成由 `PAINTABLE_CELL_TYPES` 派生）。
- **细胞类型**（按性价比）：储食（中，但是让消耗倍率成为主玩法的前置）、再生（低）、
  刺/反伤（低）、毒素（低–中）、粘附/触手（中）、光合（高，要场系统）、嗅觉/听觉（高，破坏存档）。
  最推荐储食 + 再生 + 刺。
- **无机像素**：岩石（低，价值有限）、岩浆 / 沼泽 / 水 / 冰 / 辐射带 / 腐殖质（低–中，**共用 `onEnter` 钩子**）、
  传送门（中）、光源（高）。最推荐岩浆 + 沼泽 + 辐射带 + 腐殖质。
  特别地，**辐射带**（区域内扣血但变异率 ×N）是解决"眼睛一直稀有"的另一个思路：
  它提高"探索新区域"的收益，而探索需要感知。
- **实施顺序**：`onEnter` 钩子 → 四个地形 → 储食 → 再生+刺 → 派生 BRUSHES → 最后才是环境场。

### 2. 读了 The Powder Toy 源码，得出三条直接启发

- 它的空气/热场是**粗粒度**的：`Air.h` 里 `ovx[YCELLS][XCELLS]`，`CELL = 4` —— 每 4×4 像素一个场单元
- 每个粒子带 `temp` + 4 个通用槽 `tmp/tmp2/tmp3/tmp4` + `life`（我们现在的格子没有每格状态）
- 元素属性声明式：`HeatConduct / HeatCapacity / Diffusion / Advection / LowTemperature→Transition /
  Properties(RADIOACTIVE)`——和我们的 `CELL_DEFS` 注册表是同一个思路

**性能账**（决定场怎么做）：200×150 = 30000 格，0.65 ms/tick，×50 倍速约 1000 tick/s。
- 全分辨率场：O(30000)/tick × 1000 = **1.2 亿次操作/秒 → 不可行**，必须降频
- 8×8 粗场（475 单元）：约 1900 次操作/tick → **可忽略**

### 3. 可行性评估（全部可行，两个分水岭）

逐项评估了 onEnter 钩子、6 种地形、6 种细胞、温度/辐射场、悬停查看。成本分档：
- 极低：橡皮擦改法
- 低：`onEnter` 钩子、再生、刺/反伤、岩浆、沼泽、辐射带、腐殖质、派生画笔、视觉扩容
- 中：储食细胞（改繁殖节奏，但默认对无储食者零影响）、粘附/触手（死锁风险）、冰（惯性）
- 中–高：温度/辐射场、毒素完整场（都依赖场系统）

**两个真正的分水岭**：① 场怎么建 ② 场要不要影响模拟。其余是体力活。

### 4. 用户通过选择题拍板的四个决策

1. **场用粗粒度**（8×8 或 4×4）
2. **温度/辐射先只做"可观察"**（扩散/衰减/悬停可看，暂不影响生物）
3. **毒素走完整场**（释放→浓度→扩散→降解→抗性，上限 0.9 不是免疫）
4. **分批交付**：onEnter+4 地形 → 场+悬停 → 储食/再生/刺 → 毒素/粘附 → 派生画笔+视觉扩容

### 5. 我自己定、用户未反对的三处

- `onEnter` 拆成 **`onEnter`（踏入瞬间）+ `onStand`（站着每 tick）**——辐射带/腐殖质这类
  "区域效果"只做 onEnter 实现不了
- **储食细胞**抬高繁殖阈值 `reproduceAt = foodNeeded × (1 + Σ储食细胞 × k)`，无储食者 k=0
  基线逐位不变。这是让"全局消耗量倍率"成为主玩法的钥匙（生态崩掉的根因是没有能量缓冲）
- **抗性上限 0.9**：毒素细胞越多抗性越高，但永远留 10% 伤害
