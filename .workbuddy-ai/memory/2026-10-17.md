## 新一轮需求评估前的性能实测（未改一行代码）

用户这一轮提了 8 件事，其中两件是重量级方向问题（每像素环境属性、要不要换架构），
明确要求"先讨论可行性，不要改动"。所以在讨论前先把**性能账**量清楚——否则"要不要换 GPU/换架构"
只能靠猜。

### 实测数据（Windows / Chrome / 200×150 = 30000 格）

| 项 | 实测 | 说明 |
|---|---|---|
| `world.step()` 稀疏（9 只） | 0.027 ms/tick | |
| `world.step()` 满载（1517 只） | **2.0 ms/tick** | ≈1.3 µs/只 |
| `renderer.render()` zoom 2 / 4 | 0.002 / 0.003 ms/帧 | 低倍率几乎免费 |
| `renderer.render()` zoom 8 / 16 | 0.54 / 0.13 ms/帧 | 高倍率 drawImage 放大 |
| `render()` 含全量层重建 | 0.26–0.30 ms/帧 | 30k 像素重涂 0.043 ms |
| 1× | 144 fps · 60 tps | 完全流畅 |
| 10× | **4 fps** · 600 tps | 模拟吃满线程 |
| 50× | **4.6 fps** · 1838 tps | 追不上 3000 tps 目标 |
| 单只大脑前向 | 1.01 µs | 扁平化批处理 0.68 µs（仅 1.47×） |
| 全分辨率 5 点扩散 | 0.13 ms/次 | 60Hz 只要 8 ms/s |

### 三条结论

1. **渲染不是瓶颈**：0.1–0.5 ms/帧。换 WebGL/WebGPU 只省不到 1% 的帧时间 → 不值得。
2. **瓶颈是 CPU 模拟**：每只生物 ~1.3 µs/tick，其中**大脑前向就占 1.0 µs**（40→12→5）。
   10× 时 600 tick/s × 2 ms = 1.2 s/s，线程被模拟吃光，帧率塌到 4 fps。
3. **每像素场其实很便宜**：全分辨率扩散 0.13 ms/次。只要**场更新频率与 tick 解耦**（按 60Hz 墙钟走，
   不随倍速），5 个场加起来也只有 4% 的 CPU。之前"必须用粗粒度场"的判断，是在"每 tick 都扩散"的
   前提下算的——那个前提现在可以不要。

### 关键矛盾（必须解决）

用户同时选了"Rust 全原生重写"与"先做 UI 小件"。**如果 UI 最终要用 egui/自绘重写，
那么现在往 JS 版加的 UI 功能大部分是白做**。处理方式：
- **只把"内容/数据"落在 JS 侧**（细胞与笔刷简介文案 → 注册表字段，可导出成数据文件给 Rust 读）
- **蓝图缩放、环境场、性能**直接进 Rust，不做双份实现
- JS 版冻结新功能，只修 bug，作为**参照实现**与黄金快照来源

### 重写体量（实测统计）

- 34 个 JS 模块 / **9128 行**（UI 约 3000 行、模拟内核约 3500 行、渲染 424 行）
- 逻辑测试 **549 条断言**（phase3–9-test）+ CDP 端到端 300+ 条
- 预计 Rust 版 ~7000 行；工具链已就绪：cargo/rustc **1.99.1**，host `x86_64-pc-windows-msvc`
- 卖点：单 exe 预计 **8–15 MB**（现在 Node SEA 是 83 MB）

### Rust 侧的性能预期（有依据）

- `think()` 是**只读阶段**、占每只成本的 77% → rayon 天然可并行，8 核 ≈ 6×
- `act()` 写世界，需顺序或按区域分片
- 综合预期：`step` 2.0 ms → **0.2–0.4 ms**（满载 1500 只），50× 倍速可跑满
- 每像素温度/辐射场在 Rust 里几乎免费（30k × f32 扩散 ≈ 几十 µs），可选 wgpu compute 进一步下放

### 讨论中被否掉的选项（记下来，避免以后再绕）

- **完全自研控件层**：真实账单 ~3300 行 / 9–10 天，多出来的主要是输入路由、滚动、**单行编辑器 + IME**——
  这些不是用户想要的东西，但必须付。多花 5 天只换来"第 ③ 层自己实现了一遍"
- **egui 只改主题**：4 天，但外观是"普通桌面软件"，不是 TPT
- **iced**：样式系统偏 Material，密度压不下去
- **bevy + egui**：编译 3–6 分钟、体积 25–40 MB、ECS 与 SoA 设计打架
- **首期只到"能看的最小窗口"（B）**：无法判断手感——而手感是这个项目最值钱、重写最容易丢的部分

### 关键技术结论（查过代码，有依据）

- **`think()` 不碰 RNG**（读了 `Organism.think()` 与 `Sensors`）→ rayon 并行绝对安全，且占每只成本 77%
  → **第一期就能拿 3–5×**，不必等 M5
- 世界纹理用 **R8 索引 + 256 色 LUT 着色器**（不是每帧传 RGBA）：带宽 120 KB → 30 KB/帧，
  且换配色/切图层滤镜不用重传；M4 的温度/辐射场是同一着色器多采一张纹理
- 缩放必须 **NEAREST + 世界平铺**，复刻现有观感
- 中文字体**子集化后 300–600 KB**（不是 3–5 MB），exe 体积基本不受影响
