## 批次 4 · 谱系树（`app/lineage.rs` + `panels.rs`）

物种面板原来是「一行一个物种、横条 = 存续区间」的甘特图。要看出「谁是谁的后代、哪一支活下来了」，
光有横条不够：父子可能隔着几百行，硬画连线就是一团交叉。

**排序是全部的关键。** 按祖先关系做 **DFS**，同一支的后代紧挨在父物种下面。排序对了，连线就退化成
「每个非根物种**一根竖线**」——从父物种那一行、在子物种出现的那个 tick 竖下来，正好落到自己横条的左端。
这就是时间标定的系统发生树（chronogram），天然不交叉。

实现要点
- **显式栈，不用递归**：物种数 ≈ 种群数时祖先链可能上千层，递归会爆栈。
- `ancestor_id` 存的是 `Species.id`，**不是 list 下标** —— `prune()` 会重排下标，只有 id 稳定。
- **过滤必须补全祖先链**：只按 `cumulative_pop >= N` 过滤会留下断头分支（父被滤掉、子还在），
  树变成一堆悬空枝条。可见集 =（通过过滤的）∪（它们的所有祖先），于是每个可见非根物种都有父行。
- 环兜底：祖先链成环（脏数据）时那些物种不会被任何根到达，遍历后补成独立根，
  保证 `rows.len() + hidden == reg.size()`（有测试守着）。
- `ScrollArea::show_rows` 只铺可见行（行高固定 15）。四位数物种全量 allocate 会卡成幻灯片。
  `show_rows` 假定每行占 `行高 + item_spacing.y`，传 15 时内容每行也必须真的是 15 + 4。

**时间轴必须能缩放**（这条是看图才发现的）：分叉几乎全发生在前几千 tick，而轴是 0..now 线性铺开的。
跑十万 tick 后所有分叉点挤在最左边十几个像素，树看着就是一根竖线 —— 结构对，但读不出来。
交互：轴条上**拖一段**放大、**滚轮**以光标为锚缩放、**双击/「全览」**复位。

**拖拽的坑**：`dragged()` 每帧都触发。若每帧都拿**当前**视图换算选区，就会在上一次结果上继续缩，
几帧之内窗口从 189805 tick 缩到 38 tick。修法：按下时快照视图（`species_drag`），全程以快照为基准。

**裁剪的坑**：缩放后若把窗口外的 tick 直接夹到边界，每个物种的条都会从左边拉到右边，
整张图变成一片横贯全宽的色块 —— 看着像"所有物种同时存在"，比不画还误导。
所以横条按窗口裁剪；存续区间完全在窗口外的物种仍列出来（拓扑需要它们当中间节点）但名字调暗；
分叉点在窗口左侧的连线则**故意夹到左边缘**（一条沿边界竖下来的"主干"），否则放大后的树会支离破碎。

UI 开关：`谱系树` / `只留活着的血统`（活着 + 祖先）/ `最少累计 1·2·5·10`。
实测 2150 个物种里开「只留活着的血统」后剩 34 个，可读性差别很大。

## 结论：粒度问题现在更明显了

谱系树做完之后，物种粒度过细的问题从"曲线退化"变成了"树退化" —— 每一代突变都开一个新物种、
父物种随即灭绝，于是"树"其实是"链"，`depth` 一路涨到缩进封顶（6 层）之后全是同一条线。
实现是对的，问题在数据。下一步修指纹判定（允许身体差 N 格仍算同种）。

## 讨论「指纹判定怎么改」时先量了一遍（结论推翻了我自己的判断）

加了 `crates/core/examples/species_stats.rs`（`f2f25be`）：
`cargo run --release -p evosim-core --example species_stats -- 150000 1001`

**实测（seed 1001）**

| | tick 60000 | tick 150000 |
|---|---|---|
| 个体 | 1562 | 1598 |
| 存活物种 | 73 | 78 |
| 累计物种 | 2054 | 4000（撞 `MAX_SPECIES` 上限） |
| 每存活物种摊到的个体 | 21.4 | 20.5 |
| 存活物种 vs 存活的不同「细胞组成」 | 73 vs 57 | 78 vs 47 |
| 累计物种 vs 不同组成 | — | 4000 vs 814 |
| 累计个体 < 5 的物种占比 | 73% | 69% |
| 存活物种祖先链深度 | — | 中位 4 / 最大 11 |
| 出生登记 | ≥3.60/tick | — |
| 新物种 | 0.034/tick | — |

**所以判定粒度本身是健康的**：20 个个体/物种、深度 4–11、存活 ~78 个。
我之前说「物种数 ≈ 种群数、退化成链」是**误读**——把「累计物种」当成了「存活物种」。

**真正的问题是显示**（未修，等讨论）：`ui.rs:293` 顶栏和 `panels.rs:123` 曲线采样都用
`world.species.size()`（累计），而 JS 版 `main.js:431` / `ui/Stats.js:100` 用的是
`world.species.aliveCount`。累计是单调爬升、撞 4000 上限后变平的，所以曲线看着"不对"，
顶栏「物种 2054」和「存活 73」并列也会让人以为粒度崩了。**这是移植 bug，两处改一个字段就行。**

**次要问题**：约 70% 的物种累计个体 < 5（"变异出来就死"的中间态）。谱系树 `min_cum` 默认 2 太松，
默认 5 或「只留活着的血统」开着更合适。

**布局敏感膨胀**：累计 4.9x（4000→814），但**存活层面只有 1.3–1.7x**（78→47）。
说明布局差异主要落在已灭绝的中间态上，对"现在有哪些物种"影响不大 ——
这也削弱了"必须改判据"的理由。

**成本约束**：出生登记 ≥3.6 次/tick。任何"跟所有已知物种算距离"的聚类方案 =
3.6 × 4000 ≈ 1.4 万次距离计算/tick，而整个 tick 的预算是 0.3ms —— **不能全局搜索**。
只能跟**父物种的型标本**比，O(cells)。

**关键前提（已核实）**：`state_digest`（`world.rs:1095`）只混网格 + 个体字段，
**不含指纹也不含物种表** → 改判据不会破坏 golden 对齐。但判据函数里**绝不能消耗 RNG**，
否则出生序列变化会让模拟本身分叉。

## 方案 A：修物种计数取值（`size()` → `alive_count`）

**改的四处**（都只是取值，不动模拟、不进 `state_digest`）：
- `ui.rs` 顶栏「物种 N」→ `alive_count`，悬停里附「累计 / 峰值 / 已灭绝」
- `panels.rs` 曲线采样 `Sample.species` → `alive_count`
- `world_panel.rs` 世界窗口摘要行 → `alive_count`
- `main.rs` CLI 的 `--screenshot` 与 `--bench` 输出 → 打「存活物种」

**同时收紧树过滤**：`species_min_cum` 默认 2 → **5**。依据是实测累计个体 < 5 的物种占约 69%，
它们把分叉挤成一条竖链。

**由此暴露的 UX 问题**：默认 5 之后，刚开的世界（150 tick）物种累计个体都还没到 5，
**树是空的**——两条 UI 测试当场挂掉（`species_timeline_draws_bars` / `zoomed_timeline_clips_bars`）。
处理：
- 测试里显式 `species_min_cum = 1`（测的是绘制逻辑，不是默认过滤强度）
- 空树时显示「没有符合条件的物种（累计 N 个，过滤：最少累计 5、只留存活）—— 把「最少累计」调小试试」，
  否则用户会以为面板坏了

**守门测试**：`sample_records_alive_species_not_cumulative` —— 先跑到出现灭绝物种（两个数才分得开），
再断言 `Sample.species == alive_count`。没有这条，下次谁再写回 `size()` 都无声无息。

**验证**：app 36 / core 26 / golden 2 / render 8 全绿，零警告。
CLI `--screenshot --ticks 60000` 输出「个体 969 · 存活物种 59」——量级对得上诊断数据（几十，不是几千）。

**⚠️ 本轮的验证短板**：当前会话的模型**读不了图片**，所以只能做程序化验证
（CLI 数字 + 单测），没能像前几批那样看截图确认顶栏和曲线的视觉效果。
顶栏数字来自 `alive_count` 已由代码和 CLI 双向确认，但**曲线形状、图例文案换行**需要人工看一眼。

## 批次 5：体型参数（繁殖成本指数 p + 体型上限）

**代码**：`LifeCfg` 加两个字段，参数面板末尾可调，存档 VERSION → 3。

| 字段 | 默认 | 含义 |
|---|---|---|
| `breed_cost_exponent` | 1.0 | 繁殖成本 = `体型^p`，1.0 = 线性（1.x 行为） |
| `max_body_cells` | 0 | 体型上限（细胞数），0 = 不限 |

**默认值必须逐字节等价旧行为**（黄金快照锁着）：
- `p = 1.0` 走分支不调 `powf(1.0)`；`breed_cost` 抽成自由函数，不构造 Organism 也能单测
- `cap = 0` 时连判断都不做 → 随机流与加参数之前完全一致
- 启用上限后会跳过"加细胞"那一次 `rng.chance`，随机流与无限版本错开——可接受，
  为了对齐而"先掷骰子再丢结果"是白耗随机数，且 `add_random_cell` 内部消耗量取决于身体内容，本来也对不齐

**扫描结论（`examples/body_scan`，15000 tick，seed 1001）**

| p | 个体 | 平均体型 | 最大体型 | 3 格占比 |
|---|---|---|---|---|
| 0.60 | 1901 | 2.99 | 4 | 94.3% |
| 0.80 | 555 | 3.05 | 4 | 91.4% |
| 1.00 | 1240 | 3.06 | 5 | 83.4% |
| 1.20 | 1413 | 2.94 | 5 | 72.2% |

- p 从 0.6 到 1.2，平均体型只动 **0.12 格**
- 体型上限 8 / 16 / 不限 **结果完全相同**（最大才 5 格，上限没东西可挡）
- p = 0.6 时 3 格成本才 1.93，若成本是瓶颈体型早该膨胀 —— 它没有

**真正的原因**：大体型**只有代价没有收益**。加一格 = +1 血 +100 tick 寿命，但
① 默认 `metabolism_scale = 0`，连"多吃多耗"的代价都没有
② 吃东西靠嘴的数量，不靠身体大小
③ 出生时 `can_place_at` 要求整块空地 —— **身体越大越难落脚**
净结果是轻微的反向选择，体型稳定在 3–4 格。调 p / 加上限都是在没有收益的地基上拧旋钮。

**方法论教训**：第一轮扫描用单种子单点，被噪声骗了（同 p 换种子种群 256 → 1157，4.5 倍）。
这模拟在临界点上，**任何单点结论都要多种子复核**。示例里已把这条写进文档。

**功耗约束**：用户机器满载会过热蓝屏（`clock_watchdog_timeout`）。原来那个
"9 个 p × 3 种子 × 4 万 tick + 14 组上限扫描"要跑 18 分钟满载，跑到一半被中断，输出也没留下
（`tail` 缓冲）。现在 `body_scan` 默认 15000 tick × 4 个 p × 1 种子 + 3 组上限，70 秒跑完。
**以后所有扫描都按这个量级控制。**

**验证**（全部程序化，未使用鼠标/截图）：core 32 / app 36 / golden 2 / render 8 全绿，零警告。
golden 2 项通过 = 默认值确实没改变行为。

## 批次 6：细胞参数按类型分化（`CELL_DEFS[i].params`）

**起因**：用户提出"不同细胞应该有不同的参数"。查下来发现不是"参数不匹配"，而是
**80 个滑块里 29 个是死旋钮**：

| 属性 | 真的读它的地方 | 白给的类型数 |
|---|---|---|
| `hp` / `cost` / `food_value` | 按格累加（max_health / upkeep / 尸体能量） | 0 |
| `damage` | 只有 KILLER 攻击、SPIKE 反伤 | **14** |
| `sense_range` | 只有 EYE（`is_directional` 才进视觉） | **15** |

**做法**：`CellDef` 加 `params: &'static [AttrField]`，每种细胞声明自己暴露哪几项，
顺序即显示顺序。UI 照着渲染，空数组（地形/空/墙/食物）显示一行说明而不是空窗。

| 细胞 | 参数 |
|---|---|
| 嘴 | 血量 · 消耗 · **摄取倍率** · 食物值 |
| 生产者 | 血量 · 消耗 · **生产速度** · 食物值 |
| 移动器 | 血量 · 消耗 · 食物值（一格/次，没有速度概念，用户确认不加） |
| 杀手 | 血量 · 消耗 · 伤害 · 食物值 |
| 装甲 | 血量 · 消耗 · **伤害减免** · 食物值 |
| 眼睛 | 血量 · 消耗 · 感知距离 · 食物值 |
| 储食 | 血量 · 消耗 · **储备倍率** · 食物值 |
| 再生 | 血量 · 消耗 · **再生速率** · 食物值 |
| 刺 | 血量 · 消耗 · 伤害 · 食物值 |

**5 个倍率是从全局下放的**：`bite_mult`(×food_energy_scale) / `prod_mult`(×food_prod_prob) /
`regen_mult`(×regen_rate) / `storage_mult`(×storage_food_bonus) / `armor_resist`(比例，1.0=完全免疫)。

**为什么用倍率不用绝对值**：绝对值要给 16 种细胞都填"合理"数，且默认值一变黄金快照立刻漂。
倍率写法让默认配置（全 1.0）**逐位不变**。存档 VERSION → 4。

**装甲改减免的坑**：`resist >= 1.0` 必须走 `continue` 的**快路径**，不能把伤害乘 0 送进
`harm_organism` —— 那个函数即使 `amount = 0` 也会触发刺的反伤和死亡判定，
会引入旧行为里没有的副作用。

**写端到端测试时踩的坑**：`act_organism` 末尾**包含繁殖判定**，能量够阈值就扣一份成本再生。
测"嘴吃了多少能量"时测出来是 4 份食物 → 3 点能量，因为繁殖扣了 1。
修法：先用储食细胞把阈值抬到 1000 以上隔离掉。**这个坑值得记：`act_organism` 不是"纯行为"。**

**测试**（85 项全绿，零警告）：
- core 37：新增 5 条端到端（bite/prod/regen/armor/storage 各自把倍率调离 1.0，
  断言结果跟着变且方向正确）+ 原有的 breed_cost 3 条
- app 38：新增 4 条守 `params` 声明（身体细胞必须有、地形必须没有、专属参数不能张冠李戴、
  通用参数每种都有）+ get/set 往返
- golden 2 通过 = 默认值确实没改变行为

**关键认识**：光"编译通过 + 默认值不漂"证明不了参数有用 —— 倍率乘错地方或压根没乘，
编译器和黄金快照都不会报错（默认 1.0 时乘不乘结果一样）。必须把倍率调离 1.0 去测。

## 批次 6.6：`细胞参数` → `类型参数`（细胞 + 地形合流），数据层统一成 `ParamRef`

**用户要求**："把细胞和地形的单独调整放在一起，毕竟另一个全局调整里放的是全局乘数

**先纠正自己的一个错误论断**：批次 6.5 我按"是不是细胞"把地形推给了全局参数，理由是

## 讨论：能量守恒能不能逼出复杂结构（未动手，仅设计讨论）

用户提出「总能量守恒 + 生产者是唯一入口 + 每细胞维持成本 + 死亡残骸回环境」，
并划界：守恒只对生命层严格成立，材质层（燃烧/反应）单独记账。

**查代码后确认：现在连守恒的地基都没有，有 4 个漏账点**
1. **生产者是永动机**：`food_prod_prob`（默认 5%）概率凭空造一个 FOOD 格，
   不消耗任何东西。每格食物固定值 `food_energy_scale × bite_mult`。
2. **维持成本为 0**：`metabolism_scale` 默认 0，活着不花能量。
3. **死亡时 `energy` 存量蒸发**：`kill_organism` 只把每个细胞格变成 FOOD，
   外加 `food_value_total - n` 份额外食物，**个体体内攒的 energy 完全丢弃**。
4. **食物是二值的**：`Grid` 只有 `types/owners/floor`，没有能量存量数组。
   "一份食物"是固定值，表达不了"吃了一半"。

**核心判断（写给未来的自己，别重复讨论）**
- **守恒是必要条件，不是充分条件。** 它只约束总量，不塑造形状。
  真正塑造形状的是梯度：空间不均匀、时间波动、捕食压力、功能不可兼得（一格只能一种细胞）。
- **守恒单独作用会压出「更精简」而不是「更复杂」**：成本线性、收益也线性 → 最优解是
  "刚好够用"的最小配置。现在 3 格体型（生产者+嘴+移动器）正是这个最小自给单元。
- **唯一能逼出复杂结构的路径是军备竞赛**：守恒 + 外生食物 → 捕食比自己产更划算 →
  捕食者出现 → 装甲/刺 → 感知预警 → 移动逃跑 → 正反馈。
  没有捕食压力，守恒只会让生物更小更省。
- **代谢成本必须有 sink**：能量不是被"删除"，是转成热进环境热池。直接减掉账就不平。
  用户方案里"维持成本"没写去处，这是必须补的一环。
- **±0.1% 的断言在 f64 下不可靠**：10^7 次累加会漂。要么定点整数记账，
  要么把审计做成每 tick 增量对账（而不是总量比对）。

**如果要做，最小可行第一步**：生产者改成"太阳能→食物"的转换器（效率 < 1）+
维持成本接上 + 死亡回收 energy。**先不做食物存量化**（那是 `Grid` 加数组、存档升版本的大改）。
预计现有生态会崩（现在的稳态建立在"食物免费"上），要准备好重新调平衡。

## 讨论续：用户提出「光场 + 光合直充体内 + 食物=尸体」方案（评估：方向对了）

用户方案：引入光场（生产者只在有光处转换）→ 能量**直接进生物体内**（不经食物格）→
现有食物变成**死亡后的能量储存形式**（所以狩猎才有意义）→ 手动放食物 = 外部注入。

**为什么这版比上一版好一个量级**
1. **补上了上一轮我说缺的「空间异质性」**：光场天然不均匀，移动/驻留/领地第一次有了价值。
2. **绕过了「食物存量数组」这个大改**：能量直接进 `organism.energy`，`Grid` 不用加数组。
3. **守恒账自然闭合**：食物=尸体，尸体里的能量是死者生前攒的（已记账的能量换个容器），
   不需要"凭空造食物"。账变成 `E_bio = Σ个体.energy + Σ尸体格能量`，注入只有光合一处。
4. **嘴 vs 生产者 变成 自养 vs 异养 的生态二分**——这是真实生态的结构，也是复杂化的原料。

**最大的意外收获：身体布局第一次有意义。**
现在 anatomy 只是"占几格"，布局无关紧要（3 格随机堆）。有了**方向性光 + 遮挡**之后，
生产者该朝光、嘴该朝尸体、移动器该在尾部——从"数量"进化到"结构"。
这是这个方案真正的价值，比守恒本身重要。

**必须现在决定的 5 件事（我的倾向）**
1. 能量容量上限 → 用**储食细胞提供容量**，把"抬高繁殖阈值"改成"电池"。否则无限膨胀。
2. 光的时间分布 → 加**昼夜循环**。这是让储能成为刚需的最强选择压，实现极简（光强 = f(tick)）。
3. 光合 vs 捕食的收益比 → 决定生态能否分化，只能靠扫描调，没有解析解。
4. 尸体能量分配 → **按死者 energy 分摊到各格**（肥的死了留肥尸体）。`food_value` 退化成每格容量上限。
5. 黄金快照 → **必须做 `energy_model: Legacy | Conserved` 双模式**，默认 Legacy。
   否则 1.x 逐位对齐这块质量基石就没了，而且没法做 A/B 对照。

**其它要注意**：食物腐败（`food_decay_rate=2%`）变成"能量流失"，必须记账去处；
墙遮挡光会产生天然洞穴生态（暗处只能异养），这是免费的生态多样性来源。

## 决策：放弃黄金快照维护，重心全转 Rust；腐败渐进化 + 卵生（讨论）

**用户明确：黄金快照以后不再维护，重心全放 Rust 版。**
→ 解除了最大的一条约束：默认值可改、数据结构可改、存档可随意升版本、
  `tests/golden.rs` / `tools/parity-check.mjs` / `tools/export-golden.mjs` 可删。
→ **但要注意：黄金快照同时是唯一的回归护栏。** 建议换成「特征化测试」
  （记录当前版本的种群/物种/体型基线，偏差超阈值报警），比重金快照宽松但能抓大崩。

**腐败改渐进式（用户要求）**
现在 `food_decay_rate=2` 是「每 tick 2% 概率整格消失」——断崖式。
改成食物带能量存量、每 tick 衰减。建议公式 `e -= max(abs_floor, e * rel_rate)`：
- `rel_rate`（~1%/tick）让大块肉慢慢烂
- `abs_floor`（~0.05/tick）让小块肉干脆消失，避免 0.001 能量赖着不走
- 流失的能量进热池（守恒账要过）
- 可视化：食物颜色深浅 = 剩余能量（玩家能看出这块肉还剩多少）
- **额外收益：大尸体变成长期资源** → 捕食者愿意守/抢 → 生态有节奏

**卵生（用户猜想，一起讨论）**
核心价值不是"省空间"，而是**把「繁殖」和「找空间」解耦**：
产卵只需 1 格（容易），孵化才需要 N 格，且可以无限期等待。
→ 一个生物在拥挤期可以攒多个卵（卵库），空间一释放就同时孵化 → **r/K 策略分化**。

**但必须说清楚：卵生对「体型变大」帮助有限。** 孵化仍然要 N 格连续空地，
概率还是指数下降。卵只是能等。真正让体型变大还得靠「大体型的收益」，
或者降低拥挤度（更大的世界 / 更低的种群密度 / 放宽 can_place_at）。

**卵生必须配套的三件事（否则死锁）**
1. 卵有寿命，不孵化就腐败成食物（能量回环境）
2. 卵可以被吃（营养丰富）→ 自然产生"偷蛋"策略，也让卵成为高风险投资
3. 卵存完整 anatomy + brain（孵化时父母可能已死）。内存估算：
   3000 个卵 × ~2.2KB brain ≈ 7MB，可接受；堆到 15000 个会到 33MB，要设上限

## 批次 7.5：光场改成「多源 BFS + 可放置点光源」

**用户反馈**："现在的设计会让世界强行分出上下" —— 垂直投射把世界锁成上亮下黑，

**改法**
- `LightSource { col, row, strength }`：**独立于物质世界**的一层，

- 天空光退化成「顶部一排光源」，`sky = 0` 就整个关掉（永夜）。
- 两者统一用**桶排序多源 BFS**：256 个桶从 255 往 1 扫，每格只在被更亮覆盖时入桶
  → `O(面积)`，与光源数几乎无关。
- 白捡好处：扩散让光绕进洞口，墙的阴影变**软**了。

**UI**
- 左侧工具栏加「光源」工具（`Tool::Light` / `LeftAction::Light`），
  点一下放、再点一下移除；带强度滑块（8–255）。
- 光源点用 egui 在 `hl_layer` 上画小圆点 + 光晕（不占格子，所以画面上没别的办法表示它）。
- 全局参数「太阳强度」→「天空光」，范围 0..=1。
- 着色模式 5 档，图例改成 match 2/3/4。

**踩的两个坑（都已写进注释和 DESIGN.md）**
1. **垂直方向不能环绕**。`wrap_edges = true` 时 BFS 会从第 0 行的上邻居（= 第 149 行）
   漏回来，世界变成「上下两头亮、中间黑」，剖面实测
   `r0=255 r75=30 r149=252`。修法：BFS 里垂直越界直接跳过，水平按 `grid.wrap`。
   高度方向代表"地下"，左右才是环绕的柱面。
2. **`sun_intensity` 不能同时当「天空光强度」和「光合乘数」**。第一次改完光合是
   `lit × rate × prod_mult × sun_intensity`，于是为了只用点光源把天空光拨到 0，
   点光源的光合也一起熄了，生态直接死光（0 个体）。正确关系只有一条链：
   `sun_intensity` → 天空光注入 → 光场 → 光合。

**性能：加 `World.light_dirty`**
多源 BFS 在 debug 下 3–4 ms，每帧跑会把 `field_update_is_cheap`（阈值 2ms）顶穿。
光场是「地形 + 光源 + 天空光」的纯函数，所以只在：挡光地形变化

|---|---|---|---|
| 天空光 1.0 | 736 | 5.41 | 40.6（上半部） |
| **天空光 0 + 9 盏灯** | **3776** | **2.05** | **74.1（世界中部）** |

第二行是核心证据：**关掉天空光生态照样活，而且活在世界中部**。

## 批次 8：食物带能量存量 + 渐进腐败

**核心改动**：食物从**二值**（一格 FOOD = 一个固定值）变成**带存量**（`Grid.food: Vec<f32>`）。
这一步同时解决三件事：吃了一半的肉还剩多少 / 尸体该携带死者多少能量 / 腐败的过程。

| 环节 | 行为 |
|---|---|
| 新食物（画笔/腐殖质） | 装满一份 = `life.food_energy_scale` |
| 嘴吃 | 拿走**这一格剩下的全部能量** × 摄取倍率 |
| 死亡 | 每格 `min(死者energy/格数, food_value)`，装不下撒周围，再装不下进热池 |
| 腐败 | 每格每 tick `max(e × rate/100, floor)`，流失进热池 |

**腐败用两条腿**：相对项（1%/tick）让**大块尸体慢慢烂**（守尸/抢食的前提）；
绝对项（0.02/tick）让**小块食物干脆消失**（只留相对项，指数尾巴会拖到 0.001 赖着不走）。

**热池** `World.heat_pool`：腐败流失 + 溢出丢弃的累计。批次 8 只记账，
批次 10 守恒审计时 `生物可用总能量 + heat_pool` 才该等于注入总量。

**实现坑**：腐败遍历 `food_cells` 时可能删格，删格是 **swap-remove**（会打乱数组），
所以用 `while` 手动控制下标，删掉时**原地重看**，不能 `i += 1`（否则跳过被换过来的元素）。

**验证**（light_check 3000 tick）：食物 244 格 · 总能量 92.1 · **平均每格 0.38** · 热池 8155.5。
平均每格 0.38 < 1.0 说明食物确实处于"有的满、有的半烂"的渐变状态。

**新增 6 条单元测试**：`new_food_carries_one_portion` / `food_decays_gradually`
（含"流失必须进热池"）/ `decay_floor_kills_tiny_food` /
`mouth_takes_whatever_is_left_in_the_cell` / `corpse_carries_the_organisms_energy` /
`broke_corpse_leaves_no_food`。

**回归测试放宽**：`metabolism_presses_body_size_down` 从 0.9 放到 0.95，
因为食物带能量后体型这个间接指标噪声变大（3000 tick 差异从 18% 缩到 10%）。
精确扣费由单元测试 `metabolism_drains_energy_every_tick` 守，宏观测试只查趋势。

**测试**：117 项全绿（app 46 / core 58 / regression 5 / render 2 / cli 6），零警告。
存档 `VERSION` → 7。字体 1236 字 / 254 KB。`dist/evosim2.exe` 7.10 MB。
