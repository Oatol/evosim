## 批次 8.1：`food_decay_floor` 0.02 → 0.005 + 接进「全局参数」

用户要求：把 `food_decay_floor` 调到 0.005，并加滑块到「全局参数」窗口。

**改动**
- `WorldCfg::default()` 的 `food_decay_floor` 0.02 → **0.005**。一块 1.0 能量的肉，
  0.02 时每 tick 掉 0.02（50 tick 没），0.005 时前 100 tick 由相对项主导、之后才落到
  绝对项 → 寿命翻倍多。守尸 / 抢食需要这个时间尺度。
- `ui.rs` 全局参数窗口在「食物量倍率」下面加「食物腐败下限」滑块：
  量程 0–0.1、步长 0.005、`fixed_decimals(3)`（出厂值 0.005 落在轨道 5% 处）。
  照老规矩「先读局部变量 → 画 → 比对 → 只在真变了才写回」。
  **只放出绝对项，没放出 `food_decay_rate`**（相对项对「尸体能躺多久」的影响更间接）。

**验证**（light_check 3000 tick / seed 1001）

|---|---|---|---|---|
| 0.02 | 244 | 92.1 | 0.38 | 8155.5 |

## 回归测试挂掉，暴露一个更重要的结论：体型有多个吸引子

改完默认值后 `metabolism_presses_body_size_down`（`taxed < free * 0.95`）挂：
体型只从 5.19 掉到 5.11（−1.5%），远达不到 5%。

**多种子复核（3000 tick、metab 0.05）**

| 种子 | 无成本 | 有成本 | 变化 |
|---|---|---|---|
| 1001 | 5.19 | 5.07 | −2.3% |
| 1002 | 3.45 | 3.09 | −10.4% |
| 1003 | 1.37 | 1.15 | −16.1% |

两个发现：
1. **方向在每个种子上都成立**，但幅度差 7 倍 → 在单个种子上写死百分比阈值等于赌它
   落在哪个吸引子里。改成「两个种子上方向都一致」，不再断言幅度。
2. **绝对体型差近 4 倍（5.19 / 3.45 / 1.37）**：这个生态有多个吸引子，有的稳定在
   「大而少」，有的稳定在「小而多」——**单细胞生产者也能活**（seed 1003 平均 1.37 格）。
   以前「最小自给单元 = 生产者+嘴+移动器 = 3 格」的结论，在光合直充体内之后不再成立：
   一个生产者细胞自己就能吃自己产的能量。

**批次 8 让代谢成本的相对作用变弱了**：尸体携带能量 + 腐败变慢 → 食物更富余 →
`metabolism_scale` 只占收入的百分之几 → 对体型的压制从 10% 掉到 2%（seed 1001）。
**这条对批次 10（守恒审计）很重要：成本必须和收益同量级，否则守恒只是记账，不影响演化。**

**测试**：117 项全绿（app 46 / core 58 / regression 5 / render 2 / cli 6），零警告。
regression 从 7s 涨到 23s（多了一个种子 × 两档成本）。

## 诊断：用户报「光合生物把有光区挤成一道墙，捕食者进不去也吃不到」

新建 `crates/core/examples/wall_check.rs`（纯诊断，5 个可选参数：ticks / seed / lamp / 世界尺寸 / 光合速率）。
量四件事：有光区占用率、致密格占比（八邻 ≥6 被占）、被困个体数、食物格数、各器官占比；
末尾按行分带打印「光强 → 占用率」。

**实测（seed 1001，默认参数）**
| tick | 个体 | 有光占用 | 致密% | 有光食物 | 杀手% | 嘴% | 移动% | 平均体型 |
|---|---|---|---|---|---|---|---|---|
| 4000 | 841 | 24.0% | — | 839 | 32.8 | 48.0 | 0.0 | 5.03 |
| 6000 | 922 | 24.4% | 7.8% | 775 | 21.3 | 42.2 | 0.3 | 4.63 |
| 12000 | 1765 | 26.7% | 5.0% | 1310 | **1.6** | 19.7 | **0.2** | **2.61** |

**结论一：没有真的"墙"。** 占用率上限 ~24–35%（光合速率拉到 1.0 也只有 35%），
致密格 3–9%，被困个体 0–9。分带看密度随光强单调下降（顶 30% → 边缘 11%），
是"光越强越挤"的连续梯度，不是一堵墙。

**结论二：真正死掉的是捕食者和移动器。** 杀手 33% → 1.6%，移动器 0.0–0.3%，
平均体型 5.0 → 2.6。食物格一直有 700–1300，所以不是"没食物"，是**吃不到 / 不值得吃**。

**因果链（三条，都在代码里）**
1. 光合直充体内 → **一个生产者细胞就自给自足** → 多一个细胞（嘴/杀手/移动器）
   只付 upkeep + 繁殖成本，不增收益 → 演化必然收敛到单细胞生产者。
2. 光合不需要移动 → 移动器无用 → 0%。**捕食者不能移动 = 只能守株待兔。**
3. 捕食的收益链断在三个地方：
   - `Behavior::Killer` 只 `harm_organism`，**攻击者一点能量都拿不到**；
   - 尸体变 FOOD，而 `is_clear` 用 `combat.food_blocks_reproduction` 挡路
     → **食物是路障**，吃完还得绕；
   - `Behavior::Mouth` 只吃 `types == FOOD`，**吃不到活体**。

**顺带发现（隐藏能量黑洞）**：`reproduce_organism` 先 `energy -= need` 再检查
`is_clear`，**繁殖失败白扣能量**。拥挤时它替玩家"限制了种群"（所以占用率停在 24%），
但惩罚的是"想繁殖但没地方"的个体，而不是"占着地方"的个体。

**建议的修法（按性价比）**
- A. 嘴咬活体：相邻敌方细胞 → `take = min(bite, victim.energy)`，从对方 energy 扣、
  给自己（乘效率 < 1 保守恒）。最小改动，直接给捕食正收益。
- B. 食物不挡路：`food_blocks_reproduction` 一个开关管了移动和繁殖两件事，拆开。
- C. 遮挡：生产者光合按「同列上方 N 行内的身体细胞数」衰减 → 给"墙"定价，墙自己塌，
  且让"高度"变成稀缺资源（不用每 tick 重算光场，只扫 ≤8 行）。
- D. 拥挤惩罚（外来邻居数）——更简单但不如 C 有物理意义，且要小心别惩罚大身体。

推荐 A+B 先做，跑 12000 tick 看杀手能不能撑住；撑住再考虑 C。

## C 方案（遮挡）的旁路实验：占用率能压到多少

`wall_check` 加了 `shade` / `shade=K` / `self` 三个标志，**不改 core**：
每 tick 之后把「被挡住的那部分光合产出」从能量里扣掉（事后扣账）。
模型：生产者正上方同列 8 行内每个身体格 → 光 ×(1−k)。
**已知偏差**：晚一 tick 生效，且这一 tick 的能量可能已够触发繁殖 → **遮挡效果被低估**。

**实测（10000 tick、200×150、seed 1001、天空光）**
| 配置 | 个体 | 有光占用 | 致密% | 有光食物 | 杀手% | 嘴% | 眼% | 体型 |
|---|---|---|---|---|---|---|---|---|
| 基线 | 1561 | 27.3% | 9.3% | 1155 | 3.3 | 24.8 | 2.6 | 3.02 |
| k=0.25 只算别人 | 1208 | 20.8% | **1.3%** | 1030 | 29.5 | 14.2 | 1.1 | 2.99 |
| k=0.25 含自身 | 1035 | 17.9% | 0.8% | 896 | 48.6 | 28.5 | 5.8 | 2.98 |
| k=0.5 只算别人 | 975 | 18.8% | 2.6% | 713 | 9.8 | 61.7 | 1.1 | 3.36 |

**多种子复核（k=0.25，只算别人）**
| 种子 | 占用 基线→遮挡 | 致密 基线→遮挡 | 嘴% 基线→遮挡 | 眼% 基线→遮挡 |
|---|---|---|---|---|
| 1001 | 27.3% → 20.8% | 9.3% → 1.3% | 24.8 → 14.2 | 2.6 → 1.1 |
| 1002 | 26.3% → 22.0% | 1.9% → 1.5% | **1.1 → 14.1** | **0.4 → 4.0** |
| 1003 | 26.6% → 22.8% | 3.2% → 1.8% | 1.8 → 1.4 | 0.7 → 1.7 |
点光源场景（4 盏灯）：29.3% → 23.5%，致密 2.7% → 1.2%。

**结论**
- 占用率只降 **15–25%**（26–27% → 19–23%），**不是银弹**。
- 但**致密格**降了 **60–86%**（9.3% → 1.3%）：真正被削掉的是"墙"，不是"人口"。
- 顺带把异养/感知的生态位打开了（1002：嘴 1.1% → 14.1%，眼 0.4% → 4.0%）——
  光被抢之后，吃别人的和看得远的第一次有正收益。这比占用率本身更值得注意。
- 代价：每 tick 每个生产者格扫 8 行（~2000 生产者 → 16k 查表，可忽略）。
- **未解决的设计问题**：点光源世界里"上方"没有物理意义。要做的话得把光场拆成
  `sky` / `lamp` 两层，只对 sky 分量做垂直遮挡，否则灯照的生物会被莫名其妙地罚。

## 批次 9.5：嘴咬活体（A 方案）

用户拍板 C → A → B。C（遮挡）完成后按判据「杀手/嘴有没有稳住」没过 → 进 A。

**做法**：`Behavior::Mouth` 除了吃食物，还从相邻活体身上**抽能量**：
`want = bite_rate × bite_mult × 装甲减免`，`taken = min(want, 对方剩的能量)`，
到账 `taken × bite_efficiency`，差额进 `energy_wasted`。
新增 `LifeCfg::bite_rate`（0.3）/ `bite_efficiency`（0.8），全局参数两个滑块；`VERSION` → 9。

**关键区分**：杀手让对方**死**，嘴让对方**穷**。后者顺带长出"放牧"
（吸生产者 = 只吸它的产出，宿主不死，长期共存）。大餐是储食个体（容量 6.0 能连吸 20 tick）。

**四条边界各一条测试**：被对方存量卡住 / 装甲按格减免 / 不咬自己 / 效率差额进热池。

**实测（10000 tick，bite 0 → 0.3）**：杀手% 2.0→**7.0** / 0.8→**11.6** / 1.7→**9.0**。
三个种子都站住了 —— 这是这一批真正要的东西。

**没解决的那一半（重要）**：`wall_check` 新加的 `异养%`（有嘴、没有生产者）三个种子全是 0.0。
活下来的杀手全是混养。原因：`metabolismScale = 0`，养生产者不花钱，而世界到处是光 ——
**免费的太阳能永远赢过要追着别人跑的捕食**。这条要等批次 10 把维持成本接上才可能翻。

**旋钮调大反而更乱**：bite 0.45 → 1002 的杀手 79.8%（单一策略世界）；
bite 0.6 → 1003 长出 44.8% 异养 / 45.1% 移动器，同一个数在 1002 上还是 79% 杀手。
**系统坐在分岔点上，不同种子指向完全不同的吸引子** —— 所以默认取保守的 0.3，
"调大 = 更好"是错的直觉。

**长跑 20000 tick（0.3）**：杀手 1.4 / 2.9 / 8.9 —— 1001、1002 上优势随时间衰减，
和"异养站不住"是同一个病根。

130 项测试全绿（app 46 / core 71 / regression 5 / render 2 / cli 6），零警告。

## 批次 9.6：食物算不算路障（B 方案）

原来一个 `foodBlocksReproduction` 同时管 `is_clear`（走路）和 `can_place_at`（出生），
而且**从没上过 UI**（死旋钮）。拆成 `food_blocks_movement` / `food_blocks_reproduction`，
默认都 `true`（行为不变），两个 checkbox 进「全局参数」。`VERSION` → 10。

**踩到的语义空洞**：食物不挡移动之后身体能盖到食物格上，而 `types` 是单层 ——
那格食物能量没地方存，旧代码静默清零 = 凭空丢能量。处理成**压碎 ≠ 吃掉**：
`set_cell_at` 里 `if owner >= 0 { heat_pool += food }`。`owner >= 0` 这个条件不能少，
嘴吃东西走 `reveal_floor`（owner = -1），再进热池就是重复计数（测试钉着）。

**实测（10000 tick，默认 vs freewalk）**：5 个种子里 **4 个杀手占比下降**
（1002 11.6→0.8、1005 23.9→8.5），只有 1003 长出异养 30% / 移动 30%——
而这个种子在 bite=0.6 时也会长，是同一个分岔点。1001 走另一条路：人口 971→1712、
体型 3.76→2.00、致密 5.2%→1.8%（小型个体能钻过食物堆扩散）。
**结论：B 不是解药，默认不改**，开关留给用户按场景开。

## 批次 10：维持成本 + 守恒审计

用户拍板「先做批次 10 的维持成本」。

### 一、成本改真实量级
`metabolismScale` 从 **0 → 1.0**，每种细胞的 `cost` ×5（嘴/生产者 0.002→0.010，
移动器 0.008→0.040，杀手/眼 0.006→0.030，装甲/储食/刺 0.004→0.020，再生 0.005→0.025）。
满照一个生产者挣 0.12，所以生产者成本 = 收入的 8%。`AttrField::Cost` 量程 0.05 → 0.08。

### 二、始祖必须生在光下（关键发现）
第一次扫描 1003 在 500 tick 内**全灭**。根因不在成本：`seed_origin_of_life` 把始祖放在
世界正中间（第 75 行），光强只有 **11/255**，挣 0.010 付不起 0.030。
改成 `rows / 4`（光强 ~123）之后稳定 1000~1150 只。
**这是修一个一直存在的错误**——以前代谢是 0，所以没后果。

### 三、维持成本压的是密度不是人口
10000 tick：metab=0 → 971/1428 人口、致密 5.2%；默认 1.0 → 1068/1063、致密 1.0%。
人口反而更稳（1063~1147，跨度比 metab=0 的 971~1428 小得多）。

### 四、没做成：维持成本没有制造出异养
- 全局倍率 0→5：异养 0.0~0.1%
- 生产者消耗 0.010→0.05：人口崩到 277/443，异养仍 0
- 0.010→0.08：**全灭**
生产者是唯一能量入口，把它弄贵只是让总产出变少。**真正瓶颈是光太均匀**，
不是价格。要专性异养得靠光照的空间稀缺（暗区/洞穴）。

### 五、守恒审计
`注入 == 生物 + 食物 + 热池 + 丢弃`。`World::energy_audit()` + `drift()`。
**一跑就抓到两个真 bug**：
1. **腐败被记两次**：`apply_food_decay` 先 `heat += decay`，剩余低于阈值时 `reveal_floor`
   又把数组里原来的 `e` 记进热池 → 修法「先把 left 写回数组再决定删格」。
2. **嘴吃一口被算两次**：同理，嘴必须**先清零 `grid.food[index]` 再 `reveal_floor`**。

基础设施：`Grid.food` **f32 → f64**（截断会让每笔搬运漏 1e-7）；存档 `VERSION → 11`
（`heat_pool`/`energy_wasted`/`energy_injected` 以前根本没存）。
实测 10000 tick 残差 1.1e-4 / 839475 = 1.3e-10。
「全局参数」窗口底部加了实时能量账读数（残差正常绿、漏账变红）。

### 教训
- **`metabolism_scale` 的"量纲"必须跟收入对齐**：以前 cost 是装饰值，乘 0 永远 0、
  乘 5 也才百分之几，所以"打开代谢"这件事从来没被真正测过。
- **测试用 `tiny_world` 一律关掉代谢**：单细胞功能测试量的是"这一口吃到多少"，
  开着代谢测到的就是"收入减开销"。
- **体型不能当"成本生效"的判据**：`upkeep_thins_the_population` 取代了
  `metabolism_presses_body_size_down`——1003 在 metab=0 时人口 1860 把世界挤满，
  只有小身体找得到落脚点（体型 1.82）；收税后人口减半，大身体才重新有地方生（3.28）。
  体型主要由**空间竞争**决定，不是成本。

142 项测试全绿（app 46 / core 78 / regression 6 / render 2 / cli 6 + doc），零警告。

## 批次 10.5：云影（光照的空间稀缺，阶段 1）

用户先问方案、再拍板「先只做阶段 1」。方案里我主张**世界尺寸不用动**：
200×150 里有 47% 的格子（第 79~150 行）是永久黑暗、完全没用，先把它用起来比放大更划算。

### 做法
`world.sky_patchiness` 0~1（默认 0 = 逐位等于旧行为）。天空光乘一张平滑噪声图，
亮的成"光岛"、暗的成"暗廊"。值噪声两个八度（44 / 17 格，权重 0.65/0.35）。

**乘在传播之后的场上**，不能只调制顶行种子——`absorb=3` 时横向扩散很强，
顶行的逐列调制会被抹平，结果是一条均匀亮带。

### 四个坑
1. **采样压在格线上**：世界第 0 行正好是噪声整数行，只有一条插值切片，顶行只剩 195~255。
   修法：采样加固定偏移，两个八度用不同偏移（否则两者相关）。
2. **小世界均值漂移**：120×60 时主八度只有几个格点，均值偏到 0.35，等于云影顺手把世界调暗 30%。
   修法：**先去掉均值偏差再拉对比度**（CONTRAST=3.0）。这样 `p` 才是纯碎片化旋钮。
3. **横向接缝**：世界左右环绕，非周期噪声留硬边。修法：格点下标对 period 取模。
4. **始祖又栽在固定坐标上**：加云影后 `rows/4` 可能压在暗斑里，1002 全灭。
   修法：`seed_origin_of_life` 先 `update_fields()` 算光场，再在上部三分之一找**实际最亮**的一格。
   **教训：只要"光在哪"不是均匀的，始祖坐标就不能是常数。**

### 结果
- 正面：同样平均亮度下，**碎片化比整体变暗养活 3~4 倍**（cloud=1 → 743/637/743，sun=0.5 → 184/195/257）。
  有测试 `fragmented_light_feeds_more_than_uniform_dimness` 钉着。
- **假设被证伪**：云影开满 20000 tick，异养仍是 0.0%；光合 0.6 把占用推到 28.6%、
  体型压到 1.2 格，异养也只有 0.4%。

### 为什么证伪（重要）
这个世界的平衡态是**"一个生产者细胞 = 一个完整个体"**：满照挣 0.12/tick、成本 0.010
（**12 倍回报**），而 `food_needed = 细胞数 = 1`，自己就够繁殖。任何光分布下最优策略
都是当单细胞生产者。人口还是**能量限制**不是空间限制（占用 16.6%，83% 空着）。
→ **异养的下一个杠杆不是光，是「一个生产者细胞不该足以成为完整个体」**
（最小体型 / 生产者必须搭配 / 繁殖门槛与体型脱钩）。

## 批次 11 前置调研：体型经济学（A 方案证伪 → Kleiber → 最小体型）

用户拍板「先只跑 A 的扫描，根据结果考虑要不要做 C」。A = 规模经济
（`breed_cost_exponent < 1`，让大体型繁殖更便宜）。

### 一、A 路线彻底证伪（两轮实验）

`body_scan` 15000 tick、多种子，p = 0.5/0.6/0.7/0.8/1.0：
**平均体型 2.99 → 3.07，纹丝不动**（单种子波动就有 ±0.3）。异养恒 0。
换 `free`（失败不扣钱）再扫一遍，还是 2.04~2.54，没有向上漂。

**为什么无效**（加了繁殖受阻计数器才看清）：
```
p=1.0: 尝试 733419 · 成功 16.8% · 没整块空地 59.0% · 路径被挡 24.2%
```
**86% 的尝试失败**，而 `reproduce_organism` 是**先扣能量再检查空间**的——
每次失败白付一次 `food_needed`。于是 p 越小 → 攒钱越快 → 撞墙越频繁 → 更亏。
**规模经济和这个惩罚打架，后者赢。**

### 二、根本原因是「规模中性」

| 量 | 公式 | 随体型 n 的标度 |
|---|---|---|
| 生产者产出 | `n × 0.12 × lit` | 线性 |
| 维持成本 | `n × 0.010` | 线性 |
| 能量容量 | `n × 2.0` | 线性 |
| 繁殖门槛 | `n^1.0` | 线性 |
| **出生难度** | 要 **n 格连通空地 + 直线路径** | **超线性（惩罚）** |

净收入 `0.11n` / 门槛 `n` = **繁殖速率 0.11/tick，与体型无关**。
唯一的非线性项在惩罚大体型 → 必然收敛到 1 格。

**决定性实验**：把繁殖位置搜索从 1 个候选提到 12 个 →
体型从 2.67 **掉到** 1.89（2 格占 76.9%）。
**任何"让繁殖更容易"的改动都在强化小体型**（小身体需要的空地少）。

### 三、用户提出 Kleiber 定律（表面积/体积比）

「大体型单位体重代谢慢、吃得少、活得久」→ 维持成本应该亚线性（`∝ n^0.75`）。

**方向对，但当前参数下幅度不够**：细胞 `cost` 只占满照收入（0.12）的 **8.3%**，
所以 n^0.75 的折扣最多让净收入涨 4%（10 格 vs 1 格）。实测：

| cost× | upkeep 指数 | 个体 | 平均体型 | 存活种 |
|---|---|---|---|---|
| 1 | 1.00 | 1576 | 2.67 | 35.3 |
| 1 | 0.75 | 1644 | 2.38 | 40.3 |
| 5 | 1.00 | 595 | 2.93 | 8.3 |
| 5 | 0.75 | 851 | 2.93 | 16.0 |

**Kleiber 让世界多养活 43% 的个体（595 → 851），但体型一点没动。**
把成本提到 42% 再叠最小体型：体型 3.15，但存活种从 34.6 崩到 12.6、杀手 0.2%。
→ 代谢效率是真机制，但**单独推不动体型**。

### 四、真正有效的杠杆：最小可繁殖体型

`min_breed_cells`（1 = 旧行为）。5 种子、8000 tick、free 模式：

| 配置 | 个体 | 平均体型 | 存活种 | 嘴% | 杀手% |
|---|---|---|---|---|---|
| 基线 | 956 | 2.87 | 31.2 | 37.9 | 1.6 |
| free（失败不扣钱） | 1784 | 2.38 | 31.4 | 19.7 | 2.6 |
| **free + mincells=3** | 1235 | **3.09** | 34.6 | 12.6 | **27.6** |
| free + mincells=3 + cost×5 + Kleiber | 691 | 3.15 | 12.6 | 33.3 | 0.2 |

`mincells=3` 是**唯一**同时把体型稳住（3.09）又让捕食生态位站住（27.6%）的配置。
`mincells=4` 直接崩（441 个体、存活种 7.7）——4 格太难找地方。

### 五、新增的四个旋钮（默认全部保持旧行为）

`LifeCfg::repro_fail_costs_energy`（true）/ `repro_search_tries`（1）/
`min_breed_cells`（1）/ `upkeep_exponent`（1.0）。
`World` 加了 6 个繁殖受阻计数器（诊断用，不进存档）。

**注意**：这 4 个旋钮**都还没上 UI、没进存档版本号**——它们目前只是实验脚手架。

### 六、待办

- 异养仍然 0（除 free + 4 种子时偶发 8.4/8.6%，不稳定）
- **温度场对生物完全没有作用**（`fields.temp` 只是着色）——用户的"表面积/体积比
  → 受环境影响小"正好能接在这里：给温度加伤害，让大个体能住极端温度区。
  这是一个还没被利用的现成机制。

## 批次 11：体型经济学 + 环境温度（用户拍板"先只做温度"）

### 一、繁殖顺序反转（用户明确要求）
「先检查空间再扣能量，这样更符合实际」→ `repro_fail_costs_energy` 默认翻成 **false**。
`reproduce_organism` 拆出 `charge_repro()`，成功才收费。
**副作用**：失败个体每 tick 重试，尝试次数涨约 20 倍、tick 耗时 1.67 倍（37.7s→62.9s / 6000 tick）。

### 二、温度生态位（主任务）
温度场（岩浆驱动）以前**对生物毫无作用**，只是着色。现在接上：
```
excess = (温度 − 舒适阈值) / (1 − 舒适阈值)
伤害   = temp_damage × excess² × 体型^temp_size_exponent
```
**指数默认 -0.25 而不是 +0.75**，语义是"体温"不是"接触面积"：
热容∝体积、散热∝表面积 → 升温速率 ∝ n^-0.25；血量=n → 生存时间 ∝ n^1.25。
先试 +0.75（优势只剩 n^0.25 = 1.78 倍）：**实测热区里一个生物都没有**，全被赶出去，没有梯度。

取个体身上**最热的一格**（一根手指伸进热区也要疼）。

**实测（6000 tick / 6 块岩浆 / 3 种子）**：热区平均体型比冷区高 5~20%
（冷 2.83 → 104-155 带 3.17）。**方向对，但幅度小**，两个原因：
1. 热区只有 1.5% 的个体（30~40 vs 2600）——纯惩罚没奖励，冷区占用才 5% 不挤；
2. 体型多样性太低（3 格占 70%+），n^1.25 的优势没素材。
→ **温度是机制不是解药**，需要「冷区拥挤」+「体型能分化」两个前提。

### 三、顺带修的真 bug：加能量不查容量（重要）
`repro_fail_costs_energy = false` 之后能量账残差 -8234（人口越高漏得越多）。
定位：关光合→0；关繁殖→0；逐个体对账→3 格个体在容量上限处。
**根因**：容量检查只在光合里做（判断 `room = cap - energy`）。别的路径
（吃食物、咬活体）直接 `energy += x` 把能量顶到 cap 以上，下一次光合算出
`room = 0` 然后 `energy = cap`——把个体**往下 clamp**，那一截既没进 wasted 也没进 heat。
旧行为下能量经常被繁殖清到 0，几乎撞不到上限，所以一直没暴露。
**修法**：统一成 `World::add_energy(i, amount)` 一个入口。残差 -8234 → 1e-6。

### 四、7 个旋钮上 UI（全部在「全局参数」）
`繁殖失败不扣能量`（checkbox）/ `繁殖搜索候选数` 1-16 / `最小可繁殖体型` 1-8 /
`维持成本指数` 0.5-1.5 / `温度伤害` 0-3 / `舒适温度阈值` 0-1 / `温度伤害指数` -0.75~1.0。
`min_breed_cells` 默认保持 **1**（用户要求不改默认值）。

### 五、A 路线（规模经济）最终结论
`breed_cost_exponent` 1.0→0.5，体型 2.99→3.07，**彻底无效**。
根因「规模中性」+ 86% 繁殖失败白付全款 + 出生要整块空地。
**繁殖搜索从 1 个候选提到 12 个，体型反而从 2.67 掉到 1.89**——
任何"让繁殖更容易"的改动都在强化小体型。

存档 `VERSION` → 13。

## 批次 11 验证：「拥挤 → 热区避难」假设被证伪

用户拍板「先跑这个验证」。给 `body_scan` 加了 `photo=R` 和「有光占用%」一列。

| photo | 个体 | 平均体型 | 有光占用 | 冷区 0–51 | 52–103 | 104–155 | 156–207 |
|---|---|---|---|---|---|---|---|
| 0.12 | 856 | 2.84 | **15.3%** | 2508 / 2.84 | 40 / 2.82 | 14 / 2.89 | 6 / **3.44** |
| 0.40 | 1610 | 2.72 | **27.4%** | 4702 / 2.72 | 86 / 2.68 | 19 / 2.67 | 12 / 2.74 |
| 0.80 | 2417 | 2.20 | **30.8%** | 7166 / 2.20 | 41 / 1.77 | 19 / 2.16 | 16 / **1.85** |

**结论：拥挤不但没让热区住上大个体，反而把优势吃掉了，甚至反转。**

- photo=0.12：热区体型 3.44 vs 冷区 2.84（+21%，唯一的正向信号）
- photo=0.40：2.74 vs 2.72（**归零**）
- photo=0.80：1.85 vs 2.20（**-16%，热区反而更小**）

### 三个原因

1. **占用率上限只有 ~31%**：即使 photo=0.8，还有 70% 的有光格是空的。
   繁殖受空间约束形成负反馈——越挤越难找空地，所以永远挤不到"需要避难"的程度。
2. **高光合 → 能量充足 → r 策略占优**：体型从 2.84 掉到 2.20。
   "拥挤"和"大体型"在这套经济学里是**反向**的。
3. **热区变成高周转区**：能量充足时小个体不断涌入、快速死掉、被替换，
   平均体型被拉低——不是"大个体守住热区"，是"小个体排队送死"。

### 教训

**「拥挤 → 避难 → 生态位」这条链不成立**，因为它假设空间会真的填满，
而这套繁殖机制（要整块连通空地 + 87% 失败率）让占用率封顶在 30% 左右。

→ 温度生态位如果要成立，得给热区**直接收益**（比如火山土更肥沃、腐殖质更密），
而不是指望"别处太挤"。这符合真实生态：热泉/火山附近营养丰富，但只有耐热物种能住。

## 批次 11.1：世界基础温度（摄氏度）+ 删光源工具

### 一、世界基础温度（用户提出）
「整个世界应该有一个基础温度才对，比如 22℃」。之前温度场本底是 0，
只有岩浆才热，语义上像"绝对零度"。

**改法**：温度场存的是「**高于环境的温差**」，不是绝对温度。
```
局部温度 = ambient_temp + (场值/255) × temp_span     // 摄氏度
excess   = (局部温度 − comfort_temp) / temp_span
伤害     = temp_damage × excess × 体型^指数
```
- `WorldCfg::ambient_temp` 默认 **22℃**
- `WorldCfg::temp_span` 默认 **100℃**（岩浆 = 22 + 100 = 122℃）
- `LifeCfg::temp_comfort`（0–1 比例）→ `comfort_temp`（摄氏度，默认 35℃）
- 悬停读数直接显示「温度 122℃」

**顺带做成「全球变暖」旋钮**：环境温度调到 40℃ 以上，连一格热源都没有的
常温区也会开始扣血。实测（无岩浆、伤害 0.5、3000 tick）：
22℃ → 787 个体 / 40℃ → 540 / 55℃ → **14**。

**踩的坑**：伤害原本是 `excess²`（平方）。40℃ 时 excess = 0.05、平方后 0.0025，
伤害 0.001/tick，**结果和 22℃ 一模一样**，看起来像 bug。改成线性后正常。
平方的初衷是"越近越致命"，但 excess 本身就随距离上升，线性已经够了。

### 二、删光源工具（用户提出）
「放了光源就无法移除了」。`toggle_light_at_cursor` 逻辑本身是对的（同格再点会删），
但**光源在画面上是一团光晕**，视觉位置和格子中心差几格是常事；
拖拽放置还会一次留下一串。精确坐标匹配 = 很难对准。

**改法**：新增 `Tool::LightErase`（「删光源」按钮）+ `World::remove_nearest_light_source(col, row, radius=4)`，
按「附近最近」删，点哪儿都能删掉眼前那个，支持拖拽连续删。

155 → 156 项测试全绿（app 46 / core 92 / regression 8 / render 2 / cli 6 + doc），零警告。
存档 `VERSION` → 14。

## 批次 11.2：修「温度视图全黑」

用户报：「世界温度调成 30℃ 了，但温度视图里看还是完全漆黑」。

**根因**：着色时直接把 `fields.temp`（**温差**）传给了渲染层。
温度场现在存的是"高于环境的温差"，30℃ 环境里没有热源 → 全场温差 0 →
色表 0.00 = `[6,10,20]` 近黑 → 整幅画面纯黑。

**修法**：新增 `World::temp_view()`，把温差换算成**绝对温度**再归一化：
```
celsius  = ambient + 场值/255 × span
display  = celsius / 120 × 255        // 固定 0–120℃
```
归一化范围**固定**，不随 `ambient + span` 移动——否则调环境温度时底色
会跟着一起漂，反而看不出变化。

效果：22℃ → 47，30℃ → 64，62℃ → 132，122℃（岩浆）→ 255（饱和）。
用户调 22→30 能看到底色变亮一点。

新增 3 条测试：`temp_view_shows_absolute_temperature_not_delta` /
`temp_view_brightens_with_ambient` / `temp_view_saturates_at_lava`。
UI 的着色按钮 hover 补了说明（温度视图是 0–120℃ 绝对温度）。

157 项测试全绿（app 46 / core 95 / regression 8 / render 2 / cli 6 + doc）。
