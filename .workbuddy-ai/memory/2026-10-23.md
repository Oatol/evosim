## 讨论（未动手）：进化太随机 + 细胞类型封闭枚举

用户提出两件事：① 进化太随机，要方向；② 细胞类型是封闭枚举，"演化发明新细胞"在类型层面不可能，
想把细胞功能下放到**细胞器**（如生产者=含叶绿体），在编辑器里编辑细胞器组成。

我的诊断（基于现有代码事实）：
- 变异算子纯均匀随机：`add_random_cell`（随机类型 / 随机邻居位 / 随机朝向）、`change_random_cell`、`remove_random_cell`。
- **基因型 = 表现型**（每格一个 BodyCell，无发育映射）→ 任何改动都是局部破坏性，无法表达"把这个器官做大"。
- 类型硬编码：`CELL_DEFS: [CellDef; 19]`、`config.cells: [CellAttrs; 19]`、`LIVING_CELL_TYPES: [u8;9]`、
  行为走 `match Behavior`，感知是 4×9 one-hot（8 类型 + 距离）。
- 旁证：47.4% 个体是芽；6000 tick 里 208 个指纹只活 18 个（190 个"出现即死"）；物种树很碎。

建议路线（按性价比）：
1. **变异算子结构化**（最便宜，零架构改动）：贴着同类长 / 改成邻居已有类型 / 加"复制一段"算子。
2. **方案 A：细胞器向量**——`BodyCell` 从 `type_id: u8` 变 `genes: [u8; N]`（叶绿体/线粒体/鞭毛/吞噬体/
   几丁质/刺丝/感光/储存/分泌），功能由基因算；现有 9 种活细胞降级为"原型预设"，UI/画笔/工坊不变；
   感知从 one-hot 换成 4~6 个连续通道；必须设"细胞器预算"否则"全都要"是唯一解。
3. **方案 B：新交互原语**（"分泌"最便宜：把能量吐到邻格 → niche construction）。
4. **方案 C：发育映射**（基因型→表现型，最小版本只做"对称 + 重复"两个算子）——真正解决"太随机"，
   但要动存档/变异/渲染/感知/工坊全部，放最后。

关键 framing：现有 9 种细胞其实已经是"细胞器的粗粒度版"（生产者=叶绿体、嘴=吞噬体、mover=鞭毛），
所以这个改动是**把隐式映射显式化并连续化**，不是新概念。且能解释批次 30 的 99.7% 混养体——
类型划分本身没有生态意义，大家全在中间。

待用户决定，未写任何代码。

## 讨论（第二轮，未动手）：五大演化机制 + 方案 C 发育映射

逐条评估可行性（关键事实：`BodyCell {type_id,dx,dy,dir}` 基因=表现型；
`growth_plan: Option<Anatomy>` 已经是一个"延迟构建"的雏形；
`mutability` 已经是可遗传的元变异；`in_radiation` 已经做了一次环境→生殖细胞的影响但不可遗传）。

结论：五个机制都能做，但**成本差一个量级**，且只有"发育"需要动架构。
- 中性漂移：靠"平台函数"（如 `min(叶绿体,3)`）免费获得准中性空间；靠 C1 的"多对一映射"免费获得真中性。
- 模块化：**不需要 C**，用"局部一致 / 重复 / 对称"三个算子就能在表现型层拿到。
- 表观遗传：`marks: [u8;2]`（stress/rich）+ 衰减遗传，最便宜；第二条"反应范数"其实已存在（`growth_stall_mature` 让同基因组长出不同身体）。
- 重组：没有 C 时只能做"按平面切一半再修桥"（脏）；有 C 时变成"交换段"，干净。
- 发育（C）：**推荐 C1（段 + 重复 + 镜像）**，不推荐 C2 语法 / C3 基因调控网络。

C1 的架构关键：**`genome: Option<Genome>` 作为可选字段，`anatomy.cells` 仍是表现型**。
→ 所有模拟代码不动；旧存档 / 工坊蓝图走 `None`（经典字面身体）；**golden 快照不受影响**。
变异从"改格"变成"改段"（一处改动 → N 格协调变化，这正是现在缺的）。
指纹哈希 genome（谱系）、物种聚类仍用展开后的 cells（形态）——批次 32 的双轨正好对上。

三个坑：展开时的重叠/越界要有确定性裁剪（先到先得）；不连通要按"发育失败/凋亡"丢弃；
体型会跳变（10→20 格），这其实是好事（量级化的体型）。

硬约束（必须说清）：C1 只解决"走不动"，不解决"没东西可走"。
复杂度需要生态位来奖励——单标量能量 + 空间约束下，最优永远是"小且简单"。
所以 C1 必须和「新原语（分泌）」「体型收益」配套，否则只是更漂亮的随机。

建议顺序：① 变异算子结构化 + 表观遗传第 1 条（零架构）→ ② C1 → ③ 段级重组 → ④ 中性漂移显式化 → ⑤ 反应范数。
判据：变异致死率、中性变异比例、体型上尾、谱系树深度（不是宽度）、模块数。

## 讨论（第三轮，未动手）：C2 语法 / L-system、C3 基因调控网络

**约束更新（用户明确）**：仍在开发阶段，**存档 / 蓝图失效可接受；golden 快照已放弃，不再维护**。
→ 影响：① `genome` 不必做成可选字段（可以必填，一次迁移，不留双路径）；
② 变异算子的 RNG 顺序自由，不再需要"默认值逐位不变"；
③ `BodyCell` 换结构、`CELL_DEFS` 扩容、感知维度改含义，全都可以做。

### C2 两种
- **C2a 真 L-system**（产生式 + turtle）：表达力最强（分形/递归），但适应度地形最崎岖
  （改一条被反复引用的规则 → 整个身体重画），且体型随深度量子化。不推荐。
- **C2b 有界语法（推荐）**：`Segment { cells, repeat, mirror, rot, children: [Segment] }`，
  深度 ≤ 2~3。= "躯干 + 附肢 + 附肢的附肢"。变异影响范围**结构上可预测**（只影响该段及子孙），
  所以比 C2a 可搜索得多，又能表达分支/层级。

### C3 GRN
每个细胞状态向量 s∈R^k，`s' = tanh(W·s + ΣV·s_nb + b)`，超阈值则分裂/分化，迭代到稳定。
**真正给的东西**：分化（位置由动力学决定，不用人指定）、渠道化（发育缓冲，是真实生物承受高突变率的根本）、
再生、对称自发涌现。
**代价**：参数空间病态（多数 W 长出一团或什么都不长）、**突变效应是混沌的**（会让"太随机"更严重）、
出生成本 ×10、可解释性归零、调试地狱。→ 这个项目里性价比最低。

### 核心洞见（要写进文档）
**表达力与可演化性方向相反**：C1 < C2b < C2a ≈ C3（表达力），而 C1 > C2b > C2a > C3（可演化性）。
真实生物同时拿到两者靠的不是更强语法，而是模块化 + 简并（中性网络）+ 渠道化 + 层次化调控。
C3 的默认状态是混沌的，要额外机制才能渠道化。

### C3-lite（我推荐的分化路线）
不用 GRN，用**位置信息 + 阈值**（Wolpert French flag）：细胞类型 = f(到身体中心距离 / 到边界距离 /
主轴位置)。基因组 = 几条阈值规则。可解释、可搜索（阈值连续平滑）、成本低（一次算完，不用迭代）。
表达力有限，但**这正是要的**：给"分化"而不给"混沌"。

### 新风险
C2 的分支会放大老问题：`can_place_at` 要求整块连通空地 → 大体型更难出生。
所以 C2 必须配"体型收益"或出芽/卵生这类绕开空地的路径。

## 第四轮：折叠出生 + 形态解释器 → 写成 DESIGN.md §17

**关键发现（读代码才看清的）**：折叠出生**已经实现了一半**——
`growth_enabled` 时普通繁殖只查 1 格（`reproduce_organism_inner` 里那段注释明说
"出生难度掉一个量级"），`grow_organism` 就是逐格往空地长的引擎。
真正的缺口只有四个：
1. **卵孵化仍要求整块空地**（`hatch_eggs` → `can_place_at`）
2. **生长顺序是"任意相邻"**（形态失控，不由基因组决定）
3. **受阻时随机填类型**（当年为不灭绝打的补丁，把形态彻底打乱）
4. **胚是位置约定** `plan.cell_at(0,0)`，不是性状 → 可能选到边缘的嘴，出生即饿死

**折叠出生的核心论证**：`can_place_at` 让体型成为**悬崖**（一次变大 = 直接绝后）；
1 格出生 + 有序展开把它变成**斜坡**（变异影响从"能不能活"变成"长多大"）。
四条刹车：脆弱期 / 发育时间 / 每格建造成本 / 空间仍限制最终体型。

**形态解释器**：`Genome → BodyPlan`，纯函数、无 RNG、无 World 依赖、可单测、可按 genome 哈希缓存。
`BodyPlan { cells（顺序=发育顺序 BFS）, seed, parent（子树凋亡）, depth }`。
复用点 9 处（出生/生长/受阻/工坊/指纹/物种/渲染/存档/诊断）——这是用户要的"写一次到处用"。

**新增两条规则**：① 生长必须相邻（保留）；② **受阻即凋亡**（替代随机填空）；
③ **蓝图空了 = 成年**（替代 `growth_stall_mature` 计时器，保留作兜底）。
