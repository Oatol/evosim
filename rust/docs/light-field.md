## 1. 目标与非目标

### 要解决的三个问题

当前模拟有一个结构性缺陷，导致「体型」「眼睛」「移动」三条演化轴全是死的：

1. **食物内生于身体** —— `food_prod_prob` 让生产者细胞凭空在自己旁边造食物，不需要找、不需要移动。
2. **能量没有空间梯度** —— 到处一样富饶，所以「去哪里」不是一个决策。
3. **身体布局无意义** —— `anatomy` 只决定「占几格」，3 格摆成 L 形还是直线毫无差别。

引入光场同时解决三条：光**从上方来、被墙遮挡、随深度衰减**，于是位置有了价值（去亮的地方），
身体朝向有了价值（生产者放朝光的一侧），移动有了价值（往亮处走）。

### 本批次做

- 光场：每格一个 `u8` 光强，垂直投射 + 墙遮挡 + 深度衰减
- 光合：生产者细胞按**自身所在格的光强**把能量直接充进 `organism.energy`
- 能量容量：身体越大装得越多，储食细胞是额外电池
- 着色模式「光照」+ 全局参数两个滑块

### 本批次**不**做（留给后续批次）

| 不做 | 原因 |
|---|---|
| 能量守恒审计 | 批次 10。先把生态跑起来，再用守恒去量 |
| 食物带能量存量 / 渐进腐败 | 批次 8。本批次食物仍是二值（旧的 `FOOD` 格仍可被手动放置） |
| 昼夜循环 | 光强 = 基础分布 × 全局系数，加时间函数是一行的事，等生态稳定后再加 |
| 软阴影（散射光） | 硬阴影足够产生行为差异，软化是视觉优化 |
| 生物挡光 | 见 §3.3，会破坏「光场是地形纯函数」这个性质 |
| 卵生 | 批次 9 |

## 2. 为什么光不塞进 `Fields`

`fields.rs` 里已有温度场和辐射场，但**光不是同一类东西**：

| | 温度 / 辐射 | 光 |
|---|---|---|
| 传播 | 各向同性扩散（5 点模板，自己权重 2） | **方向性投射**（从上方来，逐行往下传） |
| 更新频率 | 每帧（物理时间，60 Hz 墙钟） | **只在拓扑变化时**（它是地形的纯函数） |
| 衰减 | `saturating_sub(decay)` | 随深度线性衰减，遇墙归零 |
| 缓冲区 | 需要 `scratch` 双缓冲 | 单次扫描，不需要 |

塞进 `Fields::update()` 会让那个函数变成一个「三种算法轮流跑」的大杂烩，
而且光场本来可以**不每帧算**，混进去就被迫跟着每帧算。

所以新建 `core/src/light.rs`，独立结构。

## 3. 数据层

### 3.1 结构

```rust
// core/src/light.rs
#[derive(Clone, Serialize, Deserialize)]
pub struct Light {
    pub len: usize,
    /// 每格光强，0 = 全黑，255 = 满照
    pub level: Vec<u8>,
    /// 光每往下一格衰减多少（由世界高度推导，见 §3.2）
    pub absorb: u8,
}
```

用 `u8` 而不是 `f32`：和 `temp` / `rad` 一致，30k 格只占 30KB，
精度 256 级对「光合速率」足够（换算成 `0.0..=1.0`）。

### 3.2 计算：垂直投射 + 墙遮挡

```rust
impl Light {
    /// 重算整张光场。O(cols × rows)，30k 格约 30–50 µs。
    pub fn rebuild(&mut self, grid: &Grid) {
        // 每列独立：从顶行往下扫
        for c in 0..cols {
            let mut v: u8 = SUN_MAX;          // 顶行满照
            for r in 0..rows {
                let i = r * cols + c;
                if blocks_light(grid.floor[i]) {
                    v = 0;                     // 墙：这一格及以下全黑
                } else if r > 0 {
                    v = v.saturating_sub(self.absorb);
                }
                self.level[i] = v;
            }
        }
    }
}
```

- **顶行满照**（255），每往下一格减 `absorb`
- **遇到挡光地形 → 本格及下方全部归零**（硬阴影）
- 环绕（`wrap`）不影响光的水平传播（光只垂直走），所以不用处理

**`absorb` 的推导**：让「世界高度的 80% 处」恰好归零，保证底部是暗的、
但上部有足够的梯度供生物分层：

```
absorb = ceil(255 / (rows * 0.8))
```

150 行 → `absorb = 3`，第 85 行归零。200×150 的世界里，上半部分有光、下半部分全黑。

**挡光判定**：只有**实心地形**挡光。具体是 `!is_passable(ty) && ty != EMPTY` 的地形
（当前就是 `WALL`）。可通行地形（岩浆/沼泽/辐射带/腐殖质）不挡光 —— 它们在地面上，
光能照到。空和食物不挡。

```rust
fn blocks_light(ty: u8) -> bool {
    ty != ct::EMPTY && cell_type::is_terrain(ty) && !cell_type::is_passable(ty)
}
```

> 注意用 `floor`（地形层）而不是 `types`（当前层）：`types` 里还混着生物占位，
> 而生物不挡光（见 §3.3）。

### 3.3 生物为什么不挡光

如果生物挡光，`light` 就依赖每 tick 都在变的 `types`，光场必须每 tick 重算，
而且会产生「大身体用自己的上半身遮住自己的下半身」的负反馈——体型越大越吃亏，
正好和本批次想验证的东西相反。

物理上也说得通：生物是薄薄一层组织，叶子是透光的。

**副作用**：一个大身体里所有生产者细胞拿到的光只取决于它们各自的**绝对行号**。
身体顶部（行号小）的生产者拿光多，底部的拿光少。这正是我们想要的压力——
「生产者应该长在朝光的一侧」。

### 3.4 什么时候重算

v1：**每帧重算**（`World::update_fields()` 里顺手调 `light.rebuild()`）。

理由：30k 格 ~40 µs，60 Hz 下每秒 2.4 ms，占 0.24% CPU，完全可以接受；
而「找出所有会改 `floor` 的代码路径」容易漏（`fill_grid` / `paint` / `reset` / `resize` /
读档 / 工坊放置……漏一个就是光场和地形不同步的诡异 bug）。

留一个优化位：以后如果光场变贵（比如加了软阴影），再加 `light_dirty` 标记。

**但光合采样不每帧算**：光合发生在 `act_organism`（每 tick），直接读 `light.level[i]`。
光场是「地形 + 太阳强度」的函数，而地形变化远慢于 tick，所以每帧刷一次足够。

## 4. 光合：能量怎么进生物

### 4.1 现在的行为（要替换掉）

```rust
// world.rs act_organism 里，生产者细胞：
if rng.chance(cfg.life.food_prod_prob) {
    // 在相邻空格造一个 FOOD 格
}
```

凭空造食物，不消耗任何东西。这是「永动机」。

### 4.2 新行为

```rust
// 每个生产者细胞每 tick：
let lit = light.level[index] as f64 / 255.0;       // 0.0..=1.0
let gain = lit * cfg.life.photosynthesis_rate
              * cfg.cells[PRODUCER].prod_mult;     // 已有倍率参数
organism.energy += gain;
```

- **直接进体内**，不经过食物格
- 光强为 0 时产出为 0（所以暗处的生产者是纯负担 —— 这本身就是选择压）
- `prod_mult` 保留（类型参数窗口里的「生产速度」继续有效）

### 4.3 参数替换

| 旧 | 新 | 说明 |
|---|---|---|
| `LifeCfg.food_prod_prob`（默认 5，%） | `LifeCfg.photosynthesis_rate`（默认 0.12） | 每 tick 每单位光强产多少能量 |

`food_prod_prob` **直接删除**（不是保留不用）——留着会让人以为它还有效。
UI 上「生产者造食率」滑块改成「光合速率」。

> 默认值 0.12 的来由：满照（1.0）下一个生产者每 tick 产 0.12 能量，
> 约 8 tick 攒 1 点。先按这个量级起手，实施后用扫描调。

### 4.4 食物仍然存在

`FOOD` 格子保留，仍然可以被嘴吃掉、可以手动放置。它现在有两个来源：
- 玩家用画笔放（注入）
- 生物死亡时变成食物（残骸，见 §6）

也就是说本批次之后，**活着的生物不再产生食物**，食物只来自「死亡」和「玩家」。

这是「食物 = 尸体」的第一步（完整的能量存量改造在批次 8）。

## 5. 能量容量

光合直充体内，如果没有上限就是无限膨胀。所以需要容量。

### 5.1 公式

```
capacity = n_cells × energy_per_cell + n_storage × storage_capacity
```

| 字段 | 默认 | 含义 |
|---|---|---|
| `LifeCfg.energy_per_cell` | `2.0` | 每格身体的基础容量 |
| `LifeCfg.storage_capacity` | `6.0` | 每个储食细胞的额外容量 |

- 3 格无储食：容量 6，繁殖阈值 3 → 攒到 6 繁殖花 3 剩 3
- 3 格含 1 储食：容量 12 → 能攒更多，但被吃掉时损失也更大

**储食细胞从「抬高繁殖阈值」变成「电池」**。它现在同时有收益（装更多能量、
能熬过黑夜/饥荒）和代价（攒得越多，被杀死时对方赚得越多）。

`storage_food_bonus`（抬高繁殖阈值）**保留不动** —— 两个功能不冲突，
储食细胞同时做「电池」和「产房」。

### 5.2 超出容量怎么办

丢弃，并计入 `World.energy_wasted` 统计（f64 累加，为批次 10 的守恒审计准备）。

不要「攒着溢出到别处」—— 那会让大身体旁边凭空出现能量，破坏守恒叙事。

### 5.3 死亡时的能量

本批次**不变**：`kill_organism` 仍然按细胞数把身体变成食物格 + `food_value_total` 的额外食物。
体内攒的 `energy` 仍然丢弃。

批次 8 才改成「尸体能量 = 死者体内能量」。本批次先记一个 TODO 注释。

`sun_intensity` 放在 `WorldCfg`（默认 1.0），作用方式：

```
实际光强 = level[i] × sun_intensity   （采样时乘，不重算光场）
```

这样玩家拨滑块是**零成本**的，而且拨到 0 就是「永夜」，可以直接做对照实验。

## 10. 7.5 改版：可放置的点光源

### 为什么改

7.0 的「每列从顶行往下扫」有个致命的设计后果：**世界被强行分成上下**。
上半亮、下半黑，生物只能活在上半部，玩家想让光出现在地底或某个洞里完全做不到。
那不是「光」，那是「地表」。

### 改成了什么

* **点光源**（`LightSource { col, row, strength }`）—— 独立的一层数据，
  **不占物质世界的格子**，生物可以穿过，画笔和橡皮擦都碰不到它。
* **天空光**退化成「顶部一排光源」，可以整个关掉（`sky = 0`）。
  关掉之后世界全黑，只剩玩家放的那些灯。
* 两者统一用**桶排序多源 BFS** 计算，遇墙不传播。

### 算法

```text
for v in (1..=255).rev():
    for i in buckets[v]:            // 这一格的最亮到达值就是 v
        if level[i] != v: continue  // 已被更亮的覆盖，跳过
        for 四邻 n:
            if 墙(n): continue
            nv = v - absorb
            if nv > level[n]: level[n] = nv; buckets[nv].push(n)
```

每个格子只在「被更亮的覆盖」时入桶，所以每个格子最多处理一次：`O(面积)`，
与光源数量几乎无关。30k 格约 100–200 µs。

顺带白捡一个好处：扩散会让光**绕进洞口**，墙的阴影边缘是软的（不再是硬切）。

### 踩到的两个坑

**1. 垂直方向不能环绕。** `wrap_edges = true` 时如果垂直也环绕，天空光会从
第 0 行的"上邻居"= 第 149 行漏回来，世界变成「上下两头亮、中间黑」。
实测剖面：`r0=255 r25=180 r50=105 r75=30 r100=105 r125=180 r149=252`。

修法：BFS 里垂直越界直接跳过，水平按 `grid.wrap` 走。
高度方向代表"地下"，上下本来就不该相连；左右才是环绕的柱面世界。

**2. `sun_intensity` 不能同时当「天空光强度」和「光合乘数」。**
第一次改完时光合是 `lit × rate × prod_mult × sun_intensity`，于是把天空光拨到 0
（为了只用点光源）会把点光源的光合也一起熄掉，生态直接死光。
正确的关系只有一条链：`sun_intensity` → 天空光注入强度 → 光场 → 光合。

### 性能：加了 dirty 标记

多源 BFS 在 debug 下要 3–4 ms，每帧跑一次会把 `field_update_is_cheap` 顶穿。
但光场是「地形 + 光源 + 天空光」的纯函数，这三样都变得远比 60 Hz 慢，
所以加了 `World.light_dirty`：

* 挡光地形变了（`set_cell_at` 里比较 `blocks_light(old) != blocks_light(new)`）
* 批量填充、改尺寸、光源增删

天空光不靠这个标记——`update_fields` 里直接比对 `light.sky`（它由滑块驱动，随时可能变）。

### 验证

`light_check` 加了两个参数：天空光强度、`lamp`（在每只初始个体身上点一盏灯）。

| 场景 | 结果 |
|---|---|
| 天空光 1.0（默认） | 736 个体 / 平均体型 5.41 / 平均行 40.6（上半部） |
| **天空光 0 + 9 盏灯** | **3776 个体 / 平均体型 2.05 / 平均行 74.1（世界中部）** |

第二行是本次改版的核心证据：**关掉天空光之后，生态照样活，而且活在世界中部**。
光从哪来完全由玩家决定，世界不再被强行分上下。

（体型从 5.41 掉到 2.05 是因为 9 盏灯重叠覆盖全图，光太富余——
富余资源下"小而多"是正确结果，不是 bug。）

## 11. 批次 9：遮挡（给"墙"定价）

### 问题

光合直充体内之后，一个生产者细胞就自给自足，繁殖只要附近有空地。有光区会被逐渐填满。
实测（`examples/wall_check`，10000 tick、200×150、seed 1001）：

| tick | 个体 | 有光占用 | 致密% | 杀手% | 移动% | 平均体型 |
|---|---|---|---|---|---|---|
| 4000 | 841 | 24.0% | — | 32.8 | 0.0 | 5.03 |
| 12000 | 1765 | 26.7% | 5.0 | **1.6** | **0.2** | **2.61** |

占用率上限 24–35%（光合速率拉到顶格也只有 35%），所以**没有真正的"墙"**；
真正在灭绝的是捕食者和移动器。要治的是"挤在一起没有任何代价"。

### 做法

生产者细胞正上方同列 `SHADE_DEPTH = 8` 行内，每有一个身体格，**天空光**乘 `(1-k)`，
`k = 0.25`（`LifeCfg::shade_strength`，全局参数里有滑块）。

**光场拆成两层**：`sky_level`（会被遮挡）/ `lamp_level`（不会）。
`level = sky_level + lamp_level`（饱和相加），其余代码照旧读 `level`。
两次 BFS 仍是 `O(面积)`，且靠 `World.light_dirty` 只在改地形/放灯时重算。

### 两个踩过的坑

**1. 只数"别人"是个漏洞。** 第一版为了不惩罚大体型，只数别的个体的身体格。
结果一个身体可以在同一列叠好几个生产者，底下那些"被自己压着"却照样满额产光——
演化直接去叠高：平均体型 3.0 → 4.3，致密格一点没降。
光不知道格子归谁，**数全部**才对，而且它顺带给了布局一个价格。

**2. 垂直方向不能环绕。** `grid.index` 在 `wrap = true` 时会把 `row - d` 折到世界底部，
于是最上面几行的生产者会被底部的生物"挡住"。修法和光场 BFS 里那条一样：
`row - d < 0` 直接 `break`。有测试 `shading_does_not_wrap_vertically` 钉着。

### 实测（10000 tick，`shade=0` vs 0.25）

| 种子 | 有光占用 | 致密% | 个体 | 嘴% |
|---|---|---|---|---|
| 1001 | 27.3% → 22.2% | 9.3% → 1.9% | 1561 → 1284 | 24.8 → 18.5 |
| 1002 | 26.3% → 22.3% | 1.9% → 1.2% | 2109 → 1304 | 1.1 → 26.5 |
| 1003 | 26.6% → 21.2% | 3.2% → 1.7% | 2170 → 1755 | 1.8 → 3.2 |

占用率 −15~20%（不是银弹），**致密格 −40~80%**（削掉的是"挤成一团"），
嘴的占比在 2/3 的种子上明显上升。

### 连带影响

遮挡给了大体型一个**收益**（长得高才抢得到光），于是"维持成本 ↑ → 体型 ↓"不再成立：
metab 0.05 时 1001 的体型 4.21 → 5.03（反而更大）。回归测试改成关掉遮挡再验扣费。

## 12. 批次 9.5：嘴咬活体（给捕食一个正收益）

### 问题

遮挡把"挤成一团"削掉了，但杀手还是掉到 1~2%。病根不是打不过，是**打赢了也吃不到**：
尸体按格撒在死者身上，凶手只贴着其中一格，剩下的够不着。

### 做法

`Behavior::Mouth` 除了吃食物，还咬相邻活体：

```text
want  = bite_rate × bite_mult × 装甲减免
taken = min(want, 对方剩的能量)
到账   = taken × bite_efficiency
损耗   = taken × (1 - bite_efficiency)  → energy_wasted
```

**这是抽能量，不是掉血。** 所以它和杀手是两条路：杀手让对方死，嘴让对方穷。
后者顺带长出"放牧"：吸一个生产者等于只吸它的产出，宿主不死，长期共存。

四条边界各有一条测试：被对方存量卡住 / 装甲按格减免 / 不咬自己 / 效率差额进热池。

### 实测（10000 tick，bite 0 → 0.3）

| 种子 | 杀手% | 嘴% | 个体 |
|---|---|---|---|
| 1001 | 2.0 → **7.0** | 18.5 → **63.7** | 1284 → 971 |
| 1002 | 0.8 → **11.6** | 26.5 → 2.7 | 1304 → 1353 |
| 1003 | 1.7 → **9.0** | 3.2 → **7.2** | 1755 → 1428 |

杀手在三个种子上都站住了。

### 没解决的那一半

`wall_check` 新增的 `异养%`（有嘴、**没有**生产者）在 `bite=0.3` 下三个种子全是 0.0：
活下来的杀手全是混养，没有纯异养。原因：`metabolismScale = 0`，养一个生产者不花钱，
而世界到处是光——**免费的太阳能永远赢过要追着别人跑的捕食**。
这一条要等批次 10 把维持成本接上才可能翻过来。

### 旋钮调大反而更乱

| bite | 1001 | 1002 | 1003（异养/移动） |
|---|---|---|---|
| 0.3 | 7.0% | 11.6% | 0.0 / 0.2 |
| 0.45 | 7.7% | **79.8%** | 0.2 / 15.7 |
| 0.6 | 16.0% | **79.0%** | **44.8 / 45.1** |

1003 在 0.6 上真长出了异养猎手种群，同一个数在 1002 上把世界推成 80% 杀手。
系统正坐在分岔点上，**不同种子的随机历史指向完全不同的吸引子**，
所以默认取保守的 0.3（保证杀手活下来，又不至于让某个种子塌成单一策略）。

## 13. 批次 9.6：食物算不算路障

原来的 `foodBlocksReproduction` 一个开关同时管 `is_clear`（走路）和 `can_place_at`（出生）。
拆成 `food_blocks_movement` / `food_blocks_reproduction` 两个，默认都开（行为不变）。

**语义空洞**：食物不挡移动之后，身体能盖到食物格上，而 `types` 是单层——
那格食物的能量没地方存。处理成**压碎 ≠ 吃掉**：`owner >= 0` 时把能量记进 `heat_pool`。
`owner >= 0` 这个条件不能少：嘴吃东西走 `reveal_floor`（owner = -1），
能量已经记到个体身上，再进热池就是重复计数（有测试钉着）。

**实测（10000 tick，默认 vs `freewalk`）**

| 种子 | 个体 | 致密% | 杀手% | 异养% / 移动% |
|---|---|---|---|---|
| 1001 | 971 → 1712 | 5.2 → 1.8 | 7.0 → 4.4 | 0.2 / 0.2 |
| 1002 | 1353 → 1459 | 1.4 → 1.5 | 11.6 → 0.8 | 0.0 / 0.1 |
| 1003 | 1428 → 1451 | 0.5 → 2.3 | 9.0 → 3.5 | **30.0 / 30.0** |
| 1004 | 1690 → 1645 | 1.1 → 0.7 | 0.5 → 1.0 | 0.0 / 0.1 |
| 1005 | 1081 → 1051 | 0.9 → 5.2 | 23.9 → 8.5 | 0.1 / 0.3 |

**不是解药，默认不改**：5 个种子里 4 个杀手占比下降（踩碎的比吃到的多），
只有 1003 长出异养猎手群——而这个种子在 `bite=0.6` 时也会长（同一个分岔点）。
1001 走的是另一条路：人口翻倍、体型 3.76 → 2.00，更像"能钻过食物堆"让小型个体扩散。

## 14. 批次 10：维持成本 + 守恒审计

### 一、成本改真实量级

`metabolismScale` 一直是 0（代谢关闭），细胞的 `cost` 是装饰值。
这次把 `cost` ×5 成真实量级，`metabolismScale` 默认改 1.0：

| 细胞 | 旧 | 新 | 占满照收入 0.12 的比例 |
|---|---|---|---|
| 嘴 / 生产者 | 0.002 | 0.010 | 8% |
| 移动器 | 0.008 | 0.040 | 33% |
| 杀手 / 眼睛 | 0.006 | 0.030 | 25% |
| 装甲 / 储食 / 刺 | 0.004 | 0.020 | 17% |
| 再生 | 0.005 | 0.025 | 21% |

### 二、始祖必须生在光下（不然世界直接死）

第一次扫描 1003 在 500 tick 内全灭。根因不在成本：`seed_origin_of_life` 把始祖
放在世界正中间（第 75 行），而光强是 `234 − 3×row`，那里只有 **11/255**。
两个生产者挣 0.010/tick，付不起 0.030 的开销。

改成 `rows / 4`（四分之一深度，光强 ~123）之后，同一配置稳定在 1000~1150 只。
**这是修一个一直存在的错误**——"生命起源"本来就该落在太阳能养活自己的地方，
只是以前代谢是 0，这个错误没有后果。

### 三、维持成本压的是密度，不是人口

10000 tick、200×150、默认遮挡与咬合：

| 代谢倍率 | 1001 人口 | 1003 人口 | 1001 致密% |
|---|---|---|---|
| 0（旧基线） | 971 | 1428 | 5.2 |
| 1.0（新默认） | 1068 | 1063 | 1.0 |
| 2.0 | ~600 | — | — |
| 4.0 | ~480 | 0 | — |

人口反而更稳（各种子 1063~1147，比 `metab=0` 时 971~1428 的跨度小得多），
被压掉的是"挤成一团"。

### 四、没做成：维持成本没有制造出异养

| 手段 | 结果 |
|---|---|
| 全局代谢倍率 0→5 | 异养 0.0~0.1% |
| 生产者消耗 0.010→0.05 | 人口崩到 277/443，异养仍 0 |
| 生产者消耗 0.010→0.08 | **全灭** |

生产者是唯一的能量入口。把它弄贵只是让总产出变少，异养者能吃的也一起变少。
**真正的瓶颈是光太均匀**，不是价格。要逼出专性异养得靠光照的空间稀缺（暗区 / 洞穴）。

### 五、守恒审计

```text
注入 == 生物体内 + 地上食物 + 热池 + 丢弃
```

`World::energy_audit()` 给出五项，`drift()` 是残差。记账点：

| 路径 | 记到哪 |
|---|---|
| 光合产出 | `energy_injected`（全额；装不下的另记 `energy_wasted`） |
| 腐殖质 / 手工放置 | `energy_injected`（统一在 `set_cell_at`） |
| 维持成本 / 沼泽 / 繁殖成本 | `heat_pool`（记实际付出，不是名义开销） |
| 腐败 / 压碎 / 塞不下的溢出 | `heat_pool` |
| 超容量丢弃 / 消化损耗 / 摄取倍率 < 1 | `energy_wasted` |
| 摄取倍率 > 1 | `energy_injected`（确实凭空放大，得认） |

**对账一跑就抓到两个真 bug**：

1. **腐败被记两次**。`apply_food_decay` 先 `heat_pool += decay`，剩余量低于阈值时调
   `reveal_floor`，而后者会把"消失的食物能量"记进热池——此时数组里还是原来的 `e`，
   于是 `decay + e` 全进了热池。修法：先把 `left` 写回数组再决定删不删格。
2. **嘴吃一口被算两次**。同理，嘴必须**先清零 `grid.food[index]` 再 `reveal_floor`**。

两处基础设施：

- `Grid.food` 从 `Vec<f32>` 改成 **`Vec<f64>`**：f32 截断让每笔搬运漏 1e-7，
  几千 tick 后残差肉眼可见。
- 存档 `VERSION → 11`：三个能量池以前**根本没存**，读档后账目从 0 重新开始。

实测（10000 tick）：`注入 839475.5 = 生物 1281.8 + 食物 266.7 + 热池 697252.7 + 丢弃 140674.4`，
残差 `1.1e-4`（相对 1.3e-10）。「全局参数」窗口底部有实时读数，正常是绿的。

## 15. 批次 10.5：云影（把光打碎）

### 做法

天空光乘一张平滑噪声图，`world.sky_patchiness` 0~1（默认 0 = 逐位等于旧行为）。

**乘在传播之后的场上**，不能只调制顶行种子：`absorb = 3` 时横向扩散很强
（相邻列只差 3），顶行的逐列调制会被抹平，结果是一条均匀亮带。
只乘天空光——云挡得住太阳，挡不住玩家放的灯。

值噪声两个八度：44 格定"岛在哪"、17 格定"边缘多碎"，权重 0.65/0.35。

### 三个坑（都是实测）

| 坑 | 现象 | 修法 |
|---|---|---|
| 采样压在格线上 | 第 0 行正好是噪声整数行，只有一条插值切片，顶行只剩 195~255 | 采样加固定偏移，两个八度用不同偏移 |
| 小世界均值漂移 | 120×60 时主八度只有几个格点，均值偏到 **0.35** | 先去均值偏差再拉对比度（CONTRAST = 3.0） |
| 横向接缝 | 世界左右环绕，非周期噪声留硬边 | 格点下标对 `period` 取模，格宽校正成 `cols/period` |

归一化让 `p` 变成**纯碎片化旋钮**：p=1 ≈ 平均一半的光，但一半更亮一半更暗。
想单独测"变暗"就把「天空光」往下拨。

### 始祖必须去找光

批次 10 已经把始祖从正中挪到 `rows/4`；加云影后那个固定点可能压在暗斑里，
1002 直接全灭。现在 `seed_origin_of_life` 先 `update_fields()` 算出光场，
再在"上部三分之一"里找**实际最亮**的一格。

### 实测（10000 tick）

| 种子 | cloud=0 | cloud=1 | 异养% |
|---|---|---|---|
| 1001 | 1052 | 743 | 0.0 → 0.0 |
| 1002 | 994 | 637 | 0.0 → 0.0 |
| 1003 | 986 | 743 | 0.0 → 0.0 |

**正面结论**：同样平均亮度下，碎片化比整体变暗养活 3~4 倍。

| 配置 | 1001 | 1002 | 1003 |
|---|---|---|---|
| `cloud=1` | 743 | 637 | 743 |
| `sun=0.5` | 184 | 195 | 257 |

### 假设被证伪

云影开满、20000 tick，异养仍是 0.0%。把光推到能填满光区
（光合 0.6 → 占用 28.6%、平均体型压到 1.2 格），异养也只有 0.4%。

满照挣 0.12/tick、成本 0.010（**12 倍回报**），而 `food_needed = 细胞数 = 1`，
自己就够繁殖。任何光分布下最优策略都是当单细胞生产者。
人口还是**能量限制**不是空间限制（占用 16.6%，83% 空着）。

**下一个杠杆不是光，是「一个生产者细胞不该足以成为完整个体」。**

## 16. 批次 11：体型经济学（A 证伪 → Kleiber → 环境温度）

### 一、A 路线（规模经济）彻底证伪

用户拍板「先只跑 A 的扫描」。A = `breed_cost_exponent < 1`，让大体型繁殖更便宜。

`body_scan` 15000 tick、多种子，p = 0.5 / 0.6 / 0.7 / 0.8 / 1.0：
**平均体型 2.99 → 3.07，纹丝不动**（单种子波动就有 ±0.3）。

加了繁殖受阻计数器才看清原因：

```text
p=1.0: 尝试 733,419 · 成功 16.8% · 没整块空地 59.0% · 路径被挡 24.2%
```

**86% 的尝试失败**，而 `reproduce_organism` 是**先扣能量再检查空间**的——
每次失败白付一次 `food_needed`。于是 p 越小 → 攒钱越快 → 撞墙越频繁 → 更亏。
**规模经济和这个惩罚打架，后者赢。**

### 二、根因是「规模中性」

| 量 | 公式 | 随体型 n 的标度 |
|---|---|---|
| 生产者产出 | `n × 0.12 × lit` | 线性 |
| 维持成本 | `n × 0.010` | 线性 |
| 能量容量 | `n × 2.0` | 线性 |
| 繁殖门槛 | `n^1.0` | 线性 |
| **出生难度** | 要 **n 格连通空地 + 直线路径** | **超线性（惩罚）** |

净收入 `0.11n` / 门槛 `n` = **繁殖速率 0.11/tick，与体型无关**。
唯一的非线性项在惩罚大体型 → 必然收敛到 1 格。

**决定性实验**：繁殖搜索从 1 个候选提到 12 个 →
体型从 2.67 **掉到** 1.89（2 格占 76.9%）。
**任何"让繁殖更容易"的改动都在强化小体型**——小身体需要的空地少。

### 三、繁殖顺序反转（默认）

用户要求「先检查空间再扣能量，这样更符合实际」。已翻成默认：

```text
旧：扣 energy → 查上限 → 查空地 → 查路径 → 建 child
新：查上限 → 查空地 → 查路径 → 建 child → 扣 energy
```

`repro_fail_costs_energy = true` 保留旧行为可切回。

**副作用**：失败的个体每 tick 都会重试，尝试次数涨约 20 倍、tick 耗时约 1.67 倍。
要压回去得加「失败冷却」，那是新旋钮，暂未做。

### 四、Kleiber 定律（用户提出）

「大体型单位体重代谢慢、吃得少、活得久」→ `upkeep_exponent < 1`。

**方向对，但当前参数下幅度不够**：细胞 `cost` 只占满照收入（0.12）的 **8.3%**，
n^0.75 的折扣最多让净收入涨 4%。

| cost× | 维持指数 | 个体 | 平均体型 | 存活种 |
|---|---|---|---|---|
| 1 | 1.00 | 1576 | 2.67 | 35.3 |
| 1 | 0.75 | 1644 | 2.38 | 40.3 |
| 5 | 1.00 | 595 | 2.93 | 8.3 |
| 5 | 0.75 | **851** | 2.93 | 16.0 |

**Kleiber 让世界多养活 43% 的个体（595 → 851），但体型一格没动。**
把成本提到 42% 再叠最小体型：体型 3.15，但存活种从 34.6 崩到 12.6。

### 五、环境温度：把温度场接进模拟

温度场一直存在（岩浆驱动），但**对生物毫无作用**，只是着色。现在接上：

```text
excess = (温度 − 舒适阈值) / (1 − 舒适阈值)      // 0..1
伤害   = temp_damage × excess² × 体型^temp_size_exponent
```

**指数取 `-0.25` 而不是 `+0.75`**，因为语义是"体温"而不是"接触面积"：

```text
热容 ∝ 体积 ∝ n
散热/吸热 ∝ 表面积 ∝ n^0.75
升温速率 ∝ 表面积/体积 ∝ n^-0.25      ← 小个体升得快
```

血量 = 每格 1 HP = `n`，所以生存时间 `∝ n / n^-0.25 = n^1.25`：
**10 格个体在热区能撑 17.8 倍于 1 格个体。**

先试过 `+0.75`（"伤害 ∝ 接触面积"）：生存时间只差 `n^0.25`，10 格 1.78 倍。
**实测热区里一个生物都没有**——全被赶出去了，没有梯度，生态位不成立。

取个体身上**最热的一格**：身体只要有一角伸进热区就得承受。

### 六、实测：热区确实在筛体型，但幅度小

6000 tick、6 块岩浆、3 种子：

| 热伤害 | 冷区（0–51） | 52–103 | 104–155 | 156–207 |
|---|---|---|---|---|
| 0.10 | 2603 / 2.83 | 33 / 2.96 | 12 / **3.17** | 6 / 2.78 |
| 0.15 | 2508 / 2.84 | 40 / 2.82 | 14 / 2.89 | 6 / **3.44** |
| 0.25 | 2647 / 2.90 | 31 / 2.95 | 7 / **3.11** | 2 / 2.00 |

**方向对**：热区平均体型比冷区高 5~20%，说明小个体确实被筛掉了。

**但幅度小**，两个原因：

1. **热区只有 1.5% 的个体**（30~40 只 vs 2600）——热区纯惩罚、没奖励，
   而冷区占用才 5%，根本不拥挤，没有"进热区避难"的压力。
2. **世界里体型多样性太低**（3 格占 70%+），`n^1.25` 的优势没有素材可用。

→ **温度生态位不是独立的解药**：它需要"冷区拥挤"和"体型能分化"两个前提。
它解决的是"环境筛选体型"这个机制本身，机制是通的。

### 七、顺带修的一个真 bug：加能量不查容量

对账时发现「繁殖失败不扣钱」之后能量账残差 -8234（人口越高漏得越多）。

定位过程：关光合 → 0；关繁殖 → 0；逐个体对账 → 抓到 3 格个体在容量上限处。

**根因**：容量检查只在光合里做，而它判断的是 `room = cap - energy`。
一旦别的路径（吃食物、咬活体）把 energy 顶到 cap 以上，下一次光合就会算出
`room = 0` 然后 `energy = cap` —— 把个体**往下 clamp**，那一截既没进 `wasted`
也没进 `heat`，凭空蒸发。

**旧行为下几乎撞不到容量上限**（能量经常被繁殖清到 0），所以这个 bug
一直没暴露。统一成一个入口 `World::add_energy` 之后残差降到 1e-6（相对 1.7e5）。

## 17. 批次 12：成长过程（芽 → 成体）

### 一、做法

繁殖不再是「复制整个身体」，而是产一个 **1 格的芽** + 一份**目标蓝图**：

```text
芽 = 1 格 + growth_plan（母体的 anatomy）
每 tick：从 plan 里挑一个「未长、与身体相邻、目标格可放」的细胞长出来
        （花 growth_cost 能量）
长满 → growth_plan 清空 → 成年，才能繁殖
```

**变异作用在目标蓝图上**（临时把 plan 塞进 `anatomy` 让 `mutate_organism` 改，
改完再拆出来、重新取 1 格当种子）。否则体型永远变不了，演化直接停摆。

### 二、三个必须的补丁（都是实测踩出来的）

**1. 芽的血量要按目标蓝图算，不是按当前格数。**
1 格 = 1 HP 的话芽就是纸片：实测杀手占比从 14% 飙到 **50%+**，
人口 1359 → **117**，1002/1003 两个种子**直接灭绝**。

**2. 亲代投资**（`growth_seed_fraction`，默认 0.5）。
芽出生时能量 0，什么都干不了。母体付的繁殖成本分一半给芽当启动能量。
这也顺手给了「投多少给后代」一个真实旋钮——r/K 的核心。

**3. 生长兜底：目标格全被占时，长到任意相邻空位。**
芽生在母体旁边那片拥挤区域，蓝图指定的格子大概率被邻居占着。
严格按蓝图长 = 永远卡在 1 格 = 永远不能繁殖 = **灭绝**（1002/1003 实测）。
兜底之后三个种子全活。

### 三、实测（10000 tick、3 种子、p=1.0）

| 配置 | 个体 | 平均体型 | 最大 | 存活种 | 有光占用 | 异养% | 嘴% | 杀手% |
|---|---|---|---|---|---|---|---|---|
| 基线（无成长） | 1783 | 2.25 | 5 | 33.7 | 25.6% | **0.0** | 1.1 | 2.2 |
| **成长** | 1666 | **3.32** | 7 | **93.7** | 35.8% | **9.9** | 26.1 | 0.3 |

**三件事同时发生：**

1. **体型 +48%**（2.25 → 3.32）。这是批次 9~11 折腾了这么久第一次真正推上去。
2. **存活种近 3 倍**（33.7 → 93.7）——体型变成连续变量之后，生态位分化了。
3. **异养第一次稳定非零**（0.0% → **9.9%**）。之前所有尝试（遮挡、咬活体、Kleiber、
   云影、温度）都卡在 0%。

### 四、为什么它有效，而之前所有方案都无效

之前的方案都在改**成年个体的经济学**（成本、收益、繁殖门槛），
而体型在这个模型里是**出生即定**的常数——改经济参数只会移动一个点，不会产生分布。

成长把体型变成了**过程中的量**：
- 变异作用在目标蓝图上 → 体型可以逐代漂移
- 芽阶段有独立的选择压力（幼体存活率）→ 大个体的后代起点更高、更容易活
- 体型不再是"一个数"，而是一条可以演化的轴

**一句话：不是给了大体型收益，而是让「体型」第一次成为可遗传、可选择的东西。**

### 五、还没做的

- **环境可塑**：现在芽一定长到母体体型。如果让它在食物稀缺时提前成熟，
  就是真正的 r/K 分化（同一基因型、不同环境、不同体型）。
- **出芽**：芽长在母体上、共享母体产出，能给大体型一个超线性的收益
  （同时养多个后代）。这是目前唯一还没试过的"大体型正收益"机制。

## 18. 批次 12.1：环境可塑（提前成熟）

### 一、做法

芽如果**长不动**够久，就放弃长满、以当前体型成年：

```text
每 tick：
  长了一格        → grow_stall = 0
  没长（能量不够  → grow_stall += 1
       或目标格被占）
  grow_stall >= growth_stall_mature → 提前成熟（growth_plan = None）
```

「长不动」把**食物稀缺**和**拥挤**算作同一件事——生态上它们是一回事：
**这个环境撑不起这么大的身体。**

**关键**：后代的目标体型继承的是**成熟时的实际体型**。所以提前成熟会把体型
「固化」下来：小体型母体 → 小体型后代。这是真正的表型可塑性。

### 二、实测（10000 tick、3 种子）

| 提前成熟阈值 | 个体 | 平均体型 | 存活种 | 占用 | 异养% |
|---|---|---|---|---|---|
| 0（关闭，必须长满） | 1710 | **3.01** | 96.3 | 33.5% | 9.3 |
| 30 | 2638 | **1.69** | **112.3** | 29.1% | 10.7 |
| 60 | 2245 | 2.13 | 104.3 | 31.1% | 10.6 |

**同一个机制，参数一拨，就是 r/K 的两端：**

- **阈值 0 = K 策略**：大体型（3.01）、少人口（1710）、少物种（96）
- **阈值 30 = r 策略**：小体型（1.69）、多人口（2638）、多物种（112）

人口 +54%、存活种 +17%、异养还稳在 10.7%——这是一个**健康的 r 策略世界**，
不是崩溃。

### 三、体型分布：整体压小，不是分化

| 阈值 | 1格 | 2格 | 3格 | 4格 | 5格 |
|---|---|---|---|---|---|
| 0 | 4.2 | 28.9 | 34.4 | 27.0 | 5.4 |
| 30 | **40.0** | **51.7** | 7.4 | 0.9 | 0 |

阈值 0 时是**宽分布**（2~4 格都有），阈值 30 时**集中在 1~2 格**。

**所以它产生的是「整体 r 化」，不是「同一世界里 r 与 K 并存」。**

原因：这个世界在空间上是均匀的（光合区就是光合区），
所以环境压力是全局的——要么整体都长满，要么整体都提前成熟。

### 四、试过但没用的：云影

想用云影造空间异质性，让"光岛"里长成大体型、"暗廊"里提前成熟：

| 配置 | 个体 | 体型 | 存活种 | 异养% |
|---|---|---|---|---|
| stall=30、无云影 | 2638 | 1.69 | 112.3 | 10.7 |
| stall=30、云影 1.0 | 1875 | 1.67 | 87.3 | 4.9 |

**云影只是让整体更穷**（平均光照减半），所有地方都更容易卡住，
于是分化没出现、整体还变小了。

→ **要看到「同一世界里 r 与 K 并存」，需要的是「富斑块 + 贫斑块」的对比，
不是「整体变暗」。** 这是下一批的事。

## 19. 批次 13：富斑块 / 贫斑块

### 一、为什么需要第二个光场旋钮

批次 12.1 试过用云影造空间异质性，结论是「云影只是让整体更穷，分化没出现」。
根因很简单：**云影的暗廊是全黑的**（`patchiness = 1` 时透射率降到 0），
生物干脆不住，于是"活着的地方"仍然一样亮，环境压力还是全局均匀的。

所以要的不是"更暗"，而是**"能住但很穷"**。

### 二、做法：同一张噪声图，两个独立效果

```text
云影碎片化： 1 - p × (1 - n)            p = sky_patchiness
富贫斑块  ： floor + (1 - floor) × n     floor = 1 - patch_richness
透射率    ： 两者相乘
```

`p = 0 且 floor = 1` 时结果是恒 1 —— 默认配置**逐位等于旧行为**（有测试钉着）。

`worldgen` 用**同一个种子 + 同一个 `floor`** 再算一遍这张图，得到「肥沃度」，
用它给草甸落点加权（3 个候选取最肥）、给草甸半径和填充率缩放、给零散食物做拒绝采样。
于是「光岛」和「食物岛」在空间上重合——这在生态上也对：阳光充足的地方本来就是
食物链的起点。有一条测试 `fertility_matches_the_light_mask` 钉住这个隐性契约。

### 三、实测：机制成立，但没有产生 r/K 分化

**1. 世界确实被切成了两半**（`rich=0.7`，顶行透射率）：

| 位置 | 透射率 | 观感 |
|---|---|---|
| 富斑块 | 230~255 | 满照 |
| 贫斑块 | 约 90（= 0.3 × 255，噪声没取到 0） | 微光 |

食物密度：肥四分之一 / 瘦四分之一 = **> 2.5 倍**（`richness_piles_food_into_the_rich_patches`）。

**2. 体型没有分化。**

`stall = 30`、`growth` 开、8000 tick、2 种子：

| 配置 | 个体 | 平均体型 | 1格 | 2格 | 3格 |
|---|---|---|---|---|---|
| `rich=0.7`（梯度） | 2152 | 1.63 | 42.9 | 51.2 | 5.6 |
| `sun=0.65`（均匀变暗，同样平均亮度） | 2721 | 1.67 | 42.4 | 49.5 | 7.1 |

**两者几乎完全一样。** 梯度没有比"整体变暗"多给出任何东西。

按所在格天空光分带看也一样平：

| 天空光 | 0–24% | 25–49% | 50–74% | 75–99% |
|---|---|---|---|---|
| 个体 / 体型（`rich=0.7`） | 697 / 1.44 | 1502 / 1.74 | 1264 / 1.60 | 840 / 1.65 |
| 个体 / 体型（`sun=0.65`） | 494 / 1.36 | 1315 / 1.79 | 1752 / 1.67 | 1881 / 1.66 |

**3. `stall = 0`（必须长满）时梯度也只是把整条曲线平移**：

| `rich` | 0–24% | 25–49% | 50–74% | 75–99% |
|---|---|---|---|---|
| 0 | 2.40 | 2.96 | 3.04 | 3.13 |
| 0.7 | 2.47 | 3.04 | 3.00 | 2.97 |

注意 `rich = 0` 时**本来就有梯度**（2.40 → 3.13）——那是天空光沿深度衰减造成的
竖向梯度。富贫斑块没有把这条梯度拉宽。

### 四、为什么没成：1 格目标 = 出生即成年 = 立刻繁殖

这一条比"光够不够"关键得多。

`growth_plan` 是**母体成熟时的体型**。一个 1 格的母体生出来的芽，目标就是 1 格，
于是它**出生那一 tick 就成年**，可以立刻繁殖。而 3 格目标要花 20~40 tick 去长。

结果是 r 基因型（小目标）从贫斑块**扩散到富斑块**，并在那里同样赢——
因为繁殖速率对体型是**规模中性**的（`0.11n / n = 0.11/tick`，见 §16），
大身体在富斑块里没有任何相对优势，只是白白多花生长时间。

诊断验证：用 `mincells=2` 堵掉 1 格捷径之后，梯度才露出来一点
（`rich=0.7`、`stall=30`：0–24% 带 1.94 → 75–99% 带 2.49），但仍然不是双峰。

**所以富贫斑块是"环境的梯度"，不是"策略的分化"。**
要让它变成分化，必须让「小」有代价、或者让「大」有超线性收益——
这两件事都不在光场里，而在体型经济学里。

## 20. 批次 14：最短成长期（堵掉「1 格 = 出生即成年」）

### 一、这一批要解决什么

批次 12、12.1、13 三次实测都撞在同一堵墙上：

> `growth_plan` 是母体**成熟时的体型**。1 格母体的后代目标就是 1 格，
> 于是它**出生那一 tick 就"长满了"**，立刻成年、立刻繁殖。
> 3 格目标却要花 20~40 tick 去长。

所以「小」不是"更好"，而是**免费**。r 基因型因此在任何环境里都赢，
富贫斑块造出真实的光梯度也没用（§19）。

### 二、做法：一个年龄门槛

```text
芽每 tick：grow_age += 1
长满了 且 grow_age >= growth_min_ticks        → 成年
卡住够久 且 grow_age >= growth_min_ticks      → 提前成熟
```

**两条成熟路径都要过门槛**——否则「长不动就提前成熟」会把它绕过去，
而"长不动"正好是最需要它的场景（贫斑块里芽长不动，本来会立刻变小体型）。

它是**下限**不是**加时**：3 格身体本来就要长 20~40 tick，`N = 20` 对它没有额外惩罚，
只惩罚"什么都不用长"的个体。

**默认 20**。这一项只在 `growth_enabled` 打开时起作用，所以对旧世界零影响；
但一旦打开成长，`0` 会让整个机制塌成"1 格最优"——这不是口味问题，是功能是否成立的问题。

### 三、实测（6000 tick、单种子，扫描）

| 最短成长期 | 个体 | 平均体型 | 最大 | 存活种 | 1格% | 2格% | 3格% |
|---|---|---|---|---|---|---|---|
| 0 | 2682 | **1.69** | 5 | 107 | 42.3 | 48.6 | 7.5 |
| 15 | 1600 | **3.35** | 16 | 88 | 9.2 | 46.1 | 18.8 |
| 25 | 741 | **7.33** | 26 | 40 | 2.0 | 18.8 | 17.4 |
| 40 | 519 | **11.58** | 41 | 24 | 1.3 | 9.2 | 18.5 |

**体型从 1.69 一路涨到 11.58**，这是批次 9~13 所有努力里最强的一次杠杆
（之前最好的是成长刚落地时的 3.32）。分布也从"1~2 格占 90%"变成宽分布。

### 四、长跑 + 富贫斑块（15000 tick、3 种子）

| 配置 | 个体 | 平均体型 | 最大 | 存活种 | 占用 | 异养% | 嘴% |
|---|---|---|---|---|---|---|---|
| `mingrow = 0`（旧） | 2635 | 1.67 | 4 | 115 | 28.6% | 9.5 | 10.9 |
| **`mingrow = 20`（新默认）** | 1125 | **4.92** | 21 | 59 | 32.3% | 2.1 | 42.4 |
| `mingrow = 20` + `rich = 0.7` | 785 | **5.54** | 21 | 45 | 23.8% | 2.8 | 66.1 |

**代价**：人口减半、存活种从 115 掉到 59。但那个 115 里大部分是
"1 格生产者换个细胞类型"的伪多样性；现在最大能到 21 格，
体型分布宽得多。

### 五、富贫斑块终于分化了

`mingrow = 20` + `rich = 0.7`，按所在格天空光分带：

| 天空光 | 0–24% | 25–49% | 50–74% | 75–99% |
|---|---|---|---|---|
| 个体 / 平均体型 | 243 / **4.23** | 1137 / 4.36 | 644 / 5.94 | 331 / **8.60** |

**最亮的斑块里体型是最暗的两倍。** 批次 13 时这条曲线几乎是平的（1.44 → 1.65）——
因为那时"小"免费，梯度没有任何东西可筛。现在梯度第一次变成了真实的生态压力：
贫斑块里长不到成体尺寸就提前成熟，光岛里能长满。

### 六、为什么这一条比"给大体型收益"更根本

之前所有方案（Kleiber、繁殖折扣、温度、富贫斑块）都在改**成年个体的经济学**，
但问题根本不在成年个体身上，而在**「小」这条路径不收钱**。

一旦收钱（哪怕只是时间），体型立刻变成一条真实的演化轴。
这跟批次 12 的结论是同一句话的两面：

> 不是给了大体型收益，而是让「体型」第一次成为**有代价、可比较**的东西。

## 21. 批次 15：出芽（芽挂在母体上）

### 一、为什么它是「大个体第一次能赢」的候选

前面所有机制（Kleiber、繁殖折扣、温度、富贫斑块、最短成长期）都是**线性缩放**
或**一次性惩罚**。出芽不一样，它改的是繁殖的**结构**：

| | 普通繁殖 | 出芽 |
|---|---|---|
| 落点 | 4~6 格外的空地（失败率 70%） | **紧贴母体** |
| 一次性成本 | `food_needed = 细胞数`（随体型涨） | `bud_start_cost`（**固定 1.0**） |
| 同时能生几个 | 1 个 | `floor(n / bud_cells_per_slot)` 个 |
| 未成熟期 | 自己攒能量 | 母体每 tick 喂 `bud_feed` |

### 二、第一版是错的：出芽把体型压到了 1.80

按"1 格也有一个芽位"（`max(1)`）实现，实测：

| 配置 | 体型 | 说明 |
|---|---|---|
| 无出芽 | 4.76 | 基线 |
| 出芽（每芽位 2 格、供养 0.03） | **1.80** | 塌了 |

原因和批次 12 一模一样：**出芽最直接的效果是"出生不用再找空地"**，
而"让出生变容易"永远是偏向小体型的。1 格身体拿到了和 10 格一样的"最低配置"，
它又便宜得多，于是赢。

三个补丁，逐个都是实测逼出来的：

1. **芽位没有下限**（`floor(n / per)`，不 `max(1)`）——
   单细胞是分裂，不是出芽。
2. **没有芽位就退回普通繁殖**。第一版"出芽开着就一律走芽"，于是
   `bud_cells_per_slot >= 4` 时小个体直接绝育，**世界当场全灭（0 个体）**。
3. **芽位门槛必须够大**（默认 8 格）：

| 每芽位格数 | 2 | 4 | 6 | 8 |
|---|---|---|---|---|
| 平均体型 | 1.80 | 2.59 | 3.15 | 3.70 |

### 三、第二个关键：母体必须**喂得足**

`bud_feed = 0.03`（"多 25% 收入"）时体型只有 3.70，还是低于基线 4.76。
因为芽主要靠自己攒，而"自己攒多久"**正比于目标体型**——
大体型的芽长得慢、芽位长期占满，出芽的优势被吃光。

`bud_feed = 0.5`（满照收入的 4 倍）时，芽的成长期被压到
「最短成长期」那个**固定值**上，芽位周转快，大体型才真正赢：

| 每芽位格数 / 供养 | 体型 |
|---|---|
| 8 / 0.03 | 3.70 |
| 8 / 0.10 | 4.07 |
| 8 / 0.25 | 4.39 |
| **8 / 0.50** | **5.57** |
| 12 / 0.50 | 5.81 |

### 四、实测（15000 tick、3 种子、最短成长期 20）

| 配置 | 个体 | 平均体型 | 最大 | 存活种 | 有光占用 | 异养% | 嘴% |
|---|---|---|---|---|---|---|---|
| 基线（无出芽） | 1125 | 4.76 | 21 | 59 | 32.3% | 2.1 | 42.4 |
| **出芽** | 1339 | **5.25** | 20 | 64 | **45.1%** | **22.8** | 65.9 |

**每一项都变好了**：体型 +10%、人口 +19%、有光占用 +40%（32% → 45%）、
**异养从 2.1% 跳到 22.8%**。这是第一次有一个机制在**不牺牲任何东西**的前提下
把生态变厚。

### 五、为什么异养跟着起来了

芽是**紧贴母体**出生的，所以种群不再是散开的单细胞，而是**一簇一簇**的。
密集聚簇让「嘴」第一次有东西可吃（邻居就在旁边），而散开的单细胞世界里
捕食者要跑很远才遇到一个目标。

这是「空间结构 → 生态位」的一次自然涌现，不是我们直接调的。

### 六、诚实的边界

出芽仍然是**繁殖端**的机制。它把体型从 4.76 推到 5.25（+10%），
而不是像最短成长期那样翻倍。真正的超线性需要「后代体型不随母体增长」，
那会破坏遗传（10 格母体生出 3 格的芽，3 格的芽再生 3 格），
所以这一批没有做。

现在的状态是：**体型能稳定长到 5 格左右、最大 20 格、异养 20%+、
有光区占用 45%**。这是从批次 9 开始最健康的一个世界。

## 22. 批次 16：整口咬合（击杀时间 = 血量 ÷ 咬合力）

### 一、病根：血量是体积，伤害是接触面积

每格 1 HP，所以 n 格身体 = n 点血（**体积**）。
但旧的伤害逻辑是「每个贴着目标的杀手格各算一次」（**接触面积**）：

| 猎物 | 血量 | 同时贴着的杀手格 | 每 tick 伤害 | 击杀耗时 |
|---|---|---|---|---|
| 1 格 | 1 | 1 | 1 | 1 tick |
| 5 格 | 5 | 2~3 | 2~3 | 2 tick |
| 20 格 | 20 | 3~5 | 3~5 | **4~5 tick** |

**击杀时间 ∝ n / 接触格数 ≈ √n**。也就是说体型几乎买不到任何生存时间——
一个 20 格的巨物和 1 格的单细胞一样"几口就死"。这正是"大体型没有优势"的最后一块拼图。

### 二、做法：一个个体每 tick 对同一个目标只咬一口

```text
咬合力 = 单格伤害 × 这个个体的杀手细胞数
一个个体每 tick 对同一个目标最多造成一次「咬合力」
```

- 不按接触面积叠加（3 个接触格也只咬一口）
- 但**多只捕食者围攻**仍然有效（每只各自贡献一份）——「围攻」第一次有了意义
- 大捕食者仍然更强（杀手细胞多 → 咬合力大），只是不再"按面积白嫖"

实现：`World.killer_hits: HashSet<u32>`，每次 `act_organism` 开头清空，
所以它天然是 **per 攻击者 / per tick** 的。记的是**目标 id**。

### 三、实测

**单元测试直接钉住机制**（不靠生态数字猜）：

| 猎物 | 击杀耗时 |
|---|---|
| 1 格 | 1 tick |
| 5 格 | **5 tick** |

以及「3 个接触格仍然只挨 1.0」（旧行为是 3.0）、「3 个杀手细胞咬 3.0」、
「关掉开关逐位退回旧行为」。

**生态对照**（6000 tick、单种子、出芽世界）：

| 配置 | 个体 | 平均体型 | 最大 | 存活种 | 占用 | 异养% | 杀手% |
|---|---|---|---|---|---|---|---|
| 旧伤害（按面积叠加） | 1452 | 5.57 | 20 | 66 | 52.6% | 26.0 | **0.0** |
| **整口咬合** | 1545 | 5.10 | 21 | 67 | 51.2% | 16.4 | **0.5** |

**长跑（15000 tick、3 种子）**：

| 配置 | 个体 | 平均体型 | 最大 | 存活种 | 占用 | 异养% |
|---|---|---|---|---|---|---|
| 旧伤害 | 1339 | 5.25 | 20 | 64 | 45.1% | 22.8 |
| **整口咬合** | 1135 | **5.76** | 20 | 65 | 42.4% | 22.5 |

体型 **+10%**（5.25 → 5.76），人口 -15%，其余基本持平。
短跑（6000 tick）时体型反而略降，长跑才翻正——**过渡期和稳态的符号可以相反**，
这一条在这个项目里已经出现过很多次（批次 12 也踩过）。

杀手占比从 0.0 回到 0.5——**能活下来的捕食者变多了**。原因：整口咬合削弱了
「贴上去就秒杀」的效率，捕食者不再能在 1~2 tick 内解决战斗，于是
"咬不动就换目标"的个体被淘汰，"能持续啃"的个体活下来。

异养占比掉了（26.0 → 16.4），说明**混养**（边光合边咬）的比例上升了：
专性异养靠"秒杀后吃尸体"，而整口咬合让这件事变难。

### 四、这一批的意义

这是「体型经济学」的最后一块：前几批把**繁殖端**挖到底（最短成长期 + 出芽），
这一批补上**生存端**——体型第一次同时买得到"长得大"和"活得久"。

按理论，现在 20 格个体在被一只单杀手细胞捕食者攻击时能撑 20 tick，
足够繁殖 1~2 次；而在旧规则下只有 4~5 tick，什么都来不及。

## 23. 批次 17：默认值、双列参数、渲染与画笔修复

这一批是收口，把前几批的成果变成"打开就能用"，顺手修几个手感的坑。

### 一、成长 + 出芽设为默认开

`growthEnabled` / `buddingEnabled` 从 `false` 改成 `true`。

代价是**起步慢**：后代要先长成成体，所以 600 tick 时只有 133 只
（旧默认 648）。但它是健康的爬坡，不是崩：

| tick | 1500 | 3000 | 6000 |
|---|---|---|---|
| 个体 | 508 | 822 | 847 |
| 存活种 | 8 | 33 | 34 |

单 tick 0.82 ms（6000 tick / 4.9 s），在预算内。

### 二、全局参数改双列

参数从 3 项长到 20 多项，单列排下来 2000 多像素，一打开就铺满屏幕。
改成 `horizontal_top` + 两个固定 316px 的 `vertical`，左列放「世界 / 生命 /
繁殖 / 体型」，右列放「成长 / 环境温度 / 能量账」。

实现上有个便宜的小技巧：两列各自是一个 `|ui| { ... }` 闭包，里面的 `ui`
是**内层那个**（同名遮蔽），所以原来那 600 行代码**一个字都不用改**，
只要在中间切一刀、两头各补一个 `});`。

### 三、所有窗口默认关闭

工具 / 全局参数 / 类型参数 / 检视器 / 物种 / 曲线全部 `false`，
打开程序先看到世界本身，需要什么再从顶栏点开。

### 四、画布不再重复平铺

`grid.wgsl` 原来的逻辑是「世界比视口大的方向做取模」，本意是放大时看不出接缝。
但默认世界大小下，缩到某个比例时世界刚好比视口大一点点，平移到边缘就会
看到同一个世界**重复铺好几份**。

现在改成：**画布上永远只画一份，越界就是背景色**。
世界的上下左右回环仍然存在，但那**只在模拟里**（`grid.index` 折回、光场环绕、
生物从右边走出去从左边进来）——模拟规则和渲染是两件事。
渲染测试从 `world_wraps_when_camera_goes_negative` 改成
`world_does_not_tile_visually`，断言的是**不该**出现第二份。

### 五、画笔越界截断

`grid.index` 在 `wrap` 打开时会把越界坐标折回对面，于是"在画布上侧外面画一笔"
会真的画到世界**底部**。画笔是玩家的手，不是模拟，越界就该什么都不发生。
`apply_brush` 里加了显式边界判断。

### 六、笔刷去掉「空」，加「擦生物」

原来笔刷里的「空」既擦地形又（本应）擦生物，两种意图混在一起；而且它其实
早就擦不动生物了（`apply_brush` 有一条"别把活着的身体抹掉"的保护）。
现在拆成两个明确的橡皮擦：

| 笔刷 | 擦什么 | 不碰什么 |
|---|---|---|
| 擦地形 | 墙 / 岩浆 / 沼泽 / 辐射带 / 腐殖质 | 食物、生物 |
| **擦生物**（新） | 整只生物（不留残骸，能量进热池） | 地形、食物 |

`World::erase_creature_at` 是新加的：和 `kill_organism` 的唯一区别是**不撒食物**
——这是玩家在擦画布，不是捕食。但能量不能凭空消失，所以进热池。

## 24. 批次 19：收入审计（到底有没有捕食者）

### 一、问题

用户问：「你是如何判定一个生物是自养生物还是异养生物呢？看它有没有嘴吗？」
并观察到：物种里最常见的是「生产者」和「生产者 + 嘴」，没看到以捕食为主的生物。

**答案：之前用的判据是结构，不是行为。**

```rust
异养 = 有嘴 && !有生产者      // 纯结构判定
```

「生产者 + 嘴」在结构上算**自养**——哪怕它九成能量都是咬来的。所以那个指标
根本回答不了"有没有捕食者"。

### 二、补上行为判据：四个收入计数器

`Organism` 加了 `gain_photo` / `gain_food` / `gain_bite` / `gain_gift`，
在**实际到账**那一刻累加（`add_energy` 改成返回真正进账的量，装不下的不算）。
`income_source()` 取四项里最大的一份，就是"主要靠什么活着"。

### 三、实测（默认配置、6000 tick、3 种子）

| 光合 | 吃食物 | 咬活体 | 母体供养 | 没收入 |
|---|---|---|---|---|
| 15.0% | 0.0% | **76.4%** | 7.9% | 0.6% |

**捕食根本没缺席——它占了七成六。** 但按结构算的「异养」只有 18.8%，因为：

| 咬 > 50% 的个体 | 占比 |
|---|---|
| 其中**纯异养**（无生产者） | 17.4% |
| 其中**混养**（有生产者） | **56.4%** |

**56.4% 的个体是「生产者 + 嘴」，但主要靠咬活体活着。**
这正是用户看到的那两个"最常见物种"——它们**看起来是自养，行为上是捕食者**。

### 四、为什么长不成"纯捕食者"

算笔账（每格每 tick）：

| 策略 | 收入 | 成本 | 净 |
|---|---|---|---|
| 生产者（满照） | 0.12 | 0.010 | 0.11 |
| 嘴（咬到人） | **0.30**（`bite_rate`） | 0.010 | **0.29** |

**咬比光合划算 2.6 倍**，所以人人都咬；而一个生产者细胞只花 0.010 就能挣 0.12，
**留着它几乎是免费的**（还是没猎物时的兜底）。于是最优解就是"一张嘴 + 几个生产者"，
纯异养只有在"养生产者太贵"或"没光"时才划算。

### 五、顺带修的一个诊断工具的坑

`body_scan` 之前把没传的参数**硬编码成旧默认值**（`mingrow=0`、`budper=2.0`、
`budfeed=0.03`、`growth` 默认关），于是"不传参数"跑出来的并不是应用默认配置。
现在全部改成 `Config::default()` 兜底，并且 `growth` / `bud` 默认跟随配置，
要关得显式写 `nogrowth` / `nobud`。

（这也是为什么上面这组数字和之前报的不一样：之前的 22.8% 是 `stall=30` 的配置，
应用默认是 `stall=0`。）

## 25. 批次 20：bite_rate 扫描（拐点在 0.02，不是 0.12）

### 一、动机

批次 19 发现默认配置下 **76.4% 的个体靠咬活体活着**。最直觉的解释是
"咬 0.30/tick 比光合 0.12/tick 划算"，那就把 `bite_rate` 调低。扫了一遍。

### 二、扫描（默认配置、6000 tick、3 种子，只动 `bite_rate`）

| bite | 个体 | 体型 | 物种 | 嘴% | 光合 | 咬活体 | 供养 | 咬>50% | 纯异养 | 混养 |
|---|---|---|---|---|---|---|---|---|---|---|
| **0.30（默认）** | 830 | 9.57 | 36.3 | 18.8 | 15.0 | **76.4** | 7.9 | 73.8 | 17.4 | 56.4 |
| 0.20 | 839 | 9.68 | 35.0 | 17.1 | 15.4 | 73.7 | 10.4 | 69.2 | 15.3 | 53.9 |
| 0.15 | 813 | 10.77 | 36.3 | 15.6 | 16.0 | 68.6 | 15.1 | 64.0 | 12.8 | 51.2 |
| 0.10 | 860 | 10.14 | 33.0 | 10.4 | 24.9 | 57.6 | 17.3 | 51.8 | 8.0 | 43.8 |
| 0.05 | 778 | 11.69 | 40.0 | 9.8 | 26.8 | 49.7 | 23.1 | 41.1 | 5.7 | 35.4 |
| 0.03 | 823 | 10.70 | 41.0 | 8.4 | 36.2 | 34.3 | 29.3 | 25.9 | 3.7 | 22.2 |
| **0.02** | 939 | 9.50 | 39.0 | 6.2 | **52.1** | 20.0 | 27.4 | 14.5 | 2.3 | 12.2 |
| 0.00 | 930 | 10.56 | 50.0 | 7.8 | 48.9 | 0.0 | 50.3 | 0.0 | 0.0 | 0.0 |

**这个旋钮有效，但很钝**：从 0.30 降到 0.05（降到 1/6），捕食占比只从 76% 掉到 50%。
真正的拐点在 **0.02~0.03** —— 那时光合（52%）才第一次超过咬（20%）。

### 三、为什么拐点是 0.02 而不是 0.12

因为**一张嘴能同时咬 4 个邻居**（`Behavior::Mouth` 遍历四邻域，每个目标各抽一次），
而一个生产者只吃自己那一格的光。所以：

```text
嘴的收益上限 = 4 × bite_rate         （被围住时）
生产者的收益上限 = 0.12              （满照）
```

`4 × 0.03 = 0.12` —— 正好是光合的满照收入。**这才是真正的平衡点。**
0.30 时嘴的上限是 1.2/tick，是生产者的 **10 倍**。

### 四、顺手证伪了一个假设：遮挡不是元凶

原本猜"密集聚簇里生产者被自己人遮死，所以光合挣不到钱、只能去咬"。实测：

| 配置 | 光合 | 咬活体 | 纯异养 |
|---|---|---|---|
| bite=0.05、遮挡 0.25（默认） | 26.8 | 49.7 | 9.8 |
| bite=0.05、**遮挡 0** | 21.3 | **61.6** | 27.6 |
| bite=0.30、**遮挡 0** | 6.3 | **90.5** | 29.7 |

**关掉遮挡之后捕食反而更凶**（76% → 90%，纯异养 17% → 30%）。
机制是反的：没有遮挡 → 生产者更肥 → 人口更密 → 邻居更多 → 咬更划算。
**遮挡其实是抑制捕食的因素**（它压低了密度），不是"逼人去咬"的原因。

### 五、代价与建议

降 `bite_rate` 几乎没有副作用：体型稳定在 9.5~11.7 格，物种 36 → 39~50（略增），
人口持平。唯一的变化是**幼体存活率上升**——「供养」占比从 7.9% 涨到 27~29%，
意思是种群里有大量还没长大的芽（没有捕食压力时幼体才活得下来）。

> **两个选择**：
> 1. 直接把 `bite_rate` 默认值改成 **0.02**（一行，生态立刻变成光合主导）；
> 2. 或者修根因——**让一张嘴每 tick 只能咬一个目标**（现在能咬 4 个），
>    这样 0.30 的上限就从 1.2 降到 0.30，仍然是生产者的 2.5 倍，
>    但不再是 10 倍。这个更"物理正确"，但会动到批次 9.5 的核心逻辑。

## 26. 批次 21：一张嘴一口（修根因）

### 一、改了什么

批次 20 把根因挖出来了：`Behavior::Mouth` 遍历四邻域，**每个邻居各抽一次
`bite_rate`**，所以单嘴上限是 `4 × bite_rate`。改法不是降参数，是修模型：

> 嘴是一根管子，同一瞬间只能对上**一个**活体目标。

实现（`crates/core/src/world.rs::run_cell_function`）：

1. 先走一遍四邻域，**吃光所有够得着的食物**，顺手把活体邻居记进 `victims`；
2. 有多个目标时**随机挑一个**咬（不是按 `NEIGHBORS_4` 顺序的第一个——那会让
   嘴永远优先咬上方，生态里长出假的方向性；也刻意不挑"最肥的"，那等于给捕食者
   完美信息）；
3. 单目标时不抽随机数，`mouth_one_bite = false` 时更是一颗随机数都不碰，
   保证旧路径逐位可比。

**食物不受配额限制**：它是躺在格子里的存量，一口能舔到几格由几何决定，
不该占"咬住不放"的那个配额——否则嘴在尸体堆里反而变弱。

开关：`LifeCfg::mouth_one_bite`（默认 `true`），UI 里叫「一张嘴一口」，
`body_scan` 里是 `oldmouth` 标志。

### 二、实测（默认配置、6000 tick、3 种子，p = 1.0 行）

| 配置 | 个体 | 体型 | 物种 | 光合 | 咬活体 | 咬>50% | 纯异养 |
|---|---|---|---|---|---|---|---|
| bite 0.30 · **旧**（四邻域各一口） | 845 | 9.30 | 48.7 | 15.2 | **76.0** | 73.1 | 17.1 |
| bite 0.30 · **新**（一口一目标） | 822 | 10.27 | 38.7 | 13.3 | **61.8** | 56.6 | 11.3 |
| bite 0.15 · 新 | 799 | 10.58 | 39.0 | 19.5 | 50.8 | 45.4 | 6.7 |
| bite 0.12 · 新 | 872 | 10.18 | 41.0 | 27.0 | 48.5 | 41.6 | 3.3 |
| bite 0.06 · 新 | 904 | 9.97 | 46.0 | 37.8 | 33.5 | 26.6 | 1.4 |

（"光合 / 咬活体 / 供养"按个体累计能量收入的最大项归类，见批次 19。）

### 三、读出来的三件事

**1. 根因修对了，但幅度只有 2.5 倍，不是 4 倍。**
0.30 下「咬为主」从 73.1% 掉到 56.6%，纯异养 17.1% → 11.3%，体型反而涨了
（9.30 → 10.27：暴利通道关掉之后，靠 4 倍收益活着的薄壳策略被淘汰）。
如果每张嘴平均真能同时咬到 4 个目标，这一刀应该砍掉 3/4 的收益；实际只砍掉
一半多一点，说明**平均接触目标数是 2 个左右**，不是 4。

**2. 平衡点整体右移了 2~2.5 倍。**
旧模型拐点在 `bite ≈ 0.02~0.03`（`4 × 0.03 = 0.12`）；新模型下 `bite = 0.06`
时光合（37.8%）才第一次稳稳超过咬（33.5%）。2.5 倍这个系数和"平均接触 2 个
目标"完全对得上——**两个独立证据指向同一个数字，说明这次改的是模型不是巧合。**

**3. 默认值 0.30 仍然让捕食占优，但这是参数问题，不是模型问题了。**
0.30 是满照光合（0.12）的 **2.5 倍**，所以只要咬得到，它永远比光合划算。
想要"光合主导、捕食是少数"，得把默认值降到 **0.06~0.08**。

### 四、这一批的教训

- **「扫描参数」和「修模型」是两件事**。批次 20 已经能靠 `bite_rate = 0.02`
  拿到光合主导的生态，但那个 0.02 是"用来补偿模型错误"的假值——换个地形、
  换个密度，它立刻失效。修完根因之后 `bite_rate` 才第一次代表"咬一口值多少"，
  而不是"咬一口值多少 ÷ 4"。
- **改行为时要留旧路径**。`mouth_one_bite = false` 不是给玩家用的开关，是给
  诊断用的对照组：没有它，这次改动就只能和批次 20 的历史数字比（中间还隔着
  别的批次），没法干净地做单变量对照。
- 一个顺手的设计问题：**多嘴生物的收益仍是线性的**（每张嘴各咬一个目标），
  而光合被遮挡压成"面积上限"。这其实是个不错的生态分化通道——捕食收益 ∝ 周长，
  光合收益 ∝ 面积但有遮挡惩罚。留着看。

### 五、默认值 0.30 → 0.06（批次 21.1）

修完模型之后 `bite_rate` 才第一次代表"咬一口值多少"，所以默认值必须重定：

> **0.06 = 满照光合（0.12）的一半。**

理由不是"想让光合赢"，而是**营养级的位置**：生产者是食物网的地基，捕食者只能吃
它长出来的那一层。如果"咬一口"比"照满光造一份"更值钱，生态会整体倒过来——
绝大多数个体靠咬同类活着，而同类身上并没有凭空多出来的能量，于是整个系统变成
"谁咬得快谁赢"的零和竞争。

捕食的溢价留给别的机制去给：**猎物身上存着的能量**（`storage_capacity = 6.0`
意味着能连吸 20 tick）才是真正的大餐，而不是"每 tick 白拿一份比光合还多的收入"。

**新默认下的生态（6000 tick、3 种子、p = 1.0）**：

| 指标 | 旧默认（0.30 · 四邻域各一口） | 0.30 · 一口一目标 | **0.06 · 一口一目标（新默认）** |
|---|---|---|---|
| 个体 | 845 | 822 | **904** |
| 平均体型 | 9.30 | 10.27 | **9.97** |
| 物种 | 48.7 | 38.7 | **46.0** |
| 有光占用 | 51.7% | 55.2% | **58.7%** |
| 光合收入为主 | 15.2% | 13.3% | **37.8%** |
| 咬活体为主 | **76.0%** | 61.8% | **33.5%** |
| 母体供养为主 | 8.1% | 24.3% | **28.4%** |
| 咬 > 50% | 73.1% | 56.6% | **26.6%** |
| 纯异养（无生产者） | 17.1% | 11.3% | **1.4%** |

**三类收入第一次形成均衡**：光合 37.8% / 咬 33.5% / 供养 28.4%。
「供养」高是正常的——它统计的是还没长大、靠母体喂的芽（批次 15 出芽），
这些个体长大后会分流到光合或捕食。

**代价与收益**：

- 人口 845 → **904**（+7%），有光占用 51.7% → **58.7%**——世界反而被用得更满。
  捕食压力降下来之后，生产者能把光区铺开，总能量收入上升。
- 纯异养几乎归零（17.1% → 1.4%）。**这是唯一真正的损失**：完全靠捕食为生的物种
  在 0.06 下很难站稳——捕食者必须自己也带生产者，否则收入不够养活自己。
  如果以后想让"纯捕食者"成为稳定生态位，该动的是**猎物身上的能量密度**
  （储食细胞、残骸价值），不是把 `bite_rate` 调回去。
- 体型 9.97，介于旧默认的 9.30 和 0.30-一口的 10.27 之间——没有塌。

## 27. 批次 22：昼夜循环（光场第一次有"时间"）

### 一、为什么是它

光场从批次 7 到现在一直是**空间性**的：`sky_level` 只随位置变，云影也是固定的噪声图。
这带来一个副作用——**储能细胞（`storage_capacity = 6.0`）唯一的意义是"吃尸体"**。

给光加一个周期，储能第一次有独立价值，而"容量 ∝ 体型"意味着大体型第一次有实质优势。
这一条是冲着从批次 5 追到现在都没解决的老问题去的：**大有什么用**。

### 二、实现

- `WorldCfg::day_length`（tick，0 = 关闭 = 永远正午）+ `night_floor`（夜间剩余日照比例）。
- 日照系数 `d = night_floor + (1 - night_floor) × (0.5 + 0.5·cos(2π·phase))`，
  `phase = 0` 正午、`phase = 0.5` 午夜。**乘在天空光传播之后**（和云影同一层）。
- **点光源不受影响**：云挡得住太阳，昼夜也一样挡不住玩家放的灯。
  于是夜里灯从"锦上添花"变成"唯一的收入来源"。
- 性能：`rebuild` 把算完的天空光存成 `sky_base`（正午基准），之后 `set_daylight`
  只是拿基准乘一个标量。变化小于 1/512 就跳过——一个 600 tick 的白天最多重算 ~255 次。

曲线用**余弦**而不是方波：方波会让"日落"那一 tick 光合收入从满额直接掉到 `night_floor`，
储能来不及补；余弦让个体有整个下午去填电池。

### 三、`night_floor` 有一个悬崖（重要）

夜间净收入 = `0.12 × night_floor − 0.010`（每格每 tick）。收支平衡点在 **0.083**。

低于它，夜里净亏钱，而**刚繁殖完的个体能量是 0**（出芽启动成本 1.0 会把能量清掉），
于是 `starvation_ticks = 60` 会让它们在夜里直接饿死——出生几乎全部挤到白天。

实测（6000 tick、3 种子、p = 1.0）：

| night_floor | 个体 | 体型 | 物种 | 占用 |
|---|---|---|---|---|
| 0.05 | **148** | 12.14 | 7.0 | 11.1% |
| 0.07 | 397 | 9.24 | 16.3 | 22.2% |
| **0.085（默认）** | **499** | **9.60** | 25.7 | 29.8% |

0.05 → 0.085 只差 3.5 个百分点的日照，人口差 **3.4 倍**。这是**悬崖，不是斜坡**：
一旦夜间净收入为负，"能量为 0 的个体"就必然在 60 tick 后死亡，没有中间地带。

**所以默认取 0.085**：夜里只是"不赚钱"，不"赔钱"。

### 四、真正的发现：昼夜不是"变暗"，是"把能量集中"

这一批最反直觉的一条。同样把**平均光照砍半**，两种做法结果完全不同：

| 配置 | 个体 | 平均体型 | 物种 | 有光占用 |
|---|---|---|---|---|
| 无昼夜（基线，满照） | 904 | 9.97 | 46.0 | 58.7% |
| **均匀变暗**（`photo = 0.063`） | 754 | **4.67** | 42.3 | 23.2% |
| **昼夜**（600 tick / 0.085） | 499 | **9.60** | 25.7 | 29.8% |

**平均光照几乎一样，体型差一倍。** 昼夜把体型从 4.67 拉回 9.60——基本等于满照基线。

机制是**非线性**的：生长和繁殖都有阈值。
- 均匀的低收入 → 芽攒不够生长成本 → `growth_stall_mature` 提前成熟 → 小体型（r）。
- 白天满额 + 夜里零收入 → 白天一口气长满、夜里只是不长 → 大体型（K）。

这是 Jensen 不等式的一个实例：`f(E[x]) ≠ E[f(x)]`，而这里的 `f` 是阈值函数。
**"把能量集中"和"把能量平均削减"不是同一件事**，尽管它们的平均值相同。

顺带解释了为什么"富贫斑块 + 最短成长期"当年能让梯度分化（批次 14）：
它做的也是"把能量在时间和空间上集中"，而不是"整体调暗"。

### 五、代价与默认值

- 人口 904 → **499**（-45%），物种 46 → 26。这是平均日照 0.54 的必然结果。
- **默认 `day_length = 0`（关闭）**：它改变的是整个生态的基线，不该悄悄生效。
  想用就自己开，并且要接受"世界变穷"——想保住人口就同时提高天空光或光合速率。
- `night_floor` 默认 0.085（安全值），不是 0.05（会崩）。

## 28. 批次 22.1：收入可视化（把审计搬进 UI）

批次 19 就做出了四个收入计数器，但只有 `body_scan` 能看到。用户反复问
"怎么看有没有捕食者"，答案其实一直在数据里，只是没画出来。

- `OrgStats::income: [f64; 5]`：按**实际到账能量**归类（光合 / 吃食物 / 咬活体 /
  供养 / 没收入），五项加起来 100。`organism_stats()` 里顺手统计，零额外遍历。
- **曲线窗口**加三条线（光合收入 / 捕食收入 / 供养收入）。默认关——
  它们和"存活物种"抢同一条 Y 轴，一起开太挤。
- **检视器**加一条收入构成横条：四段彩色，一眼看出这只生物是自养还是捕食。

口径必须强调：**判据是能量，不是解剖结构**。「生产者 + 嘴」在结构上是自养，
但九成收入来自咬活体时，它在生态里就是捕食者。批次 19 之前所有"异养占比"
读数都是结构判据，所以一直显示 0，看起来像捕食者根本不存在。

## 29. 批次 23：捕食端体型差（大体型的第一条"进攻性"收益）

### 一、动机

大体型的收益在此之前**全是防御性**的：血量（活得久）、容量（囤得住）、
出芽位（多养几个）、Kleiber（维持便宜）。**捕食端完全中性**——
一只 1 格的和一只 20 格的咬同一口，抽走的能量一模一样。

真实生态里捕食有硬约束：**捕食者必须比猎物大**。

### 二、实现

`LifeCfg::size_advantage`（0 = 关闭，**默认 0**）。咬的收益乘
`clamp((n_捕食者 / n_猎物)^k, 0.25, 4.0)`。

- **用幂不用线性比**：线性比会让"20 格咬 1 格"直接 20 倍，立刻变成大者通吃的军备竞赛。
  0.5 次幂是"体长比"的直觉——捕食者的优势来自**能咬穿**，不是格子数差多少。
- **上限 4.0**：再高的话捕食收益会压过光合（满照 0.12，4 倍 = 0.48/tick），
  生态瞬间倒向"越大越好"，正是这批改动想避免的。
- **下限 0.25**：保留"蚂蚁咬大象也能啃一口"，归零会让小个体彻底失去捕食这条路，
  而小个体是生态里的多数。

### 三、扫描（6000 tick、3 种子、p = 1.0）

| size_advantage | 个体 | 平均体型 | 物种 | 有光占用 | 光合 | 咬 | 供养 |
|---|---|---|---|---|---|---|---|
| 0（默认） | 904 | 9.97 | 46.0 | 58.7% | 37.8 | 33.5 | 28.4 |
| **0.5** | 821 | **10.91** | 35.7 | 58.5% | 28.9 | 30.2 | 40.5 |
| 1.0 | 948 | 9.97 | 47.0 | 61.8% | — | — | — |

**0.5 是甜点：体型 +9.4%，但物种 -22%。1.0 直接回落到基线——非单调。**

非单调这件事在这个项目里出现过很多次（批次 9.5 的 `bite_rate` 0.45 让杀手飙到 79.8%，
0.6 又长出一堆异养）。原因是系统坐在分岔点上，"加大旋钮"不等于"加强效果"。

### 四、又一次撞上同一堵墙

**+9.4% 是"给大体型收益"这条路上最好的一次，但仍然不够。** 根因还是那个：

> `can_place_at` 要求**整块连通空地**，身体越大越难落脚。
> 这是整个经济学里唯一的非线性项，而且方向和"大更好"相反。

所有"给大加成"的尝试（规模经济、Kleiber、温度、富贫斑块、昼夜、体型压制）
都只是线性缩放收益，压不过"出生"这个反向选择。**唯一真正有效过的是出芽**
（批次 15，体型 +10%，因为它绕开了"找空地"），和最短成长期（批次 14，体型 1.67 → 4.92，
因为它堵掉了"1 格目标出生即成年"这条捷径）。

**所以下一批要动的不是"收益端"，是"出生端"**——这正是 ⑥ 卵生要解决的问题。

### 五、默认值

**默认 0（关闭）**：收益（+9%）小于代价（物种 -22%），不值得写进基线。
想要更强的捕食压制就手动调到 0.5，并且接受物种数下降。

## 30. 批次 24：同种相残惩罚（让"谁吃谁"第一次有物种）

### 一、问题

嘴咬**任何**非自己的活体——同种也咬。于是捕食压力没有"物种"这个概念：
既无法特化（没有"我的猎物是谁"），也没有"同类相残的代价"。

这是纯捕食者站不住的深层原因之一：一个刚变异的捕食者，周围最多的食物是**自己的同类**，
于是它先把自己的种群吃空，再灭绝（批次 21.1 实测纯异养只剩 1.4%）。

### 二、实现

`LifeCfg::kin_bite_penalty`（**默认 0.5**）。同种之间咬的收益乘 `1 - 本值`。

判据是 `species_fingerprint`（身体蓝图的逐格哈希）。**它很脆**：变异一次指纹就变，
母子可能被判成不同种。这一批先按它做，是为了量出"同种相残到底占多少"。

### 三、实测（6000 tick、3 种子、p = 1.0）

| 指标 | 关闭（0） | **默认（0.5）** |
|---|---|---|
| 个体 | 904 | 880 |
| 平均体型 | 9.97 | 10.12 |
| 物种 | 46.0 | 39.3 |
| 有光占用 | 58.7% | 58.1% |
| 光合收入为主 | 37.8% | **45.6%** |
| 咬活体为主 | 33.5% | **21.6%** |
| 母体供养为主 | 28.4% | 32.6% |

**捕食 -35%、光合 +21%，而人口只掉 2.6%。** 这是这一批里代价最小、方向最干净的一次。

### 四、真正的价值在低 p 配置上

`p = 0.5`（繁殖成本随体型快速上升，本该是个"小个体世界"）：

| | 个体 | 平均体型 | 物种 |
|---|---|---|---|
| kin = 0 | 382 | 2.86 | 21.0 |
| **kin = 0.5** | **750** | **6.06** | 45.3 |

**个体翻倍、体型翻倍、物种翻倍。** 高密度小体型世界里，同类互咬本来是最严重的内耗——
大家挤在一起，邻居全是自己人，咬到的每一口都在消耗自己的种群。
把这条路堵上一半，世界立刻健康。

这条结果说明：**"同种相残"不是一个小修正，它一直在悄悄吃掉生态的产能。**

### 五、为什么默认开（少数例外）

项目惯例是"新机制默认关"。这一条破例，因为：

1. 代价只有 2.6% 的人口；
2. 方向明确（捕食降、光合升），不是把参数推向某个分岔点；
3. 它在低 p 配置上救的是"濒死"（382 → 750），不是"锦上添花"。

**开满（1.0）也没有把捕食清零**（实测仍有 21% 左右）——说明被指纹漏掉的那部分
（母子、近亲）确实存在，惩罚只吃掉了"真·异种误判"之外的一部分。
如果以后要更准，用「指纹 + 体型差」的复合判据。

## 31. 批次 25：洞穴世界（暗区终于有饭吃了）

### 一、动机

批次 10.5 的结论一直挂在那里：**「有暗区」不够，暗区还得有饭吃才可能住人**。
云影把世界切成光岛和暗廊，暗廊里没有生物——不是因为黑，是因为**又黑又穷**。

两样东西其实都已经有了：`WALL` 挡光、`HUMUS` 每 tick 产食。缺的只是**把它们摆在一起**。

### 二、实现

`WorldCfg::cave_count`（0 = 关闭，默认 0）。世界生成时挖 `N` 条带顶隧道：

- 隧道本体 2~3 行高，**洞顶两层墙**（挡光）、**洞底腐殖质**（产食）；
- 每条从起点挖一条竖井通到地表——不然生物进不去，洞穴就只是装饰；
- 只挖世界下半部分（`rows × 0.50 ~ 0.90`），太靠上会和地表连成一片。

竖井会变成**光柱**：洞口亮、越往里越暗。这正好是个梯度，不需要额外设计。

### 三、实测（6000 tick、3 种子、p = 1.0，kin 已默认开 0.5）

| 指标 | 无洞穴 | **4 条洞穴** |
|---|---|---|
| 个体 | 880 | **988** |
| 平均体型 | 10.12 | 9.24 |
| 存活物种 | 39.3 | **51.0** |
| 有光占用 | 58.1% | 60.2% |

**物种 +30%，人口 +12%。** 这是"新生态位"最直接的证据：多出来的是一个
**光照上与地表隔离、但自己产食物**的空间，于是演化出只在那儿能活的形态。

按天空光分带也印证了这一点——**最暗那一带（0–24%）住着 388 个个体、平均体型 8.30**，
和平均值 9.24 差不了多少。暗区不是坟场，是另一个家。

### 四、为什么默认关

它是**世界形态**的选择，不是全局机制：喜欢开阔草原的人不该被强行塞进洞穴。
0 = 和以前逐位相同的世界；调到 4~6 就是一个"地下世界"预设。

代价要知道：洞穴会吃掉地表的一部分草甸（挖洞时覆盖），
所以地表食物会略少——这是"把资源挪到地下"的必然。

## 32. 批次 26：繁殖失败冷却（把白跑的那 80% 省掉）

### 一、问题

`repro_fail_costs_energy = false`（批次 11 改的）让失败的个体**下一 tick 立刻重试**。
好处是"找不到地方就继续攒着"，坏处是"找不到地方"的个体每 tick 白跑一遍四邻域搜索：
实测尝试次数涨 20 倍、tick 耗时 ×1.67。

### 二、实现

`LifeCfg::repro_cooldown`（**默认 10**）。失败后等 N tick 才能再试。

实现上**包了一层**而不是在每个 `return false` 上各写一句：

```rust
fn reproduce_organism(&mut self, i: usize) -> bool {
    let ok = self.reproduce_organism_inner(i);
    if !ok { /* 设冷却 */ }
    ok
}
```

`inner` 里有 5 条失败路径（太小 / 到达上限 / 找不到空地 / 路径被挡 / 变异把身体删空），
逐条维护迟早漏一条。

### 三、实测（6000 tick、3 种子、p = 1.0）

| 指标 | 冷却 0 | **冷却 10** |
|---|---|---|
| 个体 | 880 | 874 |
| 平均体型 | 10.12 | 10.00 |
| 存活物种 | 39.3 | **48.7** |
| 扫描耗时 | 169 s | **145 s（-14%）** |

尝试次数砍掉约 **80%**（p = 0.7 时 173 万 → 36 万），生态几乎不动。
物种还涨了 24%——可能是"繁殖窗口变成稀缺资源"之后，抢不到地方的个体不再空转，
而是把能量用于生存，弱竞争者活得更久、变异更容易被保留。

**白赚，所以默认开 10。**

### 四、一个可能的后续

冷却把"繁殖"从"攒够就生"变成"攒够了还得等"。如果以后要让**繁殖时机**真正可演化，
下一步是给它一个感知输入（现在的 40 维里没有"我还得等多久"）。
那属于改大脑输入维度，是另一个量级的改动。

## 33. 批次 27：卵生（捕食压力第一次进到繁殖环节）

### 一、为什么

出芽已经覆盖了"出生不用找空地"这一半价值，所以卵生的独特价值只剩一个：
**把捕食压力搬到繁殖环节**——吃一枚卵等于消灭一个未来的个体，而且**不用打赢母体**。

它和出芽正好是 r / K 两端：

| | 出芽（K） | 卵生（r） |
|---|---|---|
| 位置 | 紧贴母体 | 产在空地上（4~6 格外） |
| 供给 | 母体每 tick 供养 | 母体一次付清，之后不管 |
| 风险 | 低（躲在母体旁边） | **高（卵挡路、能被吃）** |
| 空间代价 | 占母体的芽位 | **占世界的一格** |

### 二、实现

新类型 `ct::EGG`（id 16）：**既不是地形、也不是身体细胞**——它是"别人生的东西"。

- `passable: false`：卵挡路，挡住移动和繁殖。于是"产卵"第一次有空间代价。
- `paintable: false`：玩家不该凭空画卵，那是模拟内部状态。
- `visible: true` 但**不进 `VISIBLE_CELL_TYPES`**：画面上看得见，但大脑感知不到
  （那 8 个槽位已经满了，加第 9 个会改大脑输入维度，是另一个量级的改动）。

`World::eggs: HashMap<usize, Egg>`，`Egg { hatch_at, parent, child: Organism }`。
**存完整的个体而不是蓝图**：这样 `Organism::new` 的 RNG 消耗发生在产卵那一刻
（和普通繁殖完全一致），孵化时不碰 RNG。

三个关键细节：

1. **审计要单开一项** `EnergyAudit::eggs`——卵里的能量既不在个体里、也不在食物里，
   但它确实还在生物圈内。不记这一笔，`注入 == 存量` 会凭空少一块。
2. **孵化顺序按下标排序**：`HashMap` 的迭代顺序不稳定，不排序就不可复现。
3. **孵化用 `reveal_floor` 而不是 `set_cell_at(EMPTY)`**：卵可能产在腐殖质上，
   直接设 EMPTY 会把那层地形一起抹掉。

### 三、实测（6000 tick、3 种子、p = 1.0，kin 已默认开 0.5、冷却已默认 10）

| 指标 | 无卵生 | **卵生** |
|---|---|---|
| 个体 | 874 | 754 |
| 平均体型 | 10.00 | **11.34（+13%）** |
| 存活物种 | 48.7 | 39.3 |
| 有光占用 | 57.2% | 55.7% |
| 光合收入为主 | 45.6% | 38.2% |
| 咬活体为主 | 21.6% | 21.2% |
| 母体供养为主 | 32.6% | 40.5% |

**体型 +13%——这是"给大体型收益"这条路上最好的一次**（之前最好的
`size_advantage = 0.5` 是 +9.4%）。

机制不是"给大加成"，而是**把出生的空间代价还回去**：卵占一格、挡路，
一个全是小个体的世界会被自己的卵堵满；大个体数量少、卵也少，反而活得开。
这正是从批次 5 追到现在那堵墙的反面——`can_place_at` 要求整块空地是**反向选择**，
卵生则给"生得多"标了个价。

代价：人口 -14%、物种 -19%。所以**默认关**。

### 四、和亲缘识别的耦合

卵生**必须**配合同种相残惩罚（批次 24）才有意义：否则捕食者会先把自己的卵吃光，
"卵"就从"繁殖投资"变成"给邻居送饭"。

这也是为什么这一批排在 ④ 之后——顺序不是随意的。

## 34. 批次 28：长期稳态观察（6000 tick 的结论要打折扣）

### 一、为什么

这一批所有结论都基于 **6000 tick**。而批次 16 有过一条教训：
"短跑和长跑的符号可以相反"（整口咬合在 6000 tick 下体型反而略降，15000 tick 才翻正）。

所以跑了一组 **12000 tick、单种子（1001）**，看生态到底收敛了没有。

### 二、结果（默认配置：kin 0.5 / 冷却 10 / 无卵生 / 无昼夜 / 无洞穴）

| 指标（p = 1.0） | 6000 tick（3 种子） | **12000 tick（种子 1001）** |
|---|---|---|
| 个体 | 874 | 806 |
| 平均体型 | 10.00 | **12.14（+21%）** |
| 存活物种 | 48.7 | 47.0 |
| 有光占用 | 57.2% | **63.7%** |
| 光合收入为主 | 45.6% | 35.9% |
| 咬活体为主 | 21.6% | 26.4% |
| **纯异养（无生产者）** | ~2.4% | **10.5%** |

p = 0.5 / 0.6 这两档的变化更夸张：

| p | 6000 tick（体型 / 个体） | 12000 tick |
|---|---|---|
| 0.5 | 2.86 / 382 | **11.67 / 922** |
| 0.6 | 7.70 / 1102 | **10.88 / 982** |

### 三、三条结论

**1. 6000 tick 时生态还在过渡期，远没收敛。**
体型从 10.00 长到 12.14、占用从 57% 涨到 64%、p = 0.5 那一档从"濒死"变成"最繁荣"。
**所有基于 6000 tick 的横向对比都要打折扣**——它们量的是"过渡速度"，不完全是"稳态"。

**2. 纯捕食者终于站住了：2.4% → 10.5%。**
这是从批次 19（当时结构判据显示 0%）一路追下来的那个问题。
**真正让它站住的是这一批的四件事叠加**：一口一目标（不再是 10 倍收益）、
`bite_rate` 0.06、同种相残惩罚（不能吃自己人）、繁殖冷却（繁殖窗口变稀缺）。
单独任何一件都不够——这也是为什么它是"长跑才出现"的：捕食者的种群爬升比生产者慢。

**3. 体型还在往上漂（10 → 12.14），没有平台。**
要么是还没到稳态，要么是这套经济学本身在缓慢放大体型。
**这是下一步该盯的数**：跑 24000 / 48000 tick，看它是收敛到一个平台，还是继续涨。

### 四、功耗约束

单次 12000 tick × 5 个 p 值跑了 2 分钟（单种子）。按 MEMORY 的约束
（单次扫描 < 1 分钟、这台机器长时间满载会过热），长跑要**分多次**做，
不要一次挂 4 个并行进程。

## 35. 批次 29：三组追问实验（稳态 / 纯捕食者 / 昼夜+洞穴）

### 一、长期稳态：24000 与 48000 tick

p = 1.0，默认配置（kin 0.5 / 冷却 10 / 无卵生 / 无昼夜 / 无洞穴）：

| tick | 种子数 | 个体 | 平均体型 | 存活物种 | 有光占用 | 光合 | 咬活体 | 纯异养 |
|---|---|---|---|---|---|---|---|---|
| 6000 | 3 | 874 | 10.00 | 48.7 | 57.2% | 45.6% | 21.6% | 2.4% |
| 12000 | 1 | 806 | **12.14** | 47.0 | 63.7% | 35.9% | 26.4% | **10.5%** |
| 24000 | 3 | 852 | 10.65 | 60.0 | 58.9% | 42.2% | 25.1% | 2.3% |
| 48000 | 2 | 836 | 11.19 | **67.5** | 60.1% | 38.0% | **27.8%** | 3.9% |

**1. 12000 那一行是种子噪声，不是趋势。**
它只有 1 个种子（1001），体型 12.14 / 纯异养 10.5% 看起来像"长跑会更极端"；
但 24000 tick 换回 3 种子平均，立刻回到 10.65 / 2.3%。
**教训：单种子的长跑结果不能当趋势读**——这个模拟的种子间方差比 tick 间方差大得多。

**2. 体型确实在缓慢上移，但很慢。**
10.00 → 10.65 → 11.19，tick 每翻一倍涨 5~6%。这个斜率在下降
（6000→24000 涨 6.5%，24000→48000 只涨 5%），**像是在逼近一个 11~12 的渐近线，
而不是无界漂移**。要确认得再跑 96000，但那要 20 分钟以上，超出功耗预算。

**3. 有一个单调的方向：光合在退、捕食在进。**
光合 45.6% → 38.0%，咬 21.6% → 27.8%，纯异养 2.4% → 3.9%。
三个数都是单调的，而且是 48000 tick 里唯一稳定的方向。

**4. 物种数还在涨（48.7 → 60.0 → 67.5），没有饱和。**
多样性还在积累，说明生态还没到"生态位填满"的状态。

### 二、纯捕食者：bite_rate 不是杠杆，猎物密度才是

目标是"纯异养从 10.5% 推到 20%+"。实测（6000 tick、3 种子、p = 1.0）：

| 配置 | 纯异养 | 咬活体 | 结构异养 |
|---|---|---|---|
| 基线（bite 0.06） | 2.4% | 21.6% | 8.8% |
| bite 0.08 | 3.0% | 24.7% | 8.8% |
| bite 0.12 | **2.1%** | **35.5%** | 6.9% |
| bite 0.08 + sizeadv 0.5 + 卵生 | **0.9%** | 26.3% | 11.6% |
| 同上，跑 24000 tick | 1.3% | 30.5% | 12.8% |
| **bite 0.08 + 光合 0.3（猎物极密）** | **5.0%** | 31.3% | 17.2% |

**三条读数：**

**① `bite_rate` 不是杠杆。** 0.06 → 0.12 把"咬为主"从 21.6% 推到 35.5%，
但**纯异养反而从 2.4% 掉到 2.1%**。因为咬得越狠，**混养体（生产者 + 嘴）**赚得越多——
它既有底薪又吃红利，纯捕食者抢不过它。

**② `size_advantage` 和卵生都在压纯异养。** 前者让"小咬大"打折，
而新变异出来的捕食者一定是从小开始的；后者让卵占满空间，捕食者找不到落脚点。
**这两个机制对"体型"有利，对"纯捕食者"不利**——它们不是同一个方向的目标。

**③ 真正的杠杆是猎物密度。** 光合 0.12 → 0.3（生产者铺满），纯异养 2.4% → **5.0%**，
结构异养 8.8% → 17.2%。这是唯一一个让纯捕食者明显变多的旋钮。

**结论：20% 在现有机制下达不到。** 纯捕食者的瓶颈不是"咬得不够狠"，
而是**"找不到猎物的那些 tick 会饿死"**——它没有底薪。
要突破需要结构改动，三选一：

- **让生产者铺满**（`photo` 0.3+ 或世界更小、光更足），纯异养能到 5%，但生态会整体倒向 r 策略；
- **让「生产者 + 嘴」互斥**（一个身体不能同时有这两种细胞）——人为规则，但生态上对应
  "光合和捕食是两条不能兼得的路线"；
- **给纯异养一个补偿**（更低 upkeep / 更高容量）——最人为，也最容易调。

我倾向于第二条，但它会大幅改变现有生态，需要单独一批。

### 三、昼夜 + 洞穴：叠加不是加法

6000 tick、3 种子、p = 1.0，`day = 600` + `cave = 4`。按天空光分带：

| 天空光分带 | 无昼夜 + 洞穴 | **昼夜 + 洞穴** |
|---|---|---|
| 0–24%（洞穴 / 夜间） | 388 个体 / 8.30 格 | **154 / 10.91 格** |
| 25–49% | 686 / 5.59 | **16 / 4.11** |
| 50–74% | 837 / 9.66 | **100 / 4.33** |
| 75–99%（白天满照） | 1054 / 11.63 | 593 / 12.78 |

**中间两带被清空了**（686 → 16、837 → 100），两端保留。
这不是"两种策略共存"的分化，是**昼夜把"中等光照"压成了死区**：
那个亮度白天勉强够、夜里不够，个体在夜里饿死，而两端（白天地表 / 洞穴深处）都能活。

**暗区的体型反而涨了**（8.30 → 10.91）——因为夜里地表变差，洞穴成了避难所，
而能撑过夜的都是大体型。

**所以"时间维度 + 空间维度"的叠加没有产生新生态位，只是把环境压成了两极。**
一个反直觉的教训：**两个各自有效的机制叠加，结果可能是"中间地带消失"，而不是"两头都更丰富"。**

### 四、这一批的三个方法学结论

1. **单种子长跑 = 噪声**。种子间方差 > tick 间方差，任何长跑结论至少要 2~3 个种子。
2. **调参数前先问"它的瓶颈是什么"**。`bite_rate` 调三档都没推动纯异养，
   因为它卡在"没底薪"上，不在"咬得不狠"上。
3. **叠加实验要单独做**。昼夜单独开是"把能量集中"（体型 4.67 → 9.60），
   洞穴单独开是"物种 +30%"，两个一起开却把中间带清空了。

## 36. 批次 30：只读诊断——「生产者 + 嘴」互斥该不该做

### 一、想做的事

批次 29 的结论是"混养体（生产者 + 嘴）永远更优——它有底薪又吃红利"。
顺着这个逻辑，最直接的一招是：**让一个身体不能同时有生产者和嘴**，逼它们选边。

动手前先量了三件事（`examples/mutex_probe.rs`，只读，不写世界）：

### 二、结果（6000 tick × 3 种子，平均 421 个体/种子）

**【1】结构分类（成体）**

| 分类 | 数量 | 占比 |
|---|---|---|
| 纯光合（有生产者、无嘴） | 1 | 0.1% |
| 纯捕食（有嘴、无生产者） | 3 | 0.2% |
| **混养（两者都有）** | **1259** | **99.7%** |
| 都没有 | 0 | 0.0% |

**几乎整个世界都是混养体。** 这不是"少数派策略"，这是**唯一策略**。

**【2】混养体的收入偏向（光合收入占比）**

| 光合收入占比 | 占混养体 |
|---|---|
| 0–20%（实际是捕食者） | 7.9% |
| 20–40% | 12.6% |
| 40–60%（真两栖） | 25.0% |
| 60–80% | 29.7% |
| 80–100%（实际是光合） | 24.8% |

一半以上（54.5%）其实主要靠光合，四分之一（25%）是真两栖。

**【3】混养体的身体构成（中位数）：8 个生产者 + 5 个嘴/杀手。**
嘴占了身体的三分之一以上——**它不是"顺手带的一个器官"，是重仓投资**。

**【4】强制互斥后各走一条路，净收入保留率（中位数）**

| 路线 | 净收入保留 |
|---|---|
| 只留生产者（去掉嘴） | **0.72** |
| 只留嘴（去掉生产者） | **0.27** |
| 其中「走光合更划算」的 | **887 / 1038（85.5%）** |

**【5】纯捕食者的状态（中位数）：16 格 / 能量 0.10 / 年龄 714 tick。**
能量 0.10，容量 32——**它们长期贴在饥饿线上**。这就是"没有底薪"的直观证据。

### 三、结论：**不做**

四条理由，按重要性排：

1. **99.7% 的成体是混养体**。强制互斥等于让几乎整个世界改蓝图，不是"加一个开关"，是"换一个世界"。
2. **85.5% 会走光合路线**（走捕食只保留 27% 收入）。所以结果不是"纯捕食者变多"，
   而是**世界变得更纯光合**——和初衷完全相反。
3. **走光合后净收入只剩 72%**，会有相当一部分个体活不下去，人口会明显下降。
4. **纯捕食者能量 0.10**——它们本来就活不下去，不是"被混养体挤掉了"，是"这条路本身走不通"。

**根本原因**：嘴的**性价比**太高——它贡献了混养体约一半的收入，只占三分之一的身体。
禁止组合只会让人放弃"性价比低的那一半"，而那一半恰恰是生产者。

### 四、替代方案：给「专精」正向激励，而不是禁止组合

"互斥"是**惩罚混合**；数据说混合太划算，惩罚混合等于惩罚绝大多数个体。
更对症的是**奖励专精**：

- `predator_specialization`：身体里**没有生产者细胞**时，咬合力 × 1.5（或 upkeep × 0.8）。
- 混养体完全不受影响（它照样能活），但纯捕食者第一次有了"当专家的红利"。
- 演化上会自然分化出纯捕食者——因为**收益差**，不是因为**禁令**。

这个方案的代价小得多（不动现有生态的合法性），也符合生态学：
专精有代价（放弃了底薪），所以必须给它一个收益，否则没人专精。

**建议下一批做这个，而不是互斥。**

## 37. 批次 31：捕食专精奖励（比互斥好，但天花板在 7%）

### 一、设计

`LifeCfg::predator_specialization`（**默认 2.0**）：身体里**没有生产者细胞**时，咬合力乘这个数。

为什么不是互斥（批次 30 的诊断）：**99.7% 的成体都是混养体**，禁止混合等于换一个世界，
而且 85.5% 会走光合路线——那不是"逼出捕食者"，是"把世界压成纯光合"。

正确的做法是**给"放弃底薪"这件事一个补偿**：混养体完全不受影响（倍率 1.0），
只有纯捕食者拿到红利。分化来自**收益差**，不是**禁令**。

### 二、扫描（6000 tick、3 种子、p = 1.0）

| spec | 个体 | 体型 | 物种 | 占用 | 纯异养 | 结构异养 | 咬为主 |
|---|---|---|---|---|---|---|---|
| 1.0（基线） | 874 | 10.00 | 48.7 | 57.2% | 2.4% | 8.8% | 21.6% |
| 1.3 | 899 | 9.54 | 43.3 | 56.0% | 3.6% | 10.4% | 19.7% |
| 1.5 | 877 | 10.16 | 41.7 | 58.3% | 3.2% | 7.8% | 21.6% |
| **2.0（默认）** | 821 | 10.72 | 42.0 | 56.3% | **6.9%** | 13.0% | 25.4% |
| 3.0 | 807 | 10.51 | 43.7 | 54.6% | **6.7%** | 11.5% | 23.2% |
| **2.0 + 光合 0.3** | **1096** | **12.13** | **54.3** | **86.9%** | **8.6%** | 17.2% | 28.6% |

**三条读数：**

**① 有效，而且是真的有效。** 纯异养 2.4% → **6.9%**（2.9 倍），这是这个项目追了
十几个批次里最高的一次。而且和 `bite_rate` 不同——`bite_rate` 调三档都没用，
因为它同时喂饱了混养体；专精奖励**只给纯捕食者**，所以没被混养体截胡。

**② 天花板在 7%。** 2.0 → 3.0 纯异养从 6.9% 掉到 6.7%（饱和）。
再往上加咬合力没有意义了——**纯捕食者的瓶颈不是"咬得不狠"，是"找不到猎物的那些 tick 会饿死"**。

**③ 加猎物密度能到 8.6%，但 20% 仍然不可达。**
`spec 2.0 + 光合 0.3` 时世界挤到 86.9% 占用、体型 12.13、物种 54.3，
纯异养 8.6%——这是所有实验里最高的一次，但离 20% 还有一倍多。

### 三、为什么 20% 到不了

纯捕食者的生存条件是"**在一个 tick 里找到足够多的猎物**"，而猎物密度受两个硬约束：

1. **生产者占的空间**（光合 0.12 时约 55%，光合 0.3 时约 87%）；
2. **捕食者自己的搜索能力**（4 邻域 + 移动速度）。

咬合力再高，也只能提高"咬到之后拿多少"，不能提高"多久咬到一次"。
所以这条路的天花板是**猎物密度**，不是**咬合力**。

要真到 20%，得动"抗饿"：让纯捕食者在找不到猎物时死得慢一点
（更低 upkeep / 更大容量 / 更长饥饿宽限期）。那已经是"给纯捕食者发福利"，
比专精奖励更人为——**建议到此为止，把 6.9% 当成这套机制的现实答案。**

### 四、默认值 2.0 的理由

- 1.3 / 1.5 的效果不单调（3.6% / 3.2%），说明那两个档位落在分岔点上，不可靠；
- 2.0 是唯一让纯异养**明显跃升**的档位（2.4% → 6.9%），而且 3.0 饱和，说明 2.0 是"刚好够"的点；
- 代价可接受：人口 -6%、物种 -14%，体型 +7%。

`predator_specialization = 2.0` 意味着"同样的嘴，只因为放弃了生产者就咬得狠一倍"——
物理上有点夸张，但它是**唯一一个只奖励专精、不惩罚混养的旋钮**。

## 38. 批次 32 预备：先修尺子（47% 的「个体」是芽）

规划下一步时顺手给 `body_scan` 加了两列，结果发现**过去 27 批的横向对比都被一个口径问题污染了**。

### 一、发现

| 指标 | 旧口径（全体） | 新口径（只算成体） |
|---|---|---|
| 平均体型 | 10.72 格 | **14.28 格** |

**47.4% 的"个体"是还没长完的芽**，而芽的 `anatomy` 只有 1 格（蓝图在 `growth_plan` 里）。
于是：

- `平均体型` 被 1 格的芽稀释：真实成体是 14.28，不是 10.72；
- `结构异养%` 把「蓝图第一格是嘴的芽」算成了「纯捕食者」——13.0% 里有 5.7 个点是芽；
- `个体数` 大约是把成体数**翻了一倍**。

这也解释了批次 19 之前那个困惑（"结构判据显示 0 异养、行为判据说 76%"）和批次 30 的分歧

### 二、为什么这很严重

**芽占比不是常数**，它随参数变：出芽、卵生、`repro_cooldown`、`growth_min_ticks`、
`growth_stall_mature` 全都动它。所以只要两组的芽占比不同，「平均体型」的差就混进了
「芽的占比差」——**方向可能对，幅度不可信**。

过去那些结论里，凡是涉及"体型 +X%"的（出芽 +10%、卵生 +13%、体型压制 +9.4%、
昼夜 4.67 → 9.60），都需要在新口径下复核一遍。

### 三、已经改的（本次）

`body_scan` 的【1】加两列：**成体体型 / 芽%**；【1e】加两列：**异养(结构·成体) / 芽%**。
旧列保留，方便对照。

### 四、还没改的（批次 32 要做的）

1. **物种判据**：现在是「结构指纹哈希相等」——变异一格就是新物种。所以
   「存活物种 48.7 → 60.0 → 67.5 单调上升」量的是**结构变体的累计**，不是多样性。
   改法：加一个「身体距离 ≤ 阈值算同种」的聚类口径（或双轨：指纹管谱系、距离管物种数）。
   **顺带修好亲缘识别**——同种相残惩罚现在用指纹，母子差一格就被判成异种，
   正是文档里标了很久的「已知脆弱点」。
2. **UI 口径**：曲线窗口的"平均体型"、检视器的种群数都该标清楚是不是含芽。

## 39. 批次 32：口径校准（把尺子修好，然后三条旧结论变了）

### 一、做了什么

1. **成体口径**：`OrgStats::avg_cells_adult` / `buds_pct`，`body_scan`【1】加两列，
   曲线加两条线（成体体型 / 物种(聚类)）。
2. **物种改成连续判据**：`Anatomy::composition()`（每种细胞几个）+ `composition_distance`
   （Jaccard，`1 - Σmin/Σmax`，0~1）。`World::species_clusters(min_pop)` 按它贪心聚类。
   指纹继续管**谱系**，构成管**物种**——两个口径并存，谁也不取代谁。
3. **亲缘识别可切判据**：`kin_by_species`（默认 **false** = 旧指纹）。
   打开后按构成聚类判同种，芽按**它要长成的蓝图**算（`Organism::genome()`），
   于是母子/近亲第一次算得上亲缘。
4. **修了一个统计口径 bug**：`species.update()` 只在 `stats.interval` 的整数倍跑，
   所以 `alive_count` 可能是几十 tick 前的快照，和刚算出来的聚类数不是同一时刻的数。
   `body_scan` 现在跑完强制刷一次。

### 二、新口径下的事实

| 指标 | 旧口径 | 新口径 |
|---|---|---|
| 平均体型 | 10.72 | 成体 **14.28** |
| 结构异养（有嘴、无生产者） | 13.0% | 成体 **7.3%** |
| 物种 | 42.0（指纹） | **29.3**（聚类） |
| 芽占全体 | — | **47.4%** |

**「结构异养」里有一半是芽**（13.0% → 成体 7.3%）：芽的 `anatomy` 只有 1 格，
蓝图第一格是嘴就被算成"纯捕食者"。这解释了批次 19 之前那个"结构判据显示 0 /
行为判据说 76%"的困惑，也解释了批次 30 里 `mutex_probe`（排除芽 → 99.7% 混养）
和 `body_scan`（不排除 → 13% 结构异养）的分歧。

### 三、三条旧结论复核（6000 tick、3 种子、p = 1.0、当前默认）

| 配置 | 个体 | 平均体型 | **成体体型** | 芽% | 指纹种 | 聚类种 |
|---|---|---|---|---|---|---|
| 基线 | 821 | 10.72 | 14.28 | 47.4% | 42.0 | 29.3 |
| 昼夜 600 | 422 | 10.03 | 12.78 | 36.9% | 16.0 | 18.0 |
| **均匀变暗** `photo 0.063` | 684 | 5.97 | **7.20** | 36.1% | 27.7 | 32.7 |
| 卵生 | 727 | 11.51 | **15.77** | 50.8% | 36.0 | 28.7 |

**① 批次 22 的「昼夜不是变暗，是把能量集中」成立，而且更干净。**
成体 12.78 vs 均匀变暗 7.20——1.8 倍。旧口径（9.60 vs 4.67）是 2.06 倍，方向一致。

**② 卵生对体型有效，但幅度比原来报的小**：成体 +10.4%（旧口径 +13%）。

**③ 新发现：昼夜把捕食几乎清零。**

| | 咬活体收入 | 纯异养 | 成体结构异养 |
|---|---|---|---|
| 基线 | 25.4% | 6.9% | 7.3% |
| 昼夜 600 | **2.9%** | **0.8%** | **0.0%** |

批次 22 时没看到这条，因为那时 `kin_bite_penalty` 和 `predator_specialization`
还没成为默认。现在两个都在，昼夜一开，捕食直接消失。机制很清楚：
**夜里没有光合收入，猎物自己也在挨饿**——咬一口拿不到东西，白天又不如直接光合。
于是"夜"不是给捕食者的机会，是给捕食者的死刑。

### 四、聚类物种数不是"更少"，是"另一件事"

| 配置 | 指纹种 | 聚类种 |
|---|---|---|
| 基线 | 42.0 | **29.3**（少） |
| 昼夜 600 | 16.0 | **18.0**（多） |

聚类**不可能比指纹多**——除非一个指纹对应多种实际形态。而它确实会：
`growth_stall_mature` 让攒不够能量的芽**提前成熟**，身体只长了一部分，
但指纹还是最初那份完整蓝图。于是「同一个指纹」底下躺着大小不一的实际身体，
构成口径把它们分开。

所以两个口径量的根本不是一件事：

- **指纹 = 谱系身份**（谁从谁变来），用于化石树；
- **构成 = 当前形态**（长成什么样），用于"生态里有多少种形态在共存"。

另外 `map` 里累计有 208 个指纹，活着的只有 18 个——**6000 tick 里 190 个变体
是"出现即死"的中间态**，这也解释了物种树为什么那么碎。

### 五、`kin_by_species` 的结果和预期相反

| 指标 | 指纹判据（默认） | 聚类判据 |
|---|---|---|
| 个体 | 821 | 852 |
| 成体体型 | 14.28 | 13.73 |
| 咬活体收入 | 25.4% | **30.5%** |
| 纯异养 | 6.9% | **4.4%** |
| 混养（咬>50% 且带生产者） | 13.0% | **19.6%** |
| 聚类物种 | 29.3 | 35.0 |

**判据变粗，捕食反而变多**（25.4% → 30.5%），纯异养反而变少。
本来预期是"保护更多近亲 → 捕食变少"。这个方向没搞明白，所以：

**默认保持 `false`**（旧指纹判据，行为与批次 31 逐位相同），
`kin_by_species` 留作实验旋钮。要下结论得先弄清楚机制，不能拿一个
"方向和理论相反"的结果去改默认值。

### 六、以后报数的规矩

1. 体型一律报**成体**，并且**同时报芽%**——芽占比随参数变，不报就等于把
   "芽的多少"混进"体型的大小"。
2. 物种数说清楚是**指纹**还是**聚类**；只报一个数的时候用聚类。
3. 长跑结论至少 2~3 个种子（批次 29 的教训）。

## 40. 批次 33：大脑消融（结论：它是装饰品，但不是因为网络太弱）

### 一、为什么要做

40 维感知 → 12 隐藏 → 5 输出（4 方向 + 转身），`argmax` 选方向。**从批次 1 到 32
从来没有做过对照实验**：所有生态结论都能由身体蓝图 + 能量经济学解释完，
没有一条能证明"大脑有用"。这是全项目唯一一个从没被验证过的大件。

`LifeCfg::brain_ablation`：`0` 正常 / `1` 恒直走（输出清零）/ `2` 每 tick 伪随机方向。
两种消融都**不消耗世界 RNG**（模式 2 用 `id + age` 的哈希），所以对照组的随机流一致，
差异只来自"决策"本身。

### 二、结果（6000 tick、3 种子、p = 1.0）

| 模式 | 个体 | 成体体型 | 存活种 | 有光占用 | 异养(结构) | **移动%** |
|---|---|---|---|---|---|---|
| 0 正常 | 821 | 14.28 | 42.0 | 56.3% | 13.0% | **0.1** |
| 1 恒直走 | 831 | 14.56 | 45.0 | 58.4% | 10.9% | **0.3** |
| 2 随机走 | 795 | 15.57 | 38.0 | 57.8% | 9.0% | **0.1** |

**三种模式的差别都在种子噪声范围内**（个体 ±4%、成体体型 ±9%，而种子间方差本来就这么大）。

### 三、根因：只有 0.1% 的个体有运动细胞

`移动%` 这一列是这一批最重要的数：**一千个个体里只有约 1 个带运动细胞**。
而大脑唯一的输出就是"往哪走"——没有运动细胞，`think()` 在 `if !has_mover { return; }`
就返回了，大脑算出来的东西没人用。

所以结论不是"12 个隐藏神经元不够用"，而是：

> **这个世界的移动没有收益。** 光不随时间变（昼夜默认关）、食物不耗竭、
> 生产者站着就能挣钱、捕食是四邻域咬——站着不动几乎总是最优。

这同时解释了另一桩悬案：**眼睛一直稀有**（批次 15 就在问）。没有移动，感知距离就没有价值。

### 四、所以"大脑 v2"是白费力气

给大脑更多输入维度（嗅觉 / 记忆 / 食物梯度）、更深网络、NEAT 拓扑——
在"移动无收益"的前提下全都没用，因为没有东西可学。

**要动的是移动的收益，不是大脑的容量。**

### 五、顺带修的一个坑

第一版把消融写在 `World::think_organism` 里，结果三种模式**逐位相同**——
因为 `step()` 走的是 `think_all`（rayon 并行，直接调 `o.think`），
那个包装函数根本不会被调用。消融必须放在 `Organism::think` 内部。

## 41. 批次 34：捕食者抗饿（小效应，非单调）

### 一、动机

批次 31 把纯异养推到 6.9% 后**饱和**（spec 2.0 → 3.0 反而掉到 6.7%）：
瓶颈是"找不到猎物的那些 tick 会饿死"，不是"咬得不狠"。
而捕食者本来就比光合生物抗饿——这是**生理差异**，不是凭空发钱。

`LifeCfg::predator_starve_mult`（默认 `1.0` = 关）：没有生产者细胞的个体，
饥饿致死的宽限期 × 这个数（默认 60 tick，×3 = 180）。

### 二、扫描（6000 tick、3 种子、p = 1.0）

| 倍率 | 个体 | 成体体型 | 纯异养 | 成体结构异养 | 咬活体 |
|---|---|---|---|---|---|
| 1.0（默认） | 821 | 14.28 | **6.9%** | 7.3% | 25.4% |
| 2.0 | 809 | 14.30 | **4.8%** | 4.5% | 23.2% |
| **3.0** | 801 | 14.69 | **8.6%** | 10.0% | 24.5% |
| 4.0 | 873 | 14.20 | **4.4%** | 4.6% | 22.9% |

**非单调**：2.0 和 4.0 都比基线低，只有 3.0 冒头。老规律——系统坐在分岔点上。

### 三、5 种子复核：效应真实但小得多

3 种子的 8.6% 被高估了：

| 倍率 | 纯异养 | 成体结构异养 | 咬活体 | 芽% |
|---|---|---|---|---|
| 1.0 | **6.2%** | 6.7% | 24.5% | 47.1% |
| 3.0 | **7.5%** | 8.0% | 25.0% | 48.2% |

**+1.3 个百分点**，方向对，但远不是"把纯捕食者推到 10%+"。而 3 种子那一档显示 +1.7pp
（6.9 → 8.6），说明**小效应必须 5 种子才看得准**。

### 四、默认值

**默认 `1.0`（关）**。理由：效应小（+1.3pp）、剂量响应非单调（2.0/4.0 反而降），
不值得写进基线。想要多一点捕食者就开到 3.0，并接受这个数本身有 ±1pp 的抖动。

### 五、这一批的总账

三个方向（咬合力、亲缘、抗饿）都试过了，纯异养的天花板就在 **7~8%**：

| 杠杆 | 最好结果 | 结论 |
|---|---|---|
| `bite_rate` 0.06 → 0.12 | 纯异养 2.4% → 2.1%（反而降） | 不是杠杆，喂饱的是混养体 |
| `predator_specialization` 2.0 | 2.4% → **6.9%** | 有效，天花板 7% |
| `predator_starve_mult` 3.0 | 6.2% → **7.5%**（5 种子） | 小效应 |
| 猎物密度 `photo 0.3` | → **8.6%** | 唯一更大的杠杆，但改变整个世界 |

**"纯捕食者占 20%"这个目标可以正式放弃了**——在这个模型里，捕食者的瓶颈是
"猎物密度 × 搜索能力"，而搜索能力受"移动无收益"限制（批次 33）。
不先解决移动，所有捕食相关的旋钮都只是在 7% 附近打转。

## 42. 批次 35：地力耗竭（移动第一次有收益）

### 一、先做了一个"单开关"对照

批次 33 的结论是「移动没有收益」，而配置里有一条老规则：**有运动细胞就完全不能光合**
（`movers_can_produce = false`）。世界被切成两半：**光合不能动，能动不能光合**。

先只放开这条规则（不加任何新机制）：

| 配置 | 个体 | 成体体型 | 聚类种 | **移动%** |
|---|---|---|---|---|
| 基线 | 821 | 14.28 | 29.3 | **0.1** |
| `produce`（能动也能光合） | 895 | 13.13 | 37.3 | **0.1** |

**移动细胞一个没多。** 所以那条规则不是约束——**"没有理由动"才是**。
光在哪都一样（默认无昼夜）、食物不耗竭、生产者站着就能挣钱。能动也没用。

### 二、实现：每格一个"地力"

- `World::soil: Vec<u8>`（0~255），新世界全是 255。
- 光合细胞每 tick 从**脚下那一格**抽 `soil_deplete` 点，产出乘
  `floor + (1-floor) × soil/255`。
- 全图每 tick 回 `soil_recover` 点（`apply_soil_recover`，关掉时连循环都不跑）。
- 三个旋钮：`soil_deplete`（默认 **0 = 关**）、`soil_recover`（1）、`soil_floor`（0.25）。

`soil_floor` 不能是 0——同 `night_floor` 的教训：全枯会让"停在原地"等于必死，生态当场崩。

### 三、扫描（6000 tick、3 种子、p = 1.0）

| 配置 | 个体 | 成体体型 | 占用 | 异养 | **移动%** | 地力% |
|---|---|---|---|---|---|---|
| 基线 | 821 | 14.28 | 56.3% | 13.0 | 0.1 | 100 |
| `soil=1` + `produce` | 895 | 13.13 | 59.1% | 12.6 | 0.1 | **100.0** |
| `soil=2`（不能运动光合） | 336 | 17.01 | 29.5% | 3.7 | 0.1 | — |
| **`soil=2` + `produce`** | 413 | **17.41** | 36.8% | 4.1 | **17.3** | 88.1 |
| `soil=8` | **0（灭绝）** | — | — | — | — | — |

三条读数：

1. **`soil=1` 完全无效**：消耗 1、恢复 1 → 净零，地力恒 100%。**deplete 必须严格大于 recover**
   才有梯度。这是个容易踩的坑。
2. **`soil=8` 直接把世界打死**：一块生地 32 tick 见底，全图很快压到 floor，产出只剩 25%，
   饿死到 0。所以安全区在 2~4。
3. **`soil=2` + `produce` 才出现移动（17.3%）**，而且**成体体型 +22%**（14.28 → 17.41）。
   两个开关缺一个都不行：没有地力 → 没理由动；不能运动光合 → 动了也没用。

### 四、意外：**随机乱走比演化出来的大脑更好**

`soil=2 + produce` 下做批次 33 的消融（3 种子）：

| 大脑 | 个体 | 成体体型 | **移动%** |
|---|---|---|---|
| 正常 | 413 | 17.41 | 17.3 |
| **每 tick 随机方向** | **578（+40%）** | 16.44 | **63.2** |

**随机走比演化走多活 40%。** 这不是"大脑不好"，而是**大脑看不见地力**——
40 维输入里根本没有"这块地被我吃瘦了"这个通道。它没法学一个它看不见的东西，
于是策略退化成"按当前朝向乱撞"，而随机方向至少覆盖了新地。

所以这一批的直接产物不是"移动有收益了"这么简单，而是：
**感知通道缺了，行为就学不出来。**

## 43. 批次 36：把一维"死信息"换成地力感知

### 一、改动

`SENSE_DIM = 40` 里 `[38]` 原本是**「会移动」**。但 `think()` 对没有运动细胞的个体
**直接返回**，所以这一位在任何真正用到它的个体身上**恒为 1.0**——一维死信息。

把 `[38]` 换成**脚下地力**（0~1）：

- **维度不变**、大脑形状不变、旧存档不会错位；
- 地力关闭时传 1.0，**逐位等于旧行为**（连随机流都不动）；
- `think()` 多一个 `soil` 参数，`think_all` 里按 `grid.index(col,row)` 取。

### 二、结果（6000 tick、3 种子、p = 1.0、`soil=2 produce`）

| 大脑 | 个体 | 成体体型 | 聚类种 | **移动%** | 地力% |
|---|---|---|---|---|---|
| 正常（看得见地力） | 448 | **17.65** | 14.7 | 26.4 | 87.9 |
| 恒直走 | **528** | 14.41 | 23.3 | 29.8 | 88.0 |
| 每 tick 随机 | **578** | 16.44 | 16.3 | **63.2** | 85.3 |

给了地力通道之后，正常大脑确实变好了（413 → 448、移动 17.3% → 26.4%），
但**还是打不过"恒直走"和"随机走"**。

### 三、为什么"无脑"更好：直线走自带隐式记忆

- **恒直走**：不需要感知。只要保持方向，就**自动保证**一直进入没吃过的新格子——
  "别回头"这条策略被编码在**运动本身**里，不需要大脑知道任何事。
- **随机走**：不回头（概率上），也能不断覆盖新地。
- **12 隐藏单元 + 40 维当前格感知**：每 tick 只看脚下这一格，**没有记忆**，
  所以它分不清"我在新地方"和"我在原地打转"。它最多学到"地力低 → 换个方向"，
  而那和随机走没有本质区别。

**结论：感知不够，还需要记忆。** 这是这一批真正的产出。

### 四、下一步（批次 37）

要让大脑真的学会觅食，至少缺一样：

1. **记忆通道**：把"上一次产出 / 在这格待了多久"喂进去（现在 40 维里没有），
   或者让 `[38]` 换成"停留时长"而不是瞬时地力；
2. **循环连接**：让隐藏层带一点上一 tick 的状态（RNN 味），这样"我刚从哪来"能被记住；
3. **可变拓扑**（NEAT）：让网络自己长连接——但前提是先有 1 或 2，否则只是更贵的装饰。

我倾向于 **2（循环连接）**：它一次解决"记忆"这件事，且不需要新的感知维度，
判据也清楚——**如果加了循环之后"正常"能打赢"恒直走"，大脑就第一次真的有用**。

## 44. 批次 37：循环连接（结论：不是解药，而且这批把尺子的问题暴露干净了）

### 一、实现

`BrainCfg::recurrent`（默认 **false**）+ `recurrent_scale`（0.3）。打开后隐藏层多一项
`Σ w_rec[j][k] · hidden_prev[k]`——上一 tick 的隐藏层参与这一 tick 的计算。

三个必须守住的边界：

1. **关掉时 `w_rec` 是空 `Vec`**：`forward` 走旧路径、`randomize` 也不碰随机流，
   所以 `tests/golden.rs` 的逐位比对完全不受影响。
2. **`copy_from` 要连 `w_rec` 一起抄**：不然出芽时芽的大脑会"断片"（权重是新的、记忆是旧的）。
3. **变异要覆盖第 5 组权重**：`mutate_brain` 原来只循环 4 组（w1/b1/w2/b2），
   漏掉 `w_rec` 的话循环权重从出生到死都不会变——那就不是"可演化"，是"随机常数"。

### 二、结果（6000 tick、3 种子、`soil=2 produce`）

| 大脑 | 个体 | 成体体型 | **移动%** |
|---|---|---|---|
| 正常（无循环） | 448 | 17.65 | 26.4 |
| **正常（有循环）** | 414 | 15.76 | **9.0** |
| 恒直走（无循环） | 528 | 14.41 | 29.8 |
| 恒直走（有循环） | 463 | 15.93 | 24.9 |
| 随机（无循环） | 578 | 16.44 | 63.2 |
| 随机（有循环） | 379 | 17.08 | 26.9 |

5 种子复核（正常，`soil=2 produce`）：**无循环 502 个体 / 移动 24.8%，有循环 451 / 13.3%**。

**两批种子方向一致：循环连接没有帮助，反而让移动率掉了一半（26.4 → 9.0、24.8 → 13.3）。**

### 三、但这批真正的产出是：**测量分辨率不够**

上面那张表里有一行是"对照组中的对照组"——**随机走**。它完全不经过大脑
（方向由 `id+age` 的哈希决定），所以有没有循环对它**策略上毫无影响**。可是：

| 随机走（同策略，只换随机流） | 个体 | 移动% |
|---|---|---|
| 种子 1001/777/4242 | 578 | 63.2 |
| 种子 555/8888/13 | 568 | 72.0 |
| 种子 99/1234/7777 | 615 | 55.0 |
| 带循环（多消耗 144 个高斯数/大脑 → 流整体错位） | **379** | 26.9 |

**同一个策略，3 种子的人口可以给 379~615（±30%）、移动率 27~72%。**

所以：

- 批次 36 那句"**随机乱走比演化大脑多活 40%**"**站不住**，应该降级为"**量不出来**"；
- 同理"恒直走（528）> 正常（448）"也不成立——差 18% 落在噪声里；
- 唯一稳固的是**结构性效应**：移动 0.1% → 17~27%（地力 + 运动光合），以及 `soil=8` 灭绝。

### 四、所以：记忆**先不做**

不是因为"记忆一定没用"，而是**现在的实验量不出它有没有用**。
再加一个记忆通道，结果仍然是"两次跑出 400 和 600，不知道算不算变好"。

要动记忆之前，得先把测量换掉：

1. **别用种群当判据**。种群是二阶量（繁殖 × 死亡 × 空间竞争的乘积），噪声被放大两次。
2. **改测个体的一阶量**：移动者的**净能量收入 / 平均寿命 / 单位时间吃到的地力**。
   400 个个体 × 6000 tick 会把个体级噪声平均掉，而种群数只有 3 个样本。
3. **配对种子**：同一批种子跑两个配置（现在 rec 会改变随机流，等于换了世界），
   否则连"同策略"的对照都做不干净。

### 五、一个副产品

`recurrent` 的实现本身是干净的（默认关、逐位兼容、变异覆盖、copy 覆盖），
留在 UI 上随时可复验。它的价值不在"提升"，而在**证明"加记忆"这条路在没有
好的测量之前是盲飞**。

## 45. 批次 38：移动者专项指标（换尺子，然后结论翻过来了）

### 一、为什么换尺子

批次 37 的教训：**种群是二阶量**（繁殖 × 死亡 × 空间竞争的乘积），3 种子的噪声能到 ±30%。
在那个分辨率下，"记忆有没有用""直线走是不是更好"全都量不出来。

所以这一批不加任何机制，只加**一阶量**——每个个体自己的账：

| 指标 | 定义 |
|---|---|
| 移动·收入/tick | `(gain_photo + gain_food + gain_bite + gain_gift) / age` |
| 移动·寿命 | 死者年龄的平均（`World::mover_deaths` 累计，`kill_organism` 里登记） |
| 移动·地力% | 移动者脚下那一格的平均地力 |

`OrgStats` 里按 `Flags::MOVER` 分成两组，`body_scan` 新加【1f】一节；
另外把**每个种子的原始值**摊开打印（【噪声】一节），判断差异前先看这个。

**收入用「累计 ÷ 年龄」而不是累计值**：累计值随年龄增长，那比的是"谁活得久"，
不是"谁挣得多"。

### 二、结果（6000 tick、3 种子、`soil=2 produce`）

| 策略 | 移动数 | 移动% | 移动·年龄 | **移动·收入/tick** | 移动·地力% | 静止·收入/tick |
|---|---|---|---|---|---|---|
| **正常（演化大脑）** | 117 | 26.0% | 184 | **0.2959** | 88.3 | 0.2634 |
| 正常 + 循环 | 39 | 9.5% | 378 | **0.3118** | 65.9 | 0.2614 |
| 恒直走 | 162 | 30.8% | 134 | **0.1527** | 58.7 | 0.2373 |
| 每 tick 随机 | 355 | 61.4% | 324 | **0.2236** | 66.3 | 0.2474 |

每个种子的移动者收入（中位数更可靠）：

| 策略 | 种子 1 | 种子 2 | 种子 3 | 中位数 |
|---|---|---|---|---|
| 正常 | 0.2700 | 0.2845 | 0.3333 | **0.2845** |
| 正常 + 循环 | 0.2522 | 0.2934 | 0.3898 | 0.2934 |
| 恒直走 | **0.0000** | 0.1755 | 0.2826 | **0.1755** |
| 随机 | 0.1769 | 0.2417 | 0.2521 | 0.2417 |

### 三、三条结论

**① 一阶量把信号救回来了：大脑第一次真的有优势。**

中位数 0.2845（正常） vs 0.1755（恒直走）——**+62%**。而且四个策略的收入分布在
个体级别上是稳的：正常三个种子都落在 0.27~0.33，恒直走只有一个种子进了这个区间。

**② 批次 36 那个"随机走比大脑好"的结论，正式作废。**

随机 0.2417 < 正常 0.2845。当时用种群量出来的"578 vs 448"纯粹是二阶噪声。

**③ 恒直走最差，而且有一个种子的移动者全军覆没。**

0.0000 那格不是"收入为零"，是**那个种子里没有活着的移动者**——
直线走会一头撞进墙/边界然后卡死。这解释了它移动% 高（30.8%）但收入低。

### 四、循环连接：仍然量不出来

正常 0.2845 vs 带循环 0.2934（中位数）——差 3%，落在重叠区间里。
但**移动% 从 26.0% 掉到 9.5%**，移动·年龄从 184 涨到 378。

也就是说：**记忆让个体更"宅"了（动得更少、活得更久），但单位时间收入没变。**
一个可能的解释：有了记忆之后，网络学会了"待在一个还行的格子上"，而不是到处找。
这不一定是坏事（活得更久），但也说明它没学会"觅食"这件事。

### 五、下一步

- **判据已经换好了**，以后所有关于"行为/大脑"的实验都该看【1f】，不看种群。
- 循环连接是否保留：`recurrent` 默认仍是 `false`（移动率掉一半、收入没变）。
- 真正还没解决的是：**移动者收入只比静止者高 12%**（0.2959 vs 0.2634）。
  移动的收益仍然很小——地力已经把它从 0 抬到 +12%，要更大就得让"生地"和"熟地"
  的差距更狠（`soil_floor` 更低 / `soil_recover` 更慢），或者让静止真的付代价（遮挡已经有一点）。

### 六、补测：把「寿命」修好之后，故事又变了一层

第一版测量里 `移动·寿命` 全是 0——因为死亡登记被写进了画笔的 `erase_creature_at`，
而不是 `kill_organism`。修掉之后（抽成 `note_death`，两个入口都调）重测：

| 策略 | 移动% | 移动·收入/tick | 移动·寿命 | 收入 × 寿命 |
|---|---|---|---|---|
| **正常（演化大脑）** | 26.0% | **0.2959** | 252 | ≈75 |
| 恒直走 | 30.8% | **0.1527** | 272 | ≈42 |
| 每 tick 随机 | 61.4% | 0.2236 | **373** | ≈83 |
| 静止者（同世界对照） | — | 0.2634 | **300** | ≈79 |

**① 大脑确实赢了「恒直走」，而且这次不是噪声。**

收入 0.2959 vs 0.1527——差**近一倍**，而同一策略跨种子的变异只有 ±10%
（0.27/0.28/0.33）。这是整个项目里第一次能说"大脑有用"。

**② 但移动 vs 静止：基本打平。**

移动者收入高 **12%**（0.2959 vs 0.2634），寿命短 **16%**（252 vs 300）。
按「收入 × 寿命」算，75 vs 79——**移动的收益正好被短命抵掉**。

这才是移动细胞只有 26% 的真正原因：**不是大脑不会觅食，是觅食这件事本身不划算。**
大脑能做的只是"把一件不划算的事做得比乱走好"。

**③ 收入榜和寿命榜是反的，这是个真实的 r/K 权衡。**

随机走收入最低之一、寿命最长；正常收入最高、寿命最短。高收入 → 攒得快 → 繁殖早 → 死得早。
所以**任何单一指标都会误导**：只报收入会高估"快策略"，只报寿命会高估"宅策略"。
以后报一阶量必须**两个一起报**。

**④ 顺带一个教训**：`移动·寿命` 全 0 这件事如果没被看出来，这一整节的分析都是错的。
所以**新指标第一次上线时，必须检查它有没有在动**（打印、断言、或者看它是不是恒为某个值）。

## 46. 批次 39：调地力梯度（结论：1.5x 达不到，天花板 1.23x，而且原因是算术）

### 一、目标

批次 38 定位到：移动的收益（+12%）刚好被寿命代价（-16%）抵掉。
当时的判断是"梯度不够狠"——`移动·地力%` 有 88%，说明大部分格子根本不枯。

所以这一批只调旋钮，判据是【1f】新加的一列 **`移动/静止` 收入比**：
1.0 = 打平，> 1.5 才算"移动真的值"。

### 二、扫描（6000 tick、3 种子、`produce`）

| 配置 | 个体 | 成体体型 | 移动% | 移动·收入 | 移动·地力% | 静止·收入 | **移动/静止** | 全图地力% |
|---|---|---|---|---|---|---|---|---|
| `soil=2`（38 的基线） | 448 | 17.65 | 26.4% | 0.2959 | 88.3 | 0.2634 | **1.12x** | 87.9 |
| **`soil=3`** | 394 | 17.76 | **40.5%** | 0.3076 | 77.3 | 0.2494 | **1.23x** | 85.7 |
| `soil=4` | 328 | 17.68 | 40.4% | 0.1557 | **28.2** | 0.2414 | **0.64x** | 81.9 |
| `soil=4 soilf=0.10` | 98 | **6.62** | 23.8% | 0.0842 | 11.2 | 0.0820 | 1.03x | 91.7 |
| `soil=4 soilf=0.10 soilr=0` | **0（灭绝）** | — | — | — | — | — | — | — |

### 三、三条读数

**① `soil=3` 是甜点：比值 1.23x、移动率 40.5%、人口只掉 12%。**
比基线好，但离 1.5 还差一截。

**② `soil=4` 是个陷阱：地力确实枯了（移动·地力 88 → 28%），但收入反而崩了。**
因为地力枯的不是"别人脚下"，是**整张图**——枯了之后谁都挣不到钱，
移动者跑去的地方也是枯的。所以比值掉到 0.64x。
**"让地力枯"和"制造梯度"不是一回事**：梯度要求"有的地方枯、有的地方肥"，
而现在恢复是全图均匀的，所以全图一起枯。

**③ 再往下调（`floor=0.10`）生态直接崩**：成体体型 6.62、个体 98。
`recover=0` 则灭绝。地力这条路的安全边界就是 `soil=3`。

### 四、为什么 1.5x 达不到：这是一道算术题

移动细胞**占一个身体格**。一个 N 格的身体，把一格从生产者换成 mover，
产能少了 `1/N`。所以**盈亏平衡的收入比大约是 `N/(N-1)`**：

- 成体 17.7 格 → 平衡点 **1.06**；
- 实测 1.12（soil=2）= 比平衡高 **6%**；
- 实测 1.23（soil=3）= 比平衡高 **16%**。

也就是说：**土壤梯度能给的增益，大部分被"mover 占一格"的成本吃掉了。**
这不是参数没调好，是结构决定的。要把比值推到 1.5，得让 mover 不占"纯成本"：

- **方案 A：mover 也能光合（打折）**——等于给移动打补贴，但会把"站桩"的绝对优势削弱；
- **方案 B：转身不需要 mover**——转身不改身体格数，只改**占用哪些世界格**。
  如果允许无 mover 的个体转身，那"原地旋转换地"就是**免费的移动**，
  这才是绕开那道算术题的路（现在 `act_move` 被 MOVER 挡住，无 mover 连转身都做不了）。

我倾向 **B**：它不需要新的成本项，而且它把"转身"这个已经被大脑控制（`out[4]`）、
但**从来没被真正用起来**的输出接上了——`think()` 对无 mover 直接 `return`，
所以 73% 的个体的大脑现在完全空转。

## 47. 批次 40：无 mover 也能转身（找到了那道算术题的绕法——但绕过头了）

### 一、动机

批次 39 卡在一道算术题上：**mover 占一个身体格**，所以移动的盈亏平衡收入比
大约是 `N/(N-1)`（成体 17.7 格 → 1.06）。实测天花板 1.23x，再推地力就把世界打死。

但**转身不改身体格数**——`attempt_rotate` 只是 `clear_grid` + `write_grid`，
生产者的相对坐标被旋转，落到的**世界格**变了。所以：

> 允许无 mover 转身 = **免费换一块地吃**。

`LifeCfg::rotate_without_mover`（默认 **false**）。两处改动：
`think()` 里 `if !has_mover` 的提前返回改成"除非开了这个开关"；
`act_organism_inner` 里无 mover 时走 `act_rotate_only`（只转身，并自己递减 `turn_cooldown`
——那个递减本来在 `act_move` 里做，不补的话一辈子只能转一次）。

### 二、结果（6000 tick、3 种子、`produce`）

| 配置 | 个体 | 成体体型 | 移动% | 移动·收入 | 静止·收入 | **移动/静止** |
|---|---|---|---|---|---|---|
| `soil=2` | 448 | 17.65 | 26.4% | 0.2959 | 0.2634 | **1.12x** |
| **`soil=2` + rot** | **580** | 13.61 | **13.6%** | 0.2036 | 0.2032 | **1.00x** |
| `soil=3` | 394 | 17.76 | 40.5% | 0.3076 | 0.2494 | **1.23x** |
| **`soil=3` + rot** | **560** | 11.94 | 15.0% | 0.1451 | 0.1779 | **0.82x** |
| `soil=4` | 328 | 17.68 | 40.4% | 0.1557 | 0.2414 | **0.64x** |
| **`soil=4` + rot** | 495 | 9.98 | 14.6% | 0.1671 | 0.1666 | **1.00x** |

### 三、三条读数

**① 转身一开，移动者的优势被彻底抹平：1.12x → 1.00x、1.23x → 0.82x。**

因为静止者现在也能换地了。mover 从 26~40% 掉到 14~15%——**留着 mover 纯亏一格产能**。

**② 人口 +29~51%，成体体型 -25~44%。**

人人能换地 → 世界更"富" → 更多小个体活得下去（r 策略化）。这是**机制有效**的证据：
换地真的能换到更多能量。

**③ 这一条把批次 33 的悬案解释掉了。**

批次 33 量到移动细胞只占 **0.1%**，当时的结论是"移动没有收益"。
现在看更准确的说法是：

> **有更便宜的换地办法（转身），只是之前被规则挡住了。**

同理也解释了**眼睛一直稀有、大脑一直装饰**：这个模型里最划算的策略是
**站桩 + 偶尔转身**——它只需要一个输出位（`out[4]`），不需要任何感知。

### 四、所以：`rotate_without_mover` 默认关

它改变的是整个生态形状（人口 +30~50%、体型 -30%），按项目惯例默认关、留作旋钮。
但它揭示的结构问题是真的：

**「转身」是这个模型里隐藏的免费移动，它支配了「长一个 mover」。**

要让它不支配，就得给转身定价——这就是下一批。

## 48. 转身到底是什么（附：为什么**不加**转身费）

### 一、转身是纯旋转，不是镜像

`rotate_col` / `rotate_row` 是 90° 整数倍的旋转：

| rotation | (dx, dy) → | 行列式 |
|---|---|---|
| 0 | `( dx,  dy)` | +1 |
| 1 | `(-dy,  dx)` | +1 |
| 2 | `(-dx, -dy)` | +1 |
| 3 | `( dy, -dx)` | +1 |

**四个都是正常旋转（行列式恒为 +1），没有一个是镜像**——镜像的行列式是 -1。
所以身体的手性（左右不对称）在转身之后保持不变，不会出现"翻个面"这种事。

**但"转一次"不等于"转 90°"**：`attempt_rotate` 是 `rng.int(4)`，也就是**随机换一个朝向**——
可能是 0°（等于没动）、90°、180°、270°。其中 180° 是最"猛"的换地（身体前后对调），
0° 是**空转**（白付一次 `turn_cooldown`）。

> 顺带一个可能的后续：转到 0° 时不该消耗冷却。现在会消耗，等于每四次转身有一次白付。
> 这属于"转身的效率"问题，和"转身该不该收费"是两件事。

### 二、不加 `turn_cost`：mover 已经付过账了

这一条是**结构决定的**：mover 占一个身体格，等于永久放弃了那一格的产能（`1/N`）。
再加一笔"每次转身付能量"，就是**对同一笔成本收两次**——而且第二次是流量（每次转都付），
第一次是存量（永久少一格）。

数据也支持这个判断（`soil=3 produce`，也就是「有 mover 才能转身」这条基线）：

| tick | 个体 | 成体体型 | 移动% | 移动·收入 | 静止·收入 | **移动/静止** |
|---|---|---|---|---|---|---|
| 6000 | 394 | 17.76 | 40.5% | 0.3076 | 0.2494 | **1.23x** |
| **12000** | 449 | 13.68 | **50.8%** | 0.2437 | 0.2282 | **1.07x** |

**这张表是这一轮最重要的结果**：

- mover 比例从 **0.1%（无地力）→ 40.5%（6000 tick）→ 50.8%（12000 tick）**，一路涨；
- 而收入比从 **1.23x 一路降到 1.07x**，正好落在理论平衡点 `N/(N-1) ≈ 1.06` 附近。

**这就是演化该有的样子：把有利可图的策略用光，直到利润归零。**
mover 现在既不是"没人要"，也不是"白送"——它**恰好挣到自己那一格的成本**。

如果这时候加一笔转身费，平衡点会被推高，mover 会重新变得不划算、再次消失。
**所以不加。** 规则保持现状：

> **有 mover 才能转身（`rotate_without_mover = false`），转身不额外消耗能量。**

### 三、`rotate_without_mover` 留着，但只是诊断开关

它的价值不是"拿来用"，而是**证明转身是隐藏的免费午餐**（批次 40）：
一开，比值就从 1.23x 抹到 1.00x，mover 从 40% 掉到 15%。
留着它，以后谁再问"为什么大家不长 mover"，可以直接跑一次对照。

12000 tick 下这个对照更清楚：

| 配置（12000 tick） | 个体 | 成体体型 | 移动% | 移动/静止 |
|---|---|---|---|---|
| `soil=3 produce`（有 mover 才能转） | 449 | 13.68 | **50.8%** | 1.07x |
| `soil=3 produce rot`（谁都能转） | **628** | **9.43** | 26.2% | 1.01x |

免费转身 → 人口 +40%、成体体型 -31%、mover 腰斩、收益比归零。
**"免费"换来的不是效率，是 r 策略化。**

## 49. 「转到 0°」该不该退冷却？（结论：**不改**，而且这个类比不成立）

### 一、先把两件事分开

| 情形 | 这一次**动作**做了什么 | 净位移 |
|---|---|---|
| 抽到当前朝向（0°） | **什么都没做** | 0 |
| 顺转一次 + 逆转一次 | **两次都做了事** | 0 |

`turn_cooldown` 是**按动作**计费，不是按**净位移**计费。所以：

- 「这次动作没做任何事」是可以谈的（动作定义有问题）；
- 「两次真动作加起来等于零」不可以谈——要退就得追溯，
  而任何一串动作的净位移都可能是零（顺+逆、90+270、180+180…）。
  按净位移计费的话，连「走两步又走回来」都该退移动冷却——那就没有"动作"这个概念了。

**所以「顺转再逆转」不构成「0° 空转」的反例。** 它们不是同一层的东西。

### 二、但那个「退冷却」的说法确实是补丁，不是原理

更干净的表述不是退款，而是**把动作定义改掉**：

> 转身 = 「**换**一个朝向」。所以采样应该从**另外三个**朝向里抽
> （重掷到不等于当前为止），而不是从四个里抽。

这样「空转」在**定义上**就不存在，也就不需要任何退款规则。
退款是事后打补丁，重定义是事前把动作说清楚——后者才是原理。

### 三、但结论是：不改

三条理由：

1. **25% 的空转是个均匀税，不扭曲选择。** `rng.int(4)` 均匀，1/4 撞上当前朝向，
   对**所有**个体一视同仁。它降低的是"转身的有效速率"（75%），不是"某些个体吃亏"。
   **均匀的税只影响绝对效率，不影响谁被选中**——所以它不是选择压问题。

2. **现在的平衡点是在这个 75% 效率下标定的。** mover 50.8%、收益比 1.07x ≈ 理论 1.06
   （批次 41）。改了就要重跑 12000 tick 重新标定，而结果大概率只是
   "有效转身率 +33% → 世界更富一点、体型再小一点"（对照批次 40：免费转身让体型掉 31%）。

3. **它甚至不算失真，反而更像真实。** 大脑**感知不到自己的朝向**
   （40 维里没有 rotation，视觉是自我中心的），所以它无法"故意避免空转"。
   一个想转身的个体只能瞎撞——**这正是"运动噪声"的忠实模型**。

### 四、什么情况下才值得回头看

只有一种：**把转身改成"定向"**——`out[4]` 变成"顺时针 90°"，或者再拆一个 `out[5]` 出来
（CW / CCW 两个输出）。那时"0° 空转"在定义上消失，而且顺便给大脑一个
**更可控的动作**（它现在只能在 5 个动作里瞎选）。

那是一次真正的动作空间改动，不是数值微调。**单独一批做，别混进调参里。**

## 50. 批次 43：地形补齐——水 / 冰 / 洞穴「重挖」

### 一、先澄清一件"看起来没实装"的事

问的是"腐殖质洞穴那些地形改造怎么没实装"。实际上**大部分早就实装了**：

| 已实装 | 位置 | 默认 |
|---|---|---|
| 岩浆 / 沼泽 / 辐射带 / 腐殖质 + `onEnter` / `onStand` 钩子 | 阶段 8（2026-10-16） | 有笔刷，可画 |
| 洞穴预设（墙做顶 + 腐殖质做底 + 竖井通地表） | 批次 25 `cave_count` | `0`（关） |
| 储食 / 再生 / 刺 | 阶段 9 | 有笔刷 |

**真正没做的是 §15.3 剩下的那几个**：水 / 冰 / 岩石 / 传送门 / 光源，以及生态位地图 UI。

而"看起来没实装"有两个真实原因，都不是"忘了写"：

1. **`cave_count` 只在生成世界时生效**，UI 里没有"重挖"入口——拖动滑块什么都不发生，
   除非你手动新建一个世界。**一个拖了没反应的旋钮，等于没实装。**
2. 水 / 冰 确实没做。

### 二、这一批做了什么

**① 水 `WATER`（id 17）**：`EnterFx::Slow`，踏入多耗 `water_move_cost`（默认 **0.15**）。

和沼泽的分工是量级上的：沼泽 **0.5**（"陷进去"）、水 **0.15**（"阻力"）。
所以两者生态作用完全不同——**沼泽是禁区，水是走廊**：一条河不会挡住谁，
只是让"绕路"和"蹚过去"第一次有取舍。

**② 冰 `ICE`（id 18）**：`EnterFx::Slide`，踏入后顺着原方向再滑一格（最多 2 格）。

这是这个模拟里**第一种影响"位置"而不影响"收支"的地形**。它的意义不是数值，是结构：

> `step_target()` 从"这一步的答案"变成"这一步的中间量"。

于是"预判两格"第一次有价值——这是从批次 15 起一直没解决的「眼睛为什么稀有」
的第二个答案（第一个是批次 40 的"转身是免费午餐"，那个讲的是**为什么不动**，
这个讲的是**为什么动了也不用看**）。

滑行的实现要点：`attempt_move` 拆成 `try_step` + 滑行循环，滑行那一步照样走完整的
`is_clear`——**撞墙就停，不会穿墙**。上限 2 格，防止环形边界上无限绕圈。

**③ 洞穴「重挖」按钮**：`worldgen::recarve_caves`。

关键约束：**只挖空地**（跳过 `grid.owners >= 0` 的格子）。
直接 `set_cell_at(WALL)` 会把站在那儿的身体格碾成墙——`anatomy` 还写着 `PRODUCER`、
`grid` 已经是 `WALL`，那只生物会带着一个"虚空的器官"继续活着。
挖出来的洞会比新建世界时少几个口子，但世界不会被挖坏。

### 三、测试守着什么

| 测试 | 守的东西 |
|---|---|
| `water_charges_extra_energy_on_enter` | 水扣对钱，而且**耗掉的能量进热池**（否则能量账每走一步漏一笔） |
| `ice_slides_one_extra_cell` | 滑行方向必须是**原方向**（不是随机方向） |
| `ice_without_slide_stops_immediately` | `ice_slide = false` 时逐位等于旧行为 |
| `recarve_caves_skips_occupied_cells` | 重挖之后身体格**仍然归原主**，而且真的挖出了东西 |

### 四、一个顺手修掉的坏习惯

`brush_list_covers_registry_and_both_erasers` 原来写死 `assert_eq!(ids.len(), 8)`。
加一种地形就要改测试——那不是守门，是抄写。现在改成
`TERRAIN_BRUSH_TYPES.len() + 2`，加地形不用碰测试。

### 五、这一批没有扫描数据

水 / 冰 不在任何默认世界里（要靠玩家画，或者以后的 worldgen 预设），
所以没有"配置 A vs 配置 B"的数可报。它们的价值在这一批是**结构性的**：
地形第一次能改"落点"（冰）和"路径成本"（水），而不只是"扣血 / 产食"。

下一步如果要量化它们，得先有一个**带水的世界预设**（河 + 桥），
那才有"绕路 vs 蹚水"的可测选择。

## 51. 批次 44：世界生成默认就有地形（`rich_terrain`）

### 一、先回答"按钮在哪"

「重挖洞穴」在 **顶栏「全局参数」→ 左列「世界」段 → 「洞穴」滑块正下方**。
同一段里现在还有一个 **「丰富地形（新建世界时生效）」** 复选框。

### 二、这一批真正改的东西

之前的问题不是"没有地形代码"，而是**默认世界里一格地形都没有**。
阶段 8 就有笔刷、批次 25 就有洞穴预设，但新开一局看到的是"墙 + 草甸 + 零散食物"——
于是「绕路 / 蹚水 / 冒险穿过辐射带」这些选择**从来没在默认体验里出现过**。

`WorldCfg::rich_terrain`（**默认 `true`**）：新世界自动铺一整套地形。

| 地形 | 摆法 | 为什么这么摆 |
|---|---|---|
| **水** | 2~3 条从上到下的蜿蜒河，**每隔几行留一处浅滩** | 浅滩是关键：连续的河 = 一堵墙；有浅滩才叫走廊 |
| **冰** | 河面随机冻住（12%）+ 岸边挂霜 | 冻住的河段 = "能滑过去的浅滩"，滑行自带位移 |
| **沼泽** | 3~5 块，世界下半部分 | 比水贵一个量级（0.5 vs 0.15）→ 真正的**禁区** |
| **辐射带** | 3~5 块，中段 | 风险/收益对称（变异率 ×3），制造"快速变异短命"的种群 |
| **腐殖质** | 3~5 块地表 + 洞穴底部 | 批次 10.5 的老结论：暗区得有饭吃 |
| **岩浆** | 底部 7% 的条带 + 几个探到中段的池子 | 唯一的**绝对禁区**，放最低处——先有理由往下走才遇得到 |
| **洞穴** | 随机游走隧道，**每条两个竖井** | 一个口的洞等于死胡同（洞里没光），两个口才住得人 |

### 三、三个实现上的坑

**① 斑块必须"只填空处"。** `paint_blob` 是无条件覆盖的，用它铺沼泽会把山脉抹平，
世界越挖越平。新加的 `paint_terrain_blob` 只覆盖 `EMPTY` / `FOOD`，不碰墙。

**② `cave_count = 0` 的含义分叉了。** 丰富地形下 `0` = **自动**（按面积 3~8 条），
经典地形下 `0` = 一条都不挖。这个分叉必须抽成公开的 `cave_tunnels()`——
因为**「重挖」按钮也要用同一个数**，否则默认世界（`cave_count = 0`）按重挖会一格不挖，
按钮就是个假按钮。

**③ 岩浆放最后。** 它是"熔掉一切"的东西，先铺别的再铺它，才不会被别的点缀掉。

### 四、实测（6000 tick、3 种子、p = 1.0）

| 指标 | 经典地形（`flat`） | **丰富地形（默认）** |
|---|---|---|
| 个体 | 821 | **910（+10.8%）** |
| 平均体型 | 10.72 | 9.85 |
| **成体体型** | 14.28 | 13.19 |
| 物种（聚类） | 29.3 | 30.3 |
| 有光占用 | 56.3% | 58.7% |
| 结构异养 | 13.0% | 9.4% |
| 嘴% | 90.4 | 98.1 |

**人口反而多了 10.8%。** 因为地形同时干了两件相反的事：
- 岩浆吃掉底部 4.2% 的可用面积（减人口）；
- 腐殖质在**暗处**持续产食（加人口），而洞穴给了一块和地表光照隔离的生态位。

按光分带看得很清楚：25–49% 那一带从 380 涨到 **578** 个体——
这批人住在"被墙 / 洞顶遮住、但有腐殖质"的地方。

代价是**成体体型 -7.6%**（14.28 → 13.19）：地形把空间切碎了，
大身体更难找到整块空地（这正是从批次 5 追到现在的老规律）。

### 五、怎么自己看

新增诊断工具 `examples/map_dump.rs`：

```text
cargo run --release --example map_dump -- [seed] [--flat]
```

打一张 ASCII 图（`#`墙 `~`水 `*`冰 `s`沼泽 `r`辐射 `:`腐殖质 `^`岩浆 `,`食物），
外加每种地形的格数占比。**改世界生成之前先看一眼这张图**——
它比任何数字都更快告诉你"河流是不是直的、岩浆是不是压在底部"。

## 52. 批次 45：基因组与发育（阶段 0）——顺带发现体型原来不可遗传

### 一、做了什么

- 新增 `genome.rs`：`Genome` / `Segment` / `GeneCell` / `BodyPlan` + `expand()` / `hash()` /
  `modules()` / `composition_distance()`。**纯函数、无 RNG、无 `World` 依赖**，8 个单测。
- `Organism` 加 `genome`；`growth_plan` 从 `Option<Anatomy>` 换成 `Option<BodyPlan>`
  （带**发育顺序**、父子关系、受阻计数）。
- 变异作用对象从"身体"改成"基因组"（`mutate_genome`）。
- `grow_organism` 重写：**按 BFS 顺序**长，受阻连续 3 tick 才凋亡（整支子树砍掉）。
- 繁殖 / 出芽统一走"基因组 → 变异 → 展开 → 1 格胚"。

### 二、三个坑（都踩过）

**① BFS 必须用 8 邻域。** 身体是按 8 邻域拼出来的（`add_random_cell` 从 8 个方向挑），
用 4 邻域会把对角相接的格子当孤岛丢掉——实测成体体型从 13 格砍到 **2 格**。

**② 受阻不能一刀切。** 第一版"一受阻就砍子树"，成体体型掉到 2.5 格：拥挤的芽常常是
"这一格被母体占着，下一 tick 就好了"。改成**连续卡 3 tick 才砍**，并且先找别处能长的地方。

**③ 蓝图里的胚必须在 (0,0)。** 出生时放下的是 (0,0) 那一格，如果蓝图里的胚在别处，
`pending()` 永远认为"胚还没长出来"，芽卡死。`expand` 最后会把整份蓝图**平移**到胚在原点。

### 三、最重要的发现：老世界的"体型"不是遗传性状

**证据链：**

1. 旧版兜底（"长到任意相邻空位、类型随机取"）的触发条件是 `!grew`，而完成判定要求
   `anatomy.len() >= plan.len()` **且** `old_enough`。于是"蓝图已长满、但还没到
   `growth_min_ticks`（20）"的那 20 个 tick 里，**兜底每 tick 白长一格**。
2. 把兜底禁用（`for c in cells.iter().take(0)`）重跑旧代码：

   | 版本 | 成体体型（t=800） |
   |---|---|
   | 旧版（含兜底） | **16.69** |
   | 旧版（禁用兜底） | **2.65** |

3. 结论：老世界 **蓝图 ≈ 3 格，身体 ≈ 14 格**。多出来的 11 格是
   **"芽周围有多少空地"**，不是基因。

**这意味着批次 5~44 之间所有"体型 X 格 / 体型 +N%"的结论，量的都是兜底的填充量。**
也终于解释了为什么"给大体型收益"从来没赢过——**体型根本不响应选择**。

### 四、新基线（6000 tick、3 种子、p = 1.0）

| 指标 | 旧（含兜底） | **新（阶段 0）** |
|---|---|---|
| 个体 | 821 | **1410** |
| 平均体型 | 10.72 | **2.54** |
| 成体体型 | 14.28 | **2.74** |
| 物种（聚类） | 29.3 | 24.3 |
| 芽占比 | 47.4% | 25.8% |

为什么只有 2~3 格：结构变异率 5%，6000 tick 里约 30 次"加细胞"；加/删对称 →
基因组在 3 附近随机游走；r 选择（小身体成熟快、维持便宜）把它钉住。
**这是诚实的结果，不是 bug。**

### 五、顺带修的真 bug

`add_random_cell` 纯随机挑基底细胞，而身体内部细胞的 8 个邻居全被自己占着 →
"加细胞"几乎必然失败，而"删细胞"永远成功。净效果：基因组只会缩不会长
（实测加 40% / 删 10% 的偏置都推不动体型）。改成**只从表面挑**（有至少一个空邻居的细胞）。

### 六、留给阶段 1 的判据

`examples/grow_probe.rs` 打印「个体 / 芽 / 平均体型 / 成体基因组 / 蓝图大小 / 待长 / 已凋亡」。
**判断"发育有没有在动"先看它，不要看种群**——种群是二阶量（批次 37/38 的教训）。

阶段 1 的验收：`蓝图(中位)` 从 3 涨到 8+，且 `已凋亡` 不失控。

## 53. 批次 46：段级算子（阶段 1）——体型与物种数第一次同时上涨

### 一、五个段级算子

`MutationCfg::segment_op_prob`（默认 **45%**）：结构变异有 45% 概率做**段级**操作，
否则退回细胞级（加/改/删一格）。

| 算子 | 效果 |
|---|---|
| `repeat ±1` | 体型成倍增减（上限 8 份） |
| `mirror` | 长出对称的另一半 |
| 插段 | 复制一段叠在身体下方（重尾增长的主要来源） |
| 删段 | 丢掉一段 |
| 平移 | 整段挪一格（单段时被"胚归一化"抹掉 → 中性变异） |

两道闸：`MAX_PLAN_CELLS = 64`（超了回滚）、`repeat ≤ 8`。

### 二、变异率重标定：5% → 25%

阶段 0 之后结构变异是体型唯一的原材料，5% = 每 20 个后代 1 次改动机会。
实测（1600 tick）：5% → 成体基因组 3.28 / 蓝图最大 9；**25% → 6.56 / 21**；
35% → 8.31 / 26；50% → 16.38 / 42 但 **待长 934、已凋亡 235（失控区）**。
取 25。

### 三、实测（6000 tick、3 种子、p = 1.0）

| 指标 | 阶段 0 | **阶段 1** |
|---|---|---|
| 个体 | 1410 | 1313 |
| 平均体型 | 2.54 | **4.81（1.9×）** |
| 最大体型 | 6 | **22** |
| 成体体型 | 2.74 | **5.20** |
| 物种（聚类） | 24.3 | **68.3（2.8×）** |
| 物种（指纹） | 56.7 | **300.7（5.3×）** |

**第一次看到"体型 + 物种数"同时上涨。** 段级算子让"多一个体节 / 多一个对称半身"
变成一次变异，身体蓝图第一次有了可探索的空间。

### 四、两个被证伪的猜测

**① 生长成本不是刹车**：`growth_cost` 1.0 / 0.3 / 0.1 → 成体基因组 6.56 / 4.18 / 2.96，
**越低反而越小**（长得便宜 → 小体型繁殖更快 → r 选择更强）。

**② 提高变异率有上限**：50% 之后进入"蓝图很大但长不出来"的失控区
（待长 934、凋亡 235）。限制体型的是空间与发育成功率，不是变异供给。

### 五、一个 off-by-one

插段锚点用 `bbox_max_dy(g) + 1` 会在新段和身体之间留一条缝 → 整段变孤岛被丢掉。
`bbox_max_dy` 返回的已经是"最后一行之后的那一行"，直接用就行。

### 六、下一步

阶段 2：段嵌套（`children`，深度 ≤ 2）+ 体型收益。

## 54. 批次 47：体型收益 = 体表面积/体积比

之前的"体型收益"全是 `× n^k`，而收入/成本/容量/繁殖门槛**全部线性于 n**，
所以任何 `n^k` 都只是改斜率。非线性的量只能来自几何。

### 一、`Anatomy::perimeter`（八邻域暴露面数）

1 格 8 · 并排两格 14 · 3 格直线 20 · 2×2 方块 20 · 3×3 方块 32。
归一化 `svr = 8n / perimeter`：单格 1.00 · 2 格 1.14 · 2×2 1.60 · 3×3 2.25。

**必须八邻域**：身体是八连通的，四邻域会把对角线身体数成一堆孤立格
（实测四邻域下平均 svr 1.09 vs 平均体型 3.55 格，明显矛盾）。

缓存字段：`add_cell` 增量 `+8 − 2×邻居数`，`recompute` 全量。有逐步对照测试。

### 二、两个旋钮（默认 0 = 关）

- `exposure_prod_exp`：光合 `× clamp(svr^k, 1, 4)`
- `exposure_upkeep_exp`：维持 `× clamp(svr^-k, 0.25, 1)`

单格身体恒为 1.0（`single_cell_body_gains_nothing` 钉死）。

### 三、实测（3000 / 6000 tick，3 种子）

6000 tick，k=0 → k=2：个体 1313 → **1973**，存活种 301 → **425**，
聚类物种 68 → **145**，最大体型 22 → **31**，紧凑%(svr≥2) 0.1% → **4.4%**，
但**平均体型 4.81 → 4.58（略降）**。

### 四、结论

**紧凑度第一次能被推动**（44 倍），但**平均体型没涨**——
奖励抬高的是全世界总收入，多出来的能量被小体型（r 选择）抢走。
和批次 11「光合 0.8」同一个机制。

`svr` 只 1.29 → 1.35，因为身体长不出紧凑形状：4.8 格身体 perimeter ≈ 30，
那是 T/L 形的细枝。**瓶颈在发育层，不在激励层**——段只能沿一条线堆叠。

→ 阶段 2（段嵌套）才可能让这条机制从"整体加成"变成"选择压"。

`VERSION` 36 → 37（`Anatomy` 多一个 `perimeter: u16`）。

## 55. 批次 48：段嵌套（阶段 2）

`children` 这一层终于用起来了：`MAX_DEPTH = 2`，`emit` 超过深度不展开。
`segment_op` 从 5 个算子扩到 7 个（+长子段 / 删子段），
**前 5 个算子的目标从"顶层段"改成"任意段"**——否则附肢只能靠生成那一下随机，
之后再也改不动，是死结构。

### 坑：附肢不能往"下"长

`anchor = (0, 1)` 在 `repeat > 1` 时和下一节躯干完全重叠被去重吃掉
（两节各带两格附肢应 10 格，实测 8 格）。改 `(1, 0)` 侧向长才对。

### 坑：`hash()` 必须递归进 children

阶段 1 只吃了 `children.len()` → "附肢换细胞但格数没变"的变异不改指纹 →
两个不同身体算成同一物种。

### 实测（6000 tick · 3 种子 · 收益关闭）

| 指标 | 批次 46 | **批次 48** |
|---|---|---|
| 平均体型 | 4.81 | **6.22** |
| 最大体型 | 22 | **45** |
| svr | 1.29 | **1.49** |
| 紧凑%(svr≥2) | 0.1% | **9.5%** |
| 有附肢的成体 | 0% | **85.4%** |
| 存活种 | 300.7 | 289.3 |
| 聚类物种 | 68.3 | 59.3 |

**体型第一次真的变大（+29%），不需要任何收益机制**，纯粹是形态表达力放开。
代价是物种数小幅下降（K 方向的正常代价）。

### 体型收益仍然无效

`exposure_prod_exp` 0 → 1.0 → 2.0：平均体型 6.22 → 5.89 → 4.94，
存活种 289 → 357 → 443。**第三次**看到"抬高总收入 → r 选择吃掉"。
要让体型变大只能靠形态表达力或**相对**优势，不能靠总量。

### 顺带修了一条失效的回归测试

`upkeep_thins_the_population` 断言"收税后人口变少"，批次 48 之后 4 个种子
里 2 个反向、聚合只差 -3.3%（噪声 ±20%）。改成断言**热池**暴涨——
单调、与生态吸引子无关。

## 56. 批次 49：细胞器向量（阶段 3 · 第一刀）

细胞不再是非此即彼的枚举：`Organelles { photo, mouth }`（0..=255）挂在
`BodyCell` 与 `GeneCell` 上，**可遗传**。行为按基因分派——两条轴都 > 0 的格子
会跑两遍（先光合、再摄食），这就是「半个生产者 + 半张嘴」的中间态。

出厂预设只取 0 / 255 端点（`organelles_of`），所以 `x / 255` 只可能是 0/1，
**旧世界逐位不变**（`full_strength_is_bit_identical` 守着）。

### 两个必须踩出来的坑

**① 成本必须随器官负载缩放。** 只让产出乘强度、成本不动 → `photo=128` 花同样的钱
只产一半，被选择立刻淘汰（中间态 2.8% 且站不住）。改成
`cost × org.load()`（`(photo+mouth)/255`，无器官的格子返回 1.0）才对。

**② 必须允许"新开一条轴"。** 候选槽只收 `>0` 的轴 → 生产者格永远拿不到嘴的基因，
杂食格长不出来。两条轴都进候选之后才出现真正的杂食格。

### 实测（6000 / 12000 tick · 3 种子）

| 条件 | 中间态% | 杂食格% | 存活种 | 物种(聚类) | 异养% |
|---|---|---|---|---|---|
| 6000t 关 | 0.0% | 0.0% | 289.3 | 59.3 | 10.0 |
| 6000t orgmut=100 | 3.8% | 3.2% | 335.0 | 42.7 | 6.1 |
| 12000t 关 | 0.0% | 0.0% | 283.7 | 54.3 | 9.4 |
| 12000t orgmut=100 | **4.7%** | **3.7%** | **317.0** | 40.7 | 6.0 |

**中间态第一次存在，而且稳定**（6000→12000 是累积不是衰减），
其中大部分是真杂食格。存活种 +16%。

**但频率 <5%**：满照光合 0.12/tick 是确定的收入，咬活体单价高 2.6 倍却
必须贴脸才有机会——半格生产者换半张嘴等于拿确定收入换低概率期权。
批次 9.5 以来那道墙（免费的太阳能永远赢）现在下沉到了细胞层。

**副作用**：组成聚类物种数下降（54.3 → 40.7），因为中间态让"构成"变成连续量，
Jaccard 把原本分得开的物种合并了。指纹物种数同期是上升的。

## 57. 批次 50：追猎 —— 机制对，行会不存在

`chase_prob`（默认 0）：有嘴/杀手、且没贴着猎物时，按概率把移动方向掰向最近的身体。
两档感知——**接触**（8 邻域，任何有嘴/杀手的个体）与**视觉**（要眼睛，范围 20）。

### 第一版为什么逐位不变

要求必须有眼睛 → `chase=0/0.1/0.3/1.0` 四个取值结果**完全相同**。
查下去：**眼睛 + 移动器 + 嘴/杀手 = 0.0%**。眼睛维持成本 0.030（生产者的 3 倍），
唯一用处是给大脑加 36 维输入，而大脑是随机网络——**眼睛已经灭绝**（总数 0.7%）。

死循环：没眼睛 → 追猎不触发 → 眼睛没价值 → 没眼睛。
所以加"接触"档：嘴本身就是化学感受器，挨着就能尝到。眼睛变成"1 格 → 20 格"的升级件。

### 结果：两档之后仍然没有可测效果

| chase | 个体 | 咬合% | 追猎者% | 存活种 |
|---|---|---|---|---|
| 0.0 | 1195 | 38.4 | 0.2 | 289.3 |
| 0.3 | 1218 | 37.2 | 0.2 | 275.0 |
| 1.0 | 1223 | 35.6 | 0.2 | 289.7 |

作用对象只有 0.2%（1195 只里的 2 只）。

### 把行会造出来：三条路

| 条件 | 追猎者% | 咬合% |
|---|---|---|
| `produce`（移动者能光合） | 0.4 | 34.4 |
| `movercost=0.010` | 0.1 | 36.8 |
| 两个一起 | **5.0** | 35.2 |
| 上面 + chase=1.0 | 4.3 | 35.7 |
| `bite=0.30`（×5） | 0.3 | **61.0** |
| `soil=4` | 0.1 | 15.0（生态崩，704 只） |

**行会要两个条件同时满足才出现**（移动者能光合 **且** 移动器不贵）——
单独放松任何一个都没用，因为"一个移动器格 = 放弃一整格收入"是结构性的。
**行会到 5% 之后追猎仍然没效果**：世界太密，猎物本来就贴着，
`touching_prey` 直接短路，机制不触发。

### 结论

> **运动在这个世界里没有独占收益。** 不是感知问题、不是价格问题、也不是收益问题
> （咬合速率 ×5 让咬合占收入 61%，仍然没人会动）。

这解释了批次 23/24/30/43 为什么都没能造出稳定的"移动者"行会——
它们都在给**已经会动的个体**加收益，而会动的个体不存在。

下一步：给移动一个**独占**资源。地力耗竭是最接近的候选，但 `soil=4/8`
直接把生态打崩（704 / 84 只），现在的强度是"惩罚定居"而不是"奖励迁移"。

### 三个坑

1. **`think()` 的转身分支必须从 `return` 改成打标记**，否则"大脑想转身"那一刻
   追猎永远轮不到——而那正是"看见猎物但还没对准"的时刻。
2. **已经贴着就别追**：否则朝猎物走 → 被挡 → 转身 → 绕着猎物打转。
3. **不碰世界 RNG**：`think()` 在 rayon 并行路径上，用 `id + age` 哈希。

`VERSION` 38 → 39。
